# P1.5 学习旅程设计原型 v0.1

2026-10-21。对应[信息架构](../../phase-1.5-information-architecture.md)的学习首页、生成大纲、课程学习三个主要页面。独立静态原型，不修改Vue业务页面，不连接后端，不调用Provider，不存储用户数据，也不拆task。

## 打开与核对

直接用浏览器打开 `index.html`，或从项目根运行：

```sh
python3 -m http.server 8769 --bind 127.0.0.1 --directory docs/design/prototypes/phase-1.5-learning
```

浏览器访问 `http://127.0.0.1:8769/`。仅提供原型目录，结束预览后可停止该进程。

顶端设计导航可直接切换三页。主要旅程：

1. 首页输入目标，展开偏好，点击开始生成；模拟第一节准备后自动进入课程。
2. 大纲页点击调整会暂停自动进入；保存只保留本页文字，不调用模型修改示例大纲。可停止模拟生成，保留大纲后进入示例课程。
3. 课程页点击下一步观察 `n->next = head` 与 `head = n`；切换代码可对应高亮。
4. 随堂练习包含未选择、正确和错误反馈；不更新掌握度。
5. 第3节展示局部失败，其他可用场景仍可打开；第6节可模拟就绪。
6. 提问和内容反馈使用明确标识的本地示例，不发送或保存任何内容。

窄屏中，主导航和课程目录折叠；导师面板按需展开，提问按钮不遮挡演示控制。

## 设计选择

- 学习首页以目标输入为主，不放虚构能力分数或占据主位置的模型参数。
- 配色：正文深蓝 `#19334a`、次级文本 `#607283`、重点青绿 `#14756c`、浅绿 `#e5f2ee`、背景 `#f5f7fa`、白色内容区。
- 字体：首页标题使用系统宋体衬线字形，学习正文使用系统中文无衬线字体，代码使用系统等宽字体；没有外部字体请求。
- 桌面稳定导航，大纲主内容加目标说明，课堂目录／内容／按需导师。中等屏幕收起导师，移动端内容优先。
- 链表状态演示是核心视觉元素，强调指针关系和步骤；不是任意代码执行，也不是已接入的Manim动画。
- AI草稿标识持续可见但不逐次弹窗；签核课程仅用示例卡片表达样式，不冒充已读取真实课程目录。
- 图谱、画像、记录和设置仅显示不可用的设计占位，不提供假业务交互；Phase 2功能没有入口。

## 示例边界

本原型固定使用链表课程。输入目标与时长仅用于页面预览，不真正改变场景内容。第1节和回顾复用演示，第3节故障为预设状态；它们不能作为真实课程生成、个性化或故障恢复的验收成绩。

使用场景导航不会累积真实学习进度；首页的课程与记录是显式示例。刷新后重置示例状态，没有持久化。

本次交付三页及交互状态，不代表全部主要页面视觉设计完成。图谱路径、画像掌握度、记录、模型设置尚待设计；全部主要页面设计完成前不实施前端业务改造。

## 验证

本地 Python Playwright 检查命令（需已安装Playwright浏览器）：

```sh
backend/.venv/bin/python docs/design/prototypes/phase-1.5-learning/check_preview.py --output /tmp/edumind-p15-preview-check
backend/.venv/bin/ruff check docs/design/prototypes/phase-1.5-learning/check_preview.py
```

检查覆盖三页在1440、1024、768、390、320px的15组无横向溢出断言，以及演示、代码高亮、练习反馈、局部失败、模拟就绪、内容反馈、调整暂停自动跳转、移动目录、导师与主菜单操作。输出截图和 `validation.json` 保存在指定目录，不提交生成图片。

实际已执行上述交互与响应式检查，浏览器无脚本异常，并目视检查桌面与390px课程截图。首轮受沙箱限制无法启动Chromium，获工具审批后检查通过；视觉复核中修正了导航换行、生成计数、截图过渡及移动端提问按钮遮挡问题。未做真实后端、Provider、完整可访问性审计或所有浏览器兼容测试。

## 希望用户核对

- 首页是否突出学习目标，常用入口是否容易理解。
- 课程页面的目录、内容、导师是否分工清晰；移动端折叠是否合适。
- 当前浅色、深蓝与青绿风格是否适合作为全站方向。
- 状态演示、代码和练习的切换，是否比固定三块正文更接近期望的学习体验。
