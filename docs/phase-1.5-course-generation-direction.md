## 3. 保留的方案与职责

### 3.1 三个组成部分

| 组成部分 | 采用内容 | 不自动引入的内容 |
| --- | --- | --- |
| DeepTutor 提示词组织 | 具名规则块、当前能力协议、运行时事实快照、按阶段提供必要上下文 | 完整运行框架、会话库、自由工具循环及全部检索能力 |
| MAIC-UI 交互要求 | 过程与模拟对齐、代码高亮、步进/暂停/重置、学习反馈、移动端及键盘可用性 | 任意 HTML/JavaScript 生成执行、无教学必要的控件、整站重写 |
| 程序管理共享代码与轨迹 | 受支持规格、模板代码、执行状态、参考答案、事实与引用、版本和依赖 | 任意模型代码自动执行、程序保存后即视为正确、超出支持域的猜测 |

参考固定版本：DeepTutor `a31d826`、MAIC-UI `aad58dd`，见[提示词源码梳理](reference/deeptutor/prompts.md)。这些是实现参考，不是质量背书；所查 MAIC-UI Heavy 路径跳过验证器，不能照搬其“验证通过”结论。

### 3.2 最小生成流程

```text
原始目标 + 有依据的画像
          ↓
课程规划：真实学习目标、场景与示例选择
          ↓
程序管理的共享示例：规格、代码、轨迹、事实与答案
          ↓
模型教学内容：讲解、题干、解析，引用准确事实
          ↓
程序装配：代码、状态、动作、受约束交互与版本绑定
          ↓
完整课程候选 + 分项校验结果 + 教学审核意见 + 独立评估
```

流程图表示职责和证据关系，不新增“所有模型审核意见通过才允许草稿可见”的门禁。草稿可学、正式签核和可靠评分仍按现有契约分别处理。

| 职责 | 输入与输出 | 所有权和检查 |
| --- | --- | --- |
| 规划 | 原目标/有据画像/支持范围 → 目标、场景、示例选择 | 不把场景数量当学习目标，不臆测未知学情；检查目标覆盖 |
| 示例引擎 | 受支持规格 → 代码、轨迹、事实、答案 | 程序持有；独立期望验证；不支持情形明确拒绝或走已批准的其他路线 |
| 教学内容 | 目标、约定、必要事实内容及 ID → 讲解、题干、解析 | 模型负责自然语言正确性；ID 存在不代表句子正确；不只提供无法理解的裸 ID |
| 交互装配 | 同一代码/轨迹版本及教学内容 → 可操作页面 | 程序派生状态和代码位置绑定，不重新生成另一套算法 |
| 教学审核 | 完整候选、原目标、参考与必要上游 → 可定位意见 | 保留事实、步骤、答案、安全、复杂度及教学适配维度；模型意见是建议 |
| 有限修复 | 准确父候选和具体允许意见 → 新候选版本 | 不改标准或共享事实掩盖错误；保留原稿，重新检查受影响内容 |

逻辑职责不等于独立模型数量。示例、动作、版本及推进不必交给模型；不为“多 Agent”标签增加无必要调用。若保留 B 基线，其代码、答案和动作仍由 B 独立生成，不能借 C 引擎补齐。

### 3.3 提示词、共享材料和交互的具体要求

1. **唯一有效协议。** 稳定规则、任务上下文、事实材料和本次生成/修复任务分开装配。最终提示词只保留当前字段和状态；历史字段映射写在开发文档，不靠末尾覆盖旧指令。保持已批准教学标准，检查真实发送的提示词及 Schema，而不只检查模板文件。
2. **准确共享版本。** 同一示例记录适用前提、规格/参数、代码/接口、执行前状态、操作、执行后状态、代码位置、事实/答案及模板/引擎版本。程序计算结果须有独立参考，不用引擎给自身当真值。
3. **变更传播。** 修改代码、规格或参数会产生新版本；受影响轨迹、动作、题目、讲解和检查结论须重建或失效。旧版本的通过结论不能自动继承。
4. **可操作教学。** 讲解、结构图和代码高亮对应同一步；暂停、前后步、重置、答案反馈实际可用。参数控件只覆盖已支持范围，变化后重新绑定受影响内容，不为满足模板硬塞滑块。
5. **事实能力有界。** 头插原型不代表四个数据结构主题，更不代表通用算法验证器。未知指针、环、分配失败和变量作用域按实际支持范围说明；模拟轨迹不冒称真实 C 执行。

### 3.4 运行框架决策

当前不移植 DeepTutor 完整运行框架，也不另建与 EduMind 并存的第二套调度器。优先核对复用已有 Provider Gateway、课程快照、调度/恢复服务及受约束播放器；现有 Mock/工程成绩不自动证明真实运行满足新实验条款。

以后只有能明确说明“替换哪个部件、减少哪些维护、保留哪些语义、如何验证收益”时，才评估额外运行框架。引入 TurnEngine、Capability 或其他循环不能自动解决 T102 的停止反例、凭据隔离或内容正确性，也不作为当前课程交付前置。

## 4. 推进顺序：每一步交付可检查的结果

以下为后续任务拆分依据，不是已领取任务或真实执行许可。不得用本表直接恢复 T102 或启动新的模型调用。

| 顺序 | 交付物 | 完成判断与局限 |
| --- | --- | --- |
| 第一步：统一中文可学课程 | 复用真实候选、T100 修订和播放器，形成同版本讲解/代码/练习/反馈/轨迹；处理 T099 的具体教学问题 | 用户可实际完成学习流程；检查内容一致和交互。标明模型原稿与助手修订，不能算新模型成功或正式签核 |
| 第二步：有限 C 方案真实可行性 | 固定一版候选，按事前确定的有限开发样例，交回真实完整课程及全部失败 | 检验新提示词能否生成正确清楚的教学内容，独立核对答案/解释/动作；不用回显代替教学，不据少量样例宣称稳定率 |
| 第三步：接入课程主链并通过开发准入 | 明确原型与产品的协议适配、支持主题与回归范围，完成原 T038 质量诊断并冻结通过候选 | 以现有 T005/ADR0027 门槛判定；头插单例或独立播放器不能替代多主题课程及正式接线证据 |

**第二步的执行契约仍需决定。** 当前批准的是 B/C 实验；将 C 可用性前置、暂缓 B/C 对照属于下一批范围调整，需要先明确与 ADR0041/0047/0049、既有角色准入及 T102 条款的关系。不得静默删除 B 分母、跳过原七角色门禁或把新结果填进旧批。C 路线的编排收益不能被说成多 Agent 优于单 Agent。

第二步开始前集中确定样例与支持域、模型/路由/配置、实际材料和必要角色、请求与资源上限、停止及证据保管范围、允许修复和独立评估方法；新准确批次另获授权。已有可复用检查不因文档重新组织而无差别重做，受实际变更影响的检查必须重验。

第三步对超出头插的主题应先核对可复用能力与缺口。需要新增算法规则、接口、存储或权限时，按项目协议独立拆任务；不得为了满足主题数量把头插变体当成不同主题，或冒充已具备通用引擎。

## 5. 避免再次偏移的工作规则

### 5.1 每个工作项只回答四个问题

开始前在任务或交接中写清：

1. 这项工作阻塞哪个课程目标或必要安全/证据要求？给出具体失败或缺口。
2. 交付后会新增哪份可读课程、哪项真实教学证据，或解除哪个明确前置？
3. 最小验证是什么？哪些已有组件和证据可以复用？
4. 本次范围与停止点是什么？失败后需要作哪个决策？

工程前置可以是有效任务，不强求每个底层修复立即产出课程；但必须说明它与下一份课程交付的直接关系。测试数量、文件数、审查轮数及冻结完成不单独作为产品进展。

### 5.2 测试与评审范围

- 离线测试覆盖实际改动及其必要反例；相关检查通过后，推进课程交付，不在没有新证据时重复扩大测试范围。
- 在已授权任务范围内复用仍适用的明确授权；需要新决定的范围、契约、外发或预算变化集中说明，不为例行文档整理和离线检查另建批准关卡。新真实批次不继承旧执行许可。
- 评审区分：违反当前明确契约的缺陷、探索中已披露的限制、未来生产保障。前者必须处理或明确修订契约；后两者不能未经决策持续扩大当前任务。
- 不为无限合法输入、任意进程调度、全部副本共同回滚不断扩建同一小实验。需要这类保证时明确威胁模型，单独评估工程范围；不宣称现有实现已满足。
- 有实际安全风险、数据丢失、错误结果被标为成功等问题仍然阻断相关操作，不能以“先有进展”为由略过。
- 同一问题两轮有实质区别的修复仍失败，遵守 [AGENTS.md](../AGENTS.md) 的 blocked 与求助规则；重新决定方案/范围，而非默认再追加一个版本。该规则不预先授权两次真实调用或失败重跑。

### 5.3 T102 的处置

T102 保留 blocked，停止自动追加执行器补丁或重设计，不删除成果、不伪造完成。其已批准停止、凭据和原件要求并未撤销；需要重新开展该路线时，应由用户明确决定范围和投入。

下一批若继续保留“停止未确认返回后也不得新建发送进程”的要求，就必须以具体实际入口证明满足；若希望接受不同的有限探索语义，须明确披露会允许的迟建/迟发风险并获批准。不能用一次性意图、同一请求 ID、人工监督或更换框架把违反旧契约解释成通过。

非法 JSON 丢原件、缺证据却标完整、错臂/错父候选等缺陷仍需闭合。先安全保存可留存原始响应，再解析；保存不全则记录 partial/unknown，不凭摘要自证完整。不要把这些基本要求与防御任意主机攻陷混为一项无限工程。

### 5.4 有限试验的准备与验证收敛（2026-11-12，用户明确要求）

用户指出：部分准备、入口和离线验证已经超过有限课程试验所需的重量，应减少不必要的离线测试和等待。此要求同时约束开发助手的实施与评估助手的后续任务建议。

- **按改动验证。** 在现有任务或交接中简述本次改动、影响和必要检查即可，不另建测试计划审批流程。每项新增或重跑检查须对应本次具体改动、失败证据或明确的必需门禁。
- **复用证据和入口。** 代码、依赖、环境及适用条件未发生相关变化时引用已有结果，不冒称本次重跑。不因换批次、凭据、窗口或访客而复制执行脚本、重复数据库全套与播放器回归；优先使用现有入口的参数和配置。
- **及时结束离线准备。** 相关检查通过后，推进已授权的真实课程生成与交付；只有新改动、失败或未解决的具体风险才扩大验证。Mock 数量、文件数量和审查轮数不能替代真实教学证据。
- **合并必要准备。** 同一明确行为的接线、必要验证和交接一起交付，不把例行登记拆成多个准备任务或新增框架。统一结果记录承载证据，减少重复报告。
- **保留必要门禁。** 新正文仍须接受完整教学审核及实际学习验收；准确绑定、答案隔离和受影响的安全检查继续保留。实际学习验收不意味着未变的通用控件每批都要重跑全套组件测试。已批准契约明确要求的检查不能静默删减，有冲突时集中说明差异。

| 实际变化 | 优先验证范围 |
| --- | --- |
| 仅凭据、窗口或新批身份 | 配置与凭据加载方式、准确授权和新旧操作绑定；不额外发送模型探测请求 |
| 仅提示词 | 实际请求差异、输入完整性和版本绑定；教学效果由真实输出评估 |
| 证据绑定或校验规则 | 原失败复现、对应正例与错绑反例 |
| 持久化、依赖或准入逻辑 | 受影响的数据库流程、版本、幂等与权限 |
| 播放器或页面 | 受影响的交互和实际学习流程 |

以上是验证范围的选择原则，不新增真实调用授权、不降低 T038 等正式验收阈值，也不修改旧失败、原件或 STOP。评估助手应主动指出过重准备；后续进展以新增可学课程、真实教学证据或已解除的具体阻塞为依据。

## 6. 证据如何连接课程目标

每个学习目标都应能追溯到相应场景、示例版本、讲解、练习、交互和检查结果。最小交付包含：

- 完整可读课程及同版本播放器，标明原始模型、程序派生、助手修订等来源；尚未集成正式产品时明确说明。
- 实际请求/响应与候选、审核、修复父版本的绑定，失败与未运行清单；敏感材料按批准范围保管，凭据不进入日志或证据。
- 分开记录结构合格、事实/答案正确、教学可学、交互可用及工程执行结果，不用一个 success 覆盖全部。
- 独立评估者、方法、依据、分歧和未知；模型 pass、引用存在、同源一致都不能替代语义核对。
- 首次与修复后结果分别统计；助手手改、Mock 和手写夹具不计入真实模型成功率。课堂作答记录不自动获得正式掌握度资格。

进度汇报优先给出课程入口、已解决教学问题、新增真实证据、剩余阻塞及下一明确交付。没有新增教学证据时如实写明，并解释必要工程工作解除的具体前置。

## 7. 什么才算“一套确定的课程生成方案”完成

“确定”指方案、范围和版本确定且有验收证据，不承诺模型永不出错。必须同时满足：

1. **方案固定**：支持域、职责、输入/输出、共享事实所有权、交互协议、模型配置、失败/修复规则与候选版本清楚，无旧新协议混用。
2. **完整交付**：从原目标与有据画像到完整课程的主链可运行，代码/练习/动作等需求不缺项；孤立播放器与产品协议的适配已经核对，不只展示一次样例。
3. **真实教学证据**：使用固定候选实际生成，逐段、逐题、逐步评估；代码、答案、轨迹引擎有独立依据，失败与未知保留，未用手改或 Mock 补成功。
4. **T038 开发质量准入通过**：遵守[已批准验收契约](acceptance/phase-1.5-acceptance-contract-r01/contract.md)与[批准登记](ADR/0027-approval-20261022.json)。开发样本为 12 课程槽/6 画像对、至少 4 主题，另有负例与 10 严重错误/10 正确审核对照；首次结构≥98%，完整草稿/需求兑现/可学性各≥95%，画像对照≥90%，事实≥99%，答案100%，自然严重错误0，审核召回/意见精确率≥90%且正确对照无误阻断，工程门禁全过且无未决。精确分母、取整和停止规则以原契约为准；小样本可行性不替代该准入。
5. **结论可复核**：评估结论绑定准确候选、配置、材料及全部结果，通过候选冻结；根任务与完成提交按项目协议登记。
