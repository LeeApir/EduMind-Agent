# 审核范围与请求契约修复 v4.1

沿 ADR-0015 的已有单元目标/三场景与“不进行整单元修正循环”实现；不修改已批准数据契约、
统一结果存储 Schema、阈值、人工权限或发布门禁。不声称 Prompt 能保证语义判断正确。

`review_output_schema(scope)` 在发送前收窄统一 Schema：scope 固定；resource 允许四种
原结论，unit 仅 pass/reject/needs_human。本地 unit/revise 检查保留，厂商忽略请求约束也
不能通过。运行时 Prompt 版本为 evidence-resource-review-v4.1，并显式说明这条规则。
请求的 server review_contract 在候选数据之后构建，候选不能覆盖 scope 或允许结论。

审核对象是服务端绑定的用户目标与计划/场景目标。计划自身也要满足用户目标，不能通过
缩小计划目标回避缺失。图谱其他目标及常见误解是参考，不自动要求每个单元覆盖全部节点；
单元若声称完整覆盖节点，则须兑现。任何位置的真实错误或可达安全问题仍必须报告。
缺少学习者证据时，不推断该学生有某种困难；仅在实际结论依赖缺失事实时转人工。
模型须自行核对可推导的代码/算术，不能把计划轨迹当证明，也不能只因参考未签核例子就
声称简单计算不可检查。真正无法核对的主张仍保留未知。

政策内容增加 Prompt/范围版本，active_policy_digest 随之改变，既有待审版本按原失效规则
处理；不把新 Prompt 结论嫁接到旧快照或人工案件。无迁移、无新公开接口。

r01 失败样本与两次真实结果、人工首槽确认、标签、批准和持久 halt 原样保留。
新 r02 是失败对照家族的校准，不冒充独立正式样本。正确对照补足逐步教学与对应题目，
另加真正遗漏单元目标的反例，避免只靠移除图谱要求让对照通过。标签仍待独立复核。
新执行器复用旧固定逐次传输的独立模块实例，以新目录/run_id/批准根/账本隔离；本地契约
错误在 r02 归类 INVALID_OUTPUT，旧账本的 SAFETY_FAILURE 记录不修改。

旧准备器在当前源码上应因组合变化而拒绝；原文件内容用历史哈希核验，不能重新生成覆盖。
新准备器只允许列明的三个旧来源变更，其余来源必须与原冻结摘要一致；新增文件另行绑定。
真实请求仍需准确新预算批准，待审、人工通过均不补自动质量分子。
