# ADR-0021：计划检查与受限纠错

状态：Accepted；用户批准记录见[0021-approval-20261020.json](0021-approval-20261020.json)。对应已冻结[具体方案](../acceptance/phase-1-plan-correction-proposal-r01/README.md)，批准的是该包设计，不是旧运行重启或真实调用授权。

共享计划结构合法仍可能语义冲突，资源修正不能修改计划。阻断错误发布不等于能纠正错误。采用方案A：正文前增加独立计划检查；来源/前提不清交人工，早期操作终止为failed并区分PLAN_REVIEW_REQUIRED与GOAL_CLARIFICATION_REQUIRED。现有完整单元awaiting_human及人工approve/reject不变；早期附记不授予续跑或发布权限。

模型只给检查结果与引用，服务端绑定不可变原请求、计划、参考、政策及操作身份。锚点是JSON Pointer内的UTF-8字节范围。存在锚点不等于命题成立。只有批准的独立验证器证明所有局部计划问题、初次检查且无未决/拒绝时，才允许预约一次重建；默认白名单为空。新版本重查一次，失败终止；正文阶段不循环重建，旧资源/审核/案件保留但失效。

计划检查、重建状态事件和维护者处置附记分别持久化且禁止UPDATE/DELETE；新增表使用owner/unit/operation/plan复合约束，审计依赖对象使用RESTRICT防止级联丢证据。未来账户删除须显式审计保留/脱敏政策，不能隐式级联删除这些记录。迁移回退遇非空审计表拒绝，不静默清数据。

真实请求计数仍共享20次、180秒绝对窗口，单次最多60秒且受剩余时间限制，0重试/回退。映射输出拟固定512，计划2048、资源4096、审核8192；重建占2请求，资源修正占2请求且每资源最多2次。无重建共享5对、有重建4对，许可与实际请求计数分开且保留尾部必需请求。显式服务端stage选择generation/review路由，不依赖Prompt文本相等。

PC-01–05对应活动T081–T085，依赖串行独立验证提交。业务Schema由冻结草案落地；生产额外一致性校验不得弱于原冻结门槛。任何渠道Schema投影不得削弱本地完整校验。新增早期错误/SSE报告在T082同步API，预算与执行器在T083实现，受限重建在T084实现；未完成任务不能宣称已有能力。

不开放早期人工批准/编辑续跑（方案B），不执行任意程序作为验证器，不以模型自证。H留出封存，A/G与12校准为开发材料。T040保持blocked，真实验证另行冻结和授权，正式98/95/90标准不变。后续若无可批准验证器，交付仅为检查与人工分流，不宣传自动纠错成功。

T083持久预算落地：0033增加operation预算版本/映射/重建/tail计数、修正许可与发送预约表。许可只消耗不退款，发送预约不可更新删除；两表通过operation归属用户，无公开写入口。新操作行锁保护并发，旧非零无预算版本操作拒绝续跑。有预算证据拒绝降级迁移；这属于已批准的PC-03持久计数与失败不退款约束，不增加请求数或早期人工权限。

## 2026-10-21：本批唯一机械绑定／语义审核分工（用户明确授权）

T089将计划审核前置拆成代码与模型两层。代码先检查不可变四类摘要、owner/unit/operation、当前plan ID/正整数版本、活动政策、计划与原输入/参考条目/参考来源版本的一致性；生产调用另查数据库当前操作归属及该单元最新计划，失败不得发审核请求。旧计划复用必须对应当前操作归属和最新版本，不以模型自证身份。持久化时仍重复原完整绑定和UTF-8锚点检查，前置检查不替代发布前失效保护。

`plan-check-prompt-v2`／`plan-semantic-input-v1`只向模型发送原始要求、分段目标、已知学习证据、计划语义字段、相关背景文本及带真实字段摘录的引用；源请求/计划承诺/背景角色分列。服务端摘要、全局身份与图谱/路径/参考条目版本不放入语义输入，也不再为它们提供可引用锚点。局部objective ID、scene依赖及主题标签保留语义关系；用户原文或教学内容中的哈希字面量不按正则删除。模型仍审核真实事实、安全、覆盖、来源归因及计划矛盾；代码绑定正确不等于语义正确。

原始计划/快照及完整来源映射继续保留。新记录为`plan-check-record-v2`，新增`reference_context`锚点种类：其指针指向不可变input_snapshot中的参考正文，按input_digest绑定，不能冒称用户原话；模型只见摘录/来源角色/字段位置，不见内部digest。完整业务模型输出仍`plan-review-result-v1`，仅裁剪未引用的绑定/审计Schema定义，无约束降级。v1审计、摘要和维护记录保持可读；v1不得伪造v2新来源。无数据库迁移或新发布权限；新政策摘要使旧待审授权失效，旧失败/停止账本不改。

用户限定只做这一批，不围绕P01继续循环调Prompt/换模型。T090冻结跨主题开发正负对照及唯一候选/准确调用预算，由用户核对标签和授权后真实验证，分别记录误拦截与漏检。H继续封存，开发通过也不等于正式98/95/90验收通过或自动开启H。若本批不能满足冻结准入，按用户决定收敛：已有人工签核课程是正式产品，动态生成为待审草稿能力，暂不承诺自动发布；不再自动开启下一轮审核调优。catalog_only默认及硬拒绝/身份/来源规则保持。
