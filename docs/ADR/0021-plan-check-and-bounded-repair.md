# ADR-0021：计划检查与受限纠错

状态：Accepted；用户批准记录见[0021-approval-20261020.json](0021-approval-20261020.json)。对应已冻结[具体方案](../acceptance/phase-1-plan-correction-proposal-r01/README.md)，批准的是该包设计，不是旧运行重启或真实调用授权。

共享计划结构合法仍可能语义冲突，资源修正不能修改计划。阻断错误发布不等于能纠正错误。采用方案A：正文前增加独立计划检查；来源/前提不清交人工，早期操作终止为failed并区分PLAN_REVIEW_REQUIRED与GOAL_CLARIFICATION_REQUIRED。现有完整单元awaiting_human及人工approve/reject不变；早期附记不授予续跑或发布权限。

模型只给检查结果与引用，服务端绑定不可变原请求、计划、参考、政策及操作身份。锚点是JSON Pointer内的UTF-8字节范围。存在锚点不等于命题成立。只有批准的独立验证器证明所有局部计划问题、初次检查且无未决/拒绝时，才允许预约一次重建；默认白名单为空。新版本重查一次，失败终止；正文阶段不循环重建，旧资源/审核/案件保留但失效。

计划检查、重建状态事件和维护者处置附记分别持久化且禁止UPDATE/DELETE；新增表使用owner/unit/operation/plan复合约束，审计依赖对象使用RESTRICT防止级联丢证据。未来账户删除须显式审计保留/脱敏政策，不能隐式级联删除这些记录。迁移回退遇非空审计表拒绝，不静默清数据。

真实请求计数仍共享20次、180秒绝对窗口，单次最多60秒且受剩余时间限制，0重试/回退。映射输出拟固定512，计划2048、资源4096、审核8192；重建占2请求，资源修正占2请求且每资源最多2次。无重建共享5对、有重建4对，许可与实际请求计数分开且保留尾部必需请求。显式服务端stage选择generation/review路由，不依赖Prompt文本相等。

PC-01–05对应活动T081–T085，依赖串行独立验证提交。业务Schema由冻结草案落地；生产额外一致性校验不得弱于原冻结门槛。任何渠道Schema投影不得削弱本地完整校验。新增早期错误/SSE报告在T082同步API，预算与执行器在T083实现，受限重建在T084实现；未完成任务不能宣称已有能力。

不开放早期人工批准/编辑续跑（方案B），不执行任意程序作为验证器，不以模型自证。H留出封存，A/G与12校准为开发材料。T040保持blocked，真实验证另行冻结和授权，正式98/95/90标准不变。后续若无可批准验证器，交付仅为检查与人工分流，不宣传自动纠错成功。
