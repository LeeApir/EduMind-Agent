# ADR-0017：分层审核职责与未知学情契约（T056）

用户已授权在 `codex/phase-1-t056-t070` 开发 T056–T070；该授权解除原“只规划”限制，不替代 T056 验收条款要求的具体审核协议批准。本文补充 [ADR-0015](0015-shared-plan-and-hybrid-review.md)、[ADR-0016](0016-student-visible-objective-coverage.md)，不改写其原件。批准材料还包括[具体契约](../agents/layered-review-contract-v1.md)、[对照材料](../acceptance/phase-1-layered-review-design-r01/cases.json)与[冻结清单](../acceptance/phase-1-layered-review-design-r01/manifest.json)。

## A. 决策与职责

采用“资源审核其实际全部内容及自身责任，整单元独立核验完整需求”的分工。原始请求全文、完整计划承诺与实际候选保持；计划漏分配或缩小需求不是删掉该要求的授权。

| 层级 | 必须完成 | 不据此认定缺失 |
| --- | --- | --- |
| 讲解 | 实际概念/术语/过程/边界的正确性；该场景自己的明确承诺 | 没重复代码场景的完整程序、没重复练习场景的题目 |
| 代码 | 实际实现/调用、正常与失败路径、所有权/释放、输出、注释与关键步骤 | 没重复整课概念或所有练习 |
| 练习 | 实际题干条件、正确答案/解析和分配的考查目标；过程测量必须要求用过程知识 | 没另附一份完整程序；解析含过程不自动等于题目考过过程 |
| 整单元 | 独立对照原始请求、所有计划承诺与三份最终资源，检查学生可见覆盖/时序、接口/术语/表示/轨迹/答案/动作 | 资源 pass、内部计划轨迹、未兑现媒体占位不能当作完成证据 |

任何层中的实际事实、代码片段和安全主张都须审核，不能因资源类型避开检查。明确过程目标沿 ADR-0016：实现、过程教学、过程测量分开；支持可跨载体聚合，但尊重实际可见时机和用户明确的先教后考要求。

服务端仅声明**职责**，不预判覆盖。资源审核请求中的 `unit_verification_obligations` 是交给整单元独立检查的固定职责，不是模型结果中的未决项，也不证明兄弟资源会正确交付。资源看不到兄弟正文时：不声称兄弟合格，也不凭缺席推定整课缺失。自身真缺承诺、实际主张无法判断或接口判断确实依赖缺失兄弟正文时，仍保留具体 `unresolved`。

多个场景共享同一个 objective ID 代表各自贡献，不要求每份完整重复该目标；如果某场景明确承诺“本节提供完整程序”而未提供，不能借其他场景分工洗掉自身失约。学生正文中的明确承诺与计划承诺都必须保留供判断。

## B. 学情未知的处理

`learner_fit` 检查的是有据约束一致与个性化陈述的证据，不是证明这门课对某人一定有效。

1. 没有画像、错题、偏好或掌握度时，如课程没有依赖未知学情作具体保证，检查“没有编造、没有违背已知约束”后可以记 checked；不能仅因学情未知填 unchecked 或阻止发布。
2. “刚学完指针”保留为用户自述经历，不能升格为熟练掌握，也不能反向推断学习困难。课程说明先修条件、提供一般提醒，不等于断言该学生已满足条件或存在困难。
3. “你经常混淆二级指针”等实际个性化陈述没有依据时，需要删除、改为一般提醒或补充证据；当前 finding 枚举没有“无据个性化”类别，故用具体 `needs_human/unresolved` 阻止原句自动发布，不伪造 fact/difficulty 或用“未知”推断“为假”。本批不因此增加自动修正调用或新 finding 类别。
4. 如自述、明确学习约束和可信行为证据确实冲突，应指出冲突、依赖它的结论与影响。能依据准确原文证明的错误归因可报事实矛盾；不能确定的掌握度结论留未决。`difficulty` 仍需明确学习者证据，`misconception` 沿现有定义，不能拿它们装载纯覆盖不足。
5. 如果具体教学判断确实依赖未知前提，例如声称该学生可跳过指针基础，必须列清缺什么证据及其影响。不得把所有学情未知都笼统转人工。

## C. 请求、结果与检查 ID

结果保持 `resource-review-v4` 的六个顶层字段、finding 枚举和 `unresolved: string[]`；不加置信分、解释、证据映射、角色输出字段，也不改数据库 Schema、HTTP 或 SSE。

资源五个必检 ID 保持：`facts`、`code_safety`、`learner_fit`、`objectives`、`reference_scope`。具体含义见配套契约。

**提议给 unit 增加第六个必检 ID `objectives`**，现有五项 `terminology`、`conventions`、`example_trace`、`answer_consistency`、`action_references` 不变。原因：完整目标覆盖已有规范义务，但当前本地路由没有独立必检 ID；新增项可强制要求模型声明是否完成这项检查。它不能证明语义检查真的做对，更不能自动算目标覆盖率。旧结果缺该 ID 不得自动补齐或当新政策 pass。

模型请求投影 Schema 的 `coverage.checked.items` 使用当前 scope 的精确 enum、uniqueItems 及 maxItems；允许缺项以如实表达未知，缺项由本地路由转人工，不强制伪填全满。unit 仍无 revise。业务存储 Schema 已允许字符串检查项，故无需结构迁移；Provider 的 Schema 传输适配和本地完整校验继续分别生效。

新职责及学情上下文只进入服务端最后构造的请求元数据，不能从候选自报字段取得。完整规范、版本阶段及绑定失败行为见[输入契约](../agents/layered-review-contract-v1.md)。缺输入/参考/绑定失败沿既有门禁，不借此补虚假学情或从计划还原原请求。

## D. 政策、路由与退出边界

分阶段实现 T057–T059 时分别采用可辨认的 Prompt/输入/职责版本；新版本进入 `POLICY` 摘要。三阶段目标版本见配套契约，`POLICY_VERSION=hybrid-review-v1` 的持久结构不改，但每阶段摘要必须不同。尚未实施的版本不能标为当前生效。

旧待审/已批准未发布的材料不能用于新政策发布；继续用已有的计划政策摘要复核、案件失效与发布拒绝机制，不回填旧 checked、不搬运旧模型回答或人工批准。原已发布版本按既有准确发布快照读取，不追溯改内容、评分、掌握度或历史签核；如需撤回，另按原撤回机制，不借换版批量改写。T059 以隔离真实 PG 验证这些边界。

新资源只有自身全部职责完成、无 findings/unchecked/unresolved 才有资源 pass 资格。三资源全部通过且独立 unit 六项检查通过，才可能有自动发布资格；还须通过来源/版本/owner/取消等硬门禁。真实资源未决不因 unit pass 清除；有据严重 reject 优先，混合教学缺口不能降级严重错误。纯覆盖或学情证据不足保留 needs_human，不自动发布。

保持三次资源审核加一次独立单元审核的基准路径、每资源最多两次修正、20 次正式/含临时 22 次调用上限、180 秒操作期限及现有单次请求限制；不加模型 judge、自动补全课循环或静默换厂商。T056 不调生产模型、推理档位、输出上限或费用预算。

原始失败、未运行项、原模型结论与人工状态保留。Mock 请求捕获/脚本化结论只证明契约与路由，不证明真实模型遵守分工；仍需 T070 后按新源码/政策、独立预算进入 T040 准入复核。首次 Schema≥98%、自动正式成功≥95%、严重错误召回≥90%等原标准、人工不补自动分子、catalog_only 和 T040 旧阻塞保持。
