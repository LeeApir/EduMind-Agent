# ADR-0029：按官方契约进行一次合成兼容性观察

状态：Proposed，等待准确A—C及manifest附件批准；真实执行另需准确预算批准。任务PHASE-1.5-T054。原ADR0027质量门槛、r02/r03历史及生产catalog_only不变。

| 决定 | 待批准的准确内容 |
| --- | --- |
| A 观察契约 | 用官方Responses计数/生成语义作为预期，不再把取得中转书面资料作为本次极小合成观察的前置。一次同体计数＋生成，核对count与usage、system拼接指令、Schema/strict、max_output_tokens回显及固定OK结果；任何矛盾/未知都停。不把相同回显当成实际内部实现证明。 |
| B 严格限定的探索例外 | 仅允许准确p15-compatibility-probe-p01在尚无独立上游输入/输出硬界证明时，发送一次合成生成请求。输入32k/输出16是本地占额；请求max_output_tokens=16是服务参数，**不保证中转强制执行，也不保证最终token/金额上界**。客户端超时/读取限制不保证停止上游计算或收费。只有用户明确接受该风险并单独批准本包费用例外后才发。不得把例外扩展至课程、其他探针、修复重试或后续包。 |
| C 终态与判定 | 无论干净观察还是失败，最多2 HTTP/1生成后终止。失败unknown保留占额，不重发；干净观察也不称课程准入/模型质量通过，不解锁T039或生产。旧T052 Mock限制和旧冻结入口不改；新探索入口要求契约批准与准确执行批准双登记，缺任一个即拒绝。 |

不能给出可靠上游硬界时，不应把它伪装成普通已验证预算。本例外是有明确未知风险的最小观察，不是降低正式课程质量或预算保护标准。若用户不接受这项例外，保持零调用并等待服务商可核对的资料，不能用普通“好/继续”绕过准确批准。

准确请求、预算、执行器、验证与停止规则见[执行包](../acceptance/phase-1.5-compatibility-probe-p01/README.md)，以其中manifest冻结字节为准；本提案不是实际执行或费用批准。原只计数c01提案不执行、余额不转授。本ADR不修改旧提案/批准/PRD字节，不授予push/merge/部署。
