# ADR-0022：按收敛交付范围结束Phase 1并切换Phase 1.5

- 状态：Accepted（2026-10-21，用户明确要求按本文范围执行收尾、归档及阶段切换）
- 对应任务：PHASE-1-T042；前置为本阶段其余88项已完成任务的提交及证据核对。
- 批准来源：当前会话用户“请按以下范围完成P1收尾、归档及Phase 1.5切换，不再追加模型试错或真实Provider调用”，及其五项完整指令。
- 边界：本次只治理与零调用检查；不开发Phase 1.5、不部署、不push/merge、不改模型或生产开放配置。

## 决定及依据

[最后唯一有界批次](../acceptance/phase-1-plan-boundary-results-r01/README.md)已完成8次真实审核，两个正确计划误拦，不符合冻结准入。T040的旧路线及后续小诊断都没有证明原质量指标。按用户已确定的退出条件，P1以**已有签核课程为正式产品、动态生成为待审草稿能力且不承诺自动发布**的范围结束；默认仍catalog_only。既有工程机制保留，不把诊断脚本、隔离夹具或受信维护CLI描述为已交付公开草稿运营后台。

这次结束是批准的范围收敛，不是追认原质量或性能通过，也不是下调98%／95%／90%或原时延数值。未通过的原门槛保留于只读P1账本；新阶段须按新课程契约单独设计验收、再获授权，不将不同轮次、模型、人工放行或目录成绩拼入自动分子。

## T040／T041／T042的最终含义

1. T040保持blocked，原全部失败、停止、未运行、模型与预算证据不删不改；不恢复未使用额度。
2. T041从todo标为blocked：依赖的质量门未通过，旧链动态学习／课堂性能验收暂缓。原HTTP首字节、完整首段、课堂、DSL指标未声明达标；新链性能在Phase 1.5按新课程契约、固定分母、失败处理及独立预算另行验收。
3. T042调整为“按批准的收敛范围完成P1退出与交接”，不再以T040／T041通过为依赖。依赖改为本阶段其余88项done；必须核对每项可达完成提交、当时验证记录及证据适用范围，完成交接、零调用检查后才done并提交。
4. 最终P1为91项：89 done、2 blocked。T042新增done仅表示交接完成，不替代动态质量、性能或所有Provider真实接入验收。

## 交接及归档

交接报告必须记录已交付工程／公开产品边界、Mock／真实PG／容器／浏览器／Provider的不同证据、未解决和延期取消事项、只读真实运行状态与已知用量。未取得账单的费用保持未知；预约数、预留金额与确认物理发送数不得混同，来源不完整的总量保持未知。

Ollama、Anthropic、Gemini、星火的原生适配器实现及离线验证不等于真实服务已验收；原延期继续保留。30节点知识结构不等于30套签核课程。空语义验证器注册表不提供真实自动计划重建保证。队列／DSL容器故障证据不等于动态课程质量或线上性能成绩。

H01–H08继续封存。已有输入／预标签签核只针对原契约，未运行不算通过；Phase 1.5在新课程契约确定后重新判断适用性、独立性和评测资格，不能自动继承、用来调优或发给模型。

T042交接检查通过后，将最终根task.json逐字节复制到docs/tasks/phase-1.json；在**同一治理提交**替换根活动账本并更新说明／追加日志。归档中使用Task-Completed查找T042同一提交，不写自引用提交哈希。历史阶段账本只读，只有根账本为活动事实源。

## Phase 1.5启动限制

新根账本只登记一个未领取的契约／独立验收规划任务；不是批准继续开发。初始Provider授权0，真实调用／重试／模型试错0；没有预算余额、冻结包、已通过标签或动态开放资格从P1转入。新链质量与性能必须重新冻结口径和独立证据，H适用性另审。后续拆分、实现或真实验收均需用户明确指令，不能以阶段切换自动开工。

依据与核验入口见[最终交接](../acceptance/phase-1-closeout-20261021/README.md)和[PRD](../PRD.md)。本决定不新增业务API、持久化模型或人工发布权限。
