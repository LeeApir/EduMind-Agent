## A. 固定输入和复用边界

实际目标表单输入原T108学习目标及先备知识，追加“本次明确使用 head-new-B：初始链表 [-8]，依次插入 6、0。”准确全文见执行包 `goal.txt`。程序将本批支持清单限定为已有head-new-B及准确规格；规划器仍真实生成目标、来源引文、场景目的、教学顺序与约定，但不验证自由选例能力。先备知识仍为自述，不冒称测得掌握。

复用T108的规划远端wire-v2/完整本地业务Schema、basis-v1、示例引擎、教学完整Schema、Responses缺省/final_answer适配、加密逐块原件、单前台入口及EduMind私有快照/版本/播放器/服务端答案。迁移0、Provider新接口0、独立播放器0、调度器0。

新增 `head-reuse-course-v1` 分支只用于本批新目标。旧T108精确兼容分支保留：旧父候选/四字段/最终摘要仍固定作为历史审核边界，**新候选不读取这些常量**。新父摘要由完整候选复算，修改位置和职责来自准确审核意见，最终摘要由合并输出复算，全部从记录重新验证。后续新候选、引用或审核目标变化不得要求再修改运行源码；若必须改，记本验证不通过并停止，而非临时补丁续跑。

## B. 首稿、恢复与审核驱动修订

- 首稿严格JSON/Schema/事实ID/题目情境/轨迹绑定。仅正文首稿内的 `questions` 四个既定题目键最多各2次且完全同类型同值时，可用既有 `head-questions-identical-duplicate-v1` 删除第二成员。原完整响应、严格失败、重复位置/摘要、派生摘要单独保存，不改原件，不计模型首次结构合格。修订响应不允许格式恢复。
- 每份完整候选独立逐段/逐帧/逐题审核。首稿或恢复稿无阻断问题则直接发布；不能为用满额度强制修订。
- 相对ADR0052仅minor措辞、以及随后仅F01/F02四字段事实例外，本批事前改为**最多一次审核定位的讲解段落及总结修订**。可纠正这些段落内事实、引用和表达；审核必须给出准确父摘要、basis绑定、finding ID、允许位置、原文引用、问题、可修复类别及原段教学职责。只允许 `paragraphs[i]` 的完整 `{text,fact_ids}` 和/或 `learning_summary`；动态生成封闭Schema，模型只返回这些替换项。不能改题干/解析/步骤说明/先备知识/失败与生命周期独立段/程序代码事实轨迹答案/原目标规划。上述不可改区域有阻断问题、协议/规划/程序材料/安全问题，直接停止。
- 合并不补教学文字，不自动修引用。程序校验父稿、审核引用/位置、text与fact_ids、全文Schema和全部材料绑定，拒绝相邻原段逐字复制。独立重评**全文**并明确检查引用逐项支持、原段职责、邻段近似复制、必要解释遗漏、代码/状态/答案一致及泄题。机械检查不能代替这些语义判断；修订后仍不通过即停止，不能再调一次或助手手改成功。

## C. 新批预算、入口与停止语义

拟 `head-reuse-r01`，最多 **3次HTTP：规划1、正文1、条件局部修订最多1**，新窗口600秒；旧额度/授权0继承。规划语义独立通过才生成正文；澄清或规划失败即停止。每次显式启动一个前台命令；没有自动下一请求。窗口未启动，当前实际新调用0。准确入口：

```
backend/.venv/bin/python -I scripts/head_course_goal.py --profile reuse --inspect
backend/.venv/bin/python -I scripts/head_course_goal.py --profile reuse --prepare --vault <new-vault> --owner <actual> --course <actual> --operation <actual>
backend/.venv/bin/python -I scripts/head_course_goal.py --profile reuse --send plan|generate|repair --vault <new-vault> --approval <new-approval>
backend/.venv/bin/python -I scripts/head_course_goal.py --profile reuse --publish --vault <new-vault> --approval <new-approval>
```

`plan|generate|repair`表示三种独立选择，不能把此行原样当shell多命令执行。`--publish`不调用模型。实际命令需干净环境和仅专用开发库配置；Key只在getpass提示下隐藏输入，不读项目.env、不通过环境/argv/聊天代入。新vault0700、raw.key0600仅用于响应加密，不是Provider Key。

固定DeepSeek官方 `https://api.deepseek.com/responses`，deepseek-flash，Responses/json_schema(strict)，reasoning none，temp0.2，stream/store false，无工具/重试/回退。规划/正文输出各8000，修订4000，合计最多20000输出预约；输入每次本地预约139264，合计417792（不是账单硬限），请求131072字节，响应2MiB，I/O90秒。金额未知，没有可验证金额硬上限。

**新批C2需单独接受**：沿用单前台尽力停止；最后检查后进程暂停仍可能迟发/继续计费；本机原件无独立抗回滚保障；无可验证金额硬上限。仍受T102已知暂停/迟发反例影响，不能默认为T102解除。Ctrl-C或写STOP阻止下一次显式运行，不保证撤回在途请求；未知、部分原件、异常、超限或窗口到期即保存失败并STOP，不续窗。保存完整原响应后解析，失败保留ACTIVE/失败/部分文件，不重启旧批。

## D. 证据与产品契约差异

私有最终生成记录包含准确目标/真实规划请求与原响应、规划评估、首稿原响应/严格失败或恢复记录、可选父候选/审核/替换输出、最终完整评估；独立审核pass才能原课程v1→v2，使用既有答案私有投影、临时评分和课程内掌握度，不能获正式签核资格。`sent_attempts=1`和usage表示该最终生成行对应的**最后一次HTTP**，父请求/用量均保存在只追加原件和lineage中，不借该列伪称全批仅1次。

公共 `HeadGenerationSource` 以不相交的新协议分支表达 `head-reuse-r01`，现有历史分支结构逐字保留。来源分别为原首稿、程序格式恢复、或审核驱动模型局部修订（含可选格式恢复祖先）；`offline_fixture`明确不计真实成功。摘要取候选记录而非源码常量。页面正文和演示替代文本统一由同一候选重新装配，题组/页面版本绑定原私有反馈流程。新目标仍只在显式开发配置和专用数据库可用，不开放生产动态。

批准前只评估准确接线/请求/检查；批准后必须交新课程及实际阅读、13步演示/控制、四题错答及正确反馈、整页刷新相等、独立教学评估。首次结构/恢复/修订各自统计，助手补写0。失败保留准确位置影响，不以Mock、回显、HTTP200或准备评审替代新课程；T109保持未完成。结束后停止，由用户决定后续，不启动T038或扩主题。
