# ADR-0015：共享教学计划、场景生成与混合审核

状态：**Accepted，2026-10-15用户批准补齐最小契约/兼容设计后的A–D；准确摘要见批准登记**。日期：2026-10-15。设计任务：PHASE-1-T043。

用户已选择“参照OM重构生成、保留自动审核，部分无法自动审核交人工”的方向。方向选择后，本稿按用户本次要求补齐数据契约与旧功能兼容，用户明确批准更新后的A–D。T043只交付方案，T044–T054是已获零调用实现权限、尚未实施的任务链。默认仍为catalog_only，新增真实调用授权为0。

## 背景与取舍

现有LearningUnitGenerator分三次生成讲解、代码、练习，共享节点和目标，但没有一份绑定具体示例、表示约定与教学顺序的计划。ReviewAgent逐资源审核，最多两次修正；finalize_learning_unit要求三类全部通过才开放首场景。当前审核器没有显式“不确定”结论，拒绝与不可用也不适合作为人工工作流状态。T040旧路线已停止，不能通过再补一条Prompt把它恢复成第三轮。

参照OpenMAIC提交`ecb940c136cc5b4ea56dc81b2505e64eff1dea29`的“资料/需求→大纲→场景内容→授课动作→组装”分工；该流程中的大纲确认和结构校验不等于事实审核。来源与观察边界见[源码核对](../reference/openmaic/generation-review-20261015.md)。本项目保留Vue/FastAPI/PostgreSQL、知识图谱、渐进画像、现有Provider Gateway和Manim安全边界，不移植通用编辑器、PDF/联网研究、TTS、任意HTML/JS或完整多角色生成。

## A. 共享计划与场景流水线

### A1. 一份计划，三个有顺序的场景

首版只生成一个知识节点的学习单元，包含固定的三个场景角色：`explanation`、`code`、`exercise`。每个场景关联一份同类型资源；题目仍为约3道客观题，代码仍display_only。三个场景是教学组织，不新增三套独立课程，也不强制学生确认内部大纲。

```text
目标/节点/有据画像/版本化参考
  → 一次计划生成 → 本地计划契约校验 → 保存不可变计划
  → 讲解生成/本地检查/独立审核与最多两次修正
  → 代码生成/本地检查/独立审核与最多两次修正
  → 练习生成/本地检查/独立审核与最多两次修正
  → 确定性组装受约束授课动作 → 整单元一致性检查 → 原子发布或人工复核
```

具体执行时，后续内容生成使用前序最终候选；每份资源审核后才能继续依赖它的场景。`needs_human`候选可留在私有工作区继续组装供人工完整复核，但整单元不得自动发布。硬拒绝、不可用和超限立即结束。内容全部形成后，先确定性组装动作，再以计划、三资源、动作的完整摘要执行一致性审核；动作不会在审核后偷偷新增事实。

计划包含：节点/图谱/画像证据版本、学习目标、限定先修、语言、术语、索引起点、容量/状态表示、共享示例及预期轨迹、三个场景的目标与依赖、参考条目ID。ID、摘要与顺序由服务端分配/校验；模型不计算坐标或SHA。未知画像保持未知。缺少会改变结论的约定、未知参考或越界节点使计划无效，不凭默认值补成正确答案。

共享示例与预期轨迹也是模型生成的待核对主张。不能拿计划中的答案反过来证明代码或练习正确；独立审核必须依据实际候选、可信参考、可验证反例和明确约定。不增加RAG系统，使用当前版本化知识结构和明确登记的参考摘要；参考没有覆盖的事实应标未知，不能声称已被图谱证明。

计划最多8KiB；三资源内容合计最多48KiB，完整单元检查数据最多64KiB（UTF-8序列化后的字节，不是Token）。各类内容继续服从其schema。超限失败，不裁掉代码尾部、答案或参考以凑限额。具体token费用界仍在真实轮次冻结时证明。

A1的规范性结构见[最小数据与兼容契约](../acceptance/phase-1-om-redesign/data-and-compatibility-contract.md)及[JSON Schema](../acceptance/phase-1-om-redesign/minimum-contract.schema.json)：冻结模型计划正文、服务端标识、版本/摘要绑定、不可变字段和审核结果；T044先按此持久化，后续不得另改字段语义。

### A2. 授课动作独立组装，但首版不增加模型调用

受信模板生成`show_resource`、`highlight`、`ask_exercise`三种内部动作。动作仅引用准确资源版本、服务端文本片段锚点或题号；不接受任意代码、HTML、网络地址或新讲解文本。先呈现讲解，再呈现完整代码和关键步骤，最后进入题目。模板不能编造教师/同学发言。动作版本/引用/顺序及摘要参与整单元检查和人工案件绑定。

这是对OM内容/动作分离的有限采用。自然语言授课脚本、多角色动作和语音保留后续范围，不借本次重构提前实现。

### A3. 调用上界与等待

正式链路基线最多8次：计划1、三类生成3、逐资源审核3、整单元一致性1。每资源最多两次定向修正，每次增加生成1和完整资源审核1，最多另12次，合计**20次**。一致性不合格不启动全单元自动重生成循环。临时画像/首屏临时流各至多1次，若使用则同一操作总上界**22次**，实际每次都计费/计数。动作与人工CLI均0调用。

所有阶段共享180秒生成/审核绝对截止；单次至多60秒且不超过剩余期限。20/22是请求上界，不承诺一定跑满。修正产生新摘要，后序依赖必须失效并重新构建；若剩余次数或时间不足则失败，不复用旧审核、不自动重开预算。不因“原来某步已经生成”而不计重建调用。计划输出上限2048、资源生成/修正4096、资源/一致性审核2048总输出Token（均含推理）；真实轮次可缩紧但不能绕过冻结批准扩限。默认零传输重试、零隐式回退，依旧通过Gateway逐次预算预留；不改现有选定厂商或推理配置。

临时首段仍按现有规则显示为未审核文本，与正式课程分开计时，不把计划状态或心跳当作教学正文。首次完整单元与正式发布延迟另测。180秒限制模型生成/审核阶段；待人工结束在线生成，人工等待/复核不占该模型期限、不占模型连接，也不承诺人工处理时限。人工决定与发布不再发模型请求，不能重新打开已结束的模型窗口；若需要新内容或政策重验则旧案失效，须显式新操作。

## B. 自动判断、硬门禁与人工路由

### B1. 职责与四种语义结论

本地程序检查：schema、长度/计数、来源/摘要/owner/版本、禁用执行原语、客观题格式及引用一致性、动作引用。可为有明确表示的示例增加独立状态模型检查，但不能声称这些规则证明所有C程序安全。本次不新增执行任意生成C/Python的通用沙箱；Manim仍走原受限DSL链。

资源语义审核新协议`resource-review-v4`：`pass`、`revise`、`reject`、`needs_human`。每条发现提供原候选字段/锚点、实际条件/反例、影响与类别；`coverage`明确检查范围，`unresolved`保存未知项。引用有效不等于判断真实，不以模型自报置信度充当事实证据。新解析器与旧v3显式隔离，不能把缺字段旧响应当新协议pass。

| 情况 | 路由 | 是否可发布 |
| --- | --- | --- |
| 本地硬规则失败、来源/身份失配、schema无效 | failed/硬拒绝 | 不可；人工也不能豁免 |
| 有据具体严重缺陷，模型reject | rejected | 不可；修正须新候选重新走流程 |
| 模型revise且有剩余预算/轮次 | 定向修正，完整重审 | 当前候选不可 |
| 明确表示不确定、前提有歧义、覆盖不完整、审核意见证据不足 | needs_human | 等人工 |
| 两次修正后仍有可解析语义问题 | needs_human | 等人工，保留全部原问题 |
| 资源与整单元检查均pass、无未知项、全部本地资格有效 | 自动资格通过 | 原子发布后可用 |
| Provider超时/无效响应/凭据或预算故障/总期限耗尽 | failed | 不可；不自动用人工旁路掩盖调用故障 |

本地能识别的“只有标签、没有实质证据”等问题转人工；它不保证能识别每个流畅的错误反例。模型仍可能自信漏检或误报，必须由独立真实验收衡量。分类`fact/misconception`错配与实际缺陷漏检分别记录，不因改一个标签自动变成事实正确。

一致性审核使用同样的pass/reject/needs_human表达，核对三资源的表示、同一示例、算法行为和题目答案；不输出代码补丁。有据的具体严重缺陷返回reject并结束；其余未决跨场景冲突返回needs_human。只有全部硬门禁有效且没有当前候选reject时，任一场景待人工或一致性needs_human才使完整单元进入一个人工案件，不拆成多个局部pass拼出整篇通过。判定优先级为硬失败/调用失败→当前严重reject→needs_human→全部pass；人工不能接管一个已经reject的当前候选来变相放行。

### B2. 人工只处理语义，不绕过硬边界

人工查看完整计划、三资源、动作、版本化参考、原自动发现与修正记录，明确approve/reject并写理由。只有B1所述仍待判定的needs_human案件可批准；当前候选的有据严重reject不是可人工豁免项。approve代表此准确整单元的人工语义结论，不把原needs_human或历史修正意见改写成模型pass。发现内容需要修改时拒绝原候选；修订生成新版本和案件，不直接编辑已批准内容。

人工不能豁免schema、本地禁用代码规则、owner/来源、失效版本、撤回、取消、SSRF、预算或Manim沙箱。无审核人时保持等待，学生可继续已有目录课程；不自动将待审内容作为降级课程、不假定审核必在几分钟内完成。

## C. 数据、权限与发布契约

### C1. 不可变绑定与复核主体

通过Alembic新增`learning_plan_versions`，保存owner/单元/版本、规范计划JSON、内容与输入/参考/政策摘要；`generated_resources`增加可空plan引用，旧数据不回填成新协议已验收。新增`learning_review_cases`和只追加`learning_review_decisions`：案件绑定owner、操作、计划、三候选ID与摘要、动作、整单元摘要和政策版本；决定保存准确案件digest、复核人标识、理由、时间、approve/reject和幂等键。复合外键与事务校验拒绝跨owner/跨单元引用；当前有效案件唯一，旧决定不能复活。

候选仍可用现有pending/passed/rejected字段；pending不包含任何发布资格。`passed`表示最终发布资格，具体来自`approval_source=auto|human_assisted`，不是伪造模型审核结论。实际自动原结果、人工决定及其绑定分开保存。不得构造一个假的ReviewOutcome(pass)来调用旧发布函数。

首版人工入口为**受信主机上的维护CLI**，不新增公网管理后台或学生审核API。复核人必须来自服务端维护allowlist，CLI依据受信本机操作者配置验证身份并记录来源；此边界信任维护主机及其配置，不声称本地JSON或一段姓名是密码学身份凭据。学生Cookie、用户自报reviewer、模型文本和任意`passed=true`文件均不能签核。若未来要浏览器远程多人审核，须另设计账号/角色权限，不复用学生身份。

CLI接口拟为`python scripts/review_learning_cases.py list|show|decide`，decide必须提供case ID、期望case digest、approve/reject和理由；正文只在受信终端按需查看，默认输出摘要，导出须显式指定路径。CLI不读Provider Key、不调用模型、不执行候选代码，也不能替用户自动填入人工通过。

案件/决定在同一单元行锁下处理。取消、撤回、计划/政策或候选变更使尚未发布的旧案失效；审批与发布共享锁与摘要重检。失效案件不可重开，原操作结束为failed（固定码REVIEW_CASE_INVALIDATED）；已取消仍保持canceled，已删除按既有owner删除语义处理。显式新生成创建新操作/案件，不让旧操作永久停在awaiting_human。已正式发布后的撤回只追加撤回事实并阻断资格，不倒改历史completed或旧审核结论。重复同键同决定只返回原结果，不重复发布；相同键不同内容409/CLI冲突。删除沿既有owner学习数据级联规则，不把敏感正文复制到通用日志/队列。

### C2. 原子发布与兼容

三个场景、三资源、一致性结果和最终审核来源全部有效后，在一个短事务里开放完整单元。待人工/局部通过不能从正式资源、测验、Markdown导出、路径课程资格或动画接口读到未审正文。不能先让record_reviewed_resource逐个设published_at，再在单元失败后仅隐藏页面。生成和人工审批期间不持有长数据库事务。

目录版的旧人工课程签核与allowlist保持原资格，已发布版本不重新打分。新语义审核政策只适用新链路；旧资源不能靠添加plan_id或新标签升级。重解释创建新候选/版本，重新核对相同计划或明确新计划；未改资源是否可复用须摘要和依赖完全匹配，不能继承失效人工批准。

三场景与旧入口/重解释的映射、发布快照和失效矩阵按[兼容契约§4–5](../acceptance/phase-1-om-redesign/data-and-compatibility-contract.md)执行：legacy保留intro；planned入口为explanation，intro仅作请求别名；关联代码按同一发布快照取得，不按单场景或各自最新版本拼接。换示例重建计划与三资源，simpler/deeper重绑后重新审核；旧已发布完整版本在新候选失败/待人工时保留。T052实现服务适配，T053同步界面/OpenAPI，T054复核。

### C3. 学生可见状态与接口增量

沿现有owner-scoped操作GET、学习单元GET和POST fetch SSE增加`phase`：planning/generating/reviewing/consistency_check/awaiting_human/publishing。操作新增`awaiting_human`等待状态和`rejected`终态；原有failed/canceled/completed语义保留，待人工不是completed。

操作GET增加可空`review_summary`，只含state（pending/approved/rejected/invalidated）、approval_source、等待原因固定码和更新时间；不公开审核人信息、内部发现全文、未审候选或维护路径。SSE新增`review_required`事件携带操作ID及固定原因码，随后`done`携带`status=awaiting_human`，表示流结束而不是课程已完成。人工审批后的终态通过原操作GET读取，不承诺回放旧token或永久保持SSE。仅页面可见且用户仍查看时有界轮询，离开/取消停止；同幂等键只读原操作，不自动重发模型。

收到待人工状态，前端保留已有课程/进度，明确“内容待人工复核，暂不可作为正式课程使用”，不提供无依据ETA。批准后显示真实正式版本和human_assisted来源；拒绝/失效保留原因固定码并允许用户显式发起新操作。课堂publication_version、重解释409及新发布事件按兼容附件明确；接口schema、SSE示例和前端类型在T053一起落地；本稿不直接修改现行OpenAPI来假装接口已实施。

## D. 新验收与实施顺序

完整计划见[重构验收方案](../acceptance/phase-1-om-redesign/acceptance-plan.md)。继承首次schema≥98%、自动正式成功≥95%、严重错误召回≥90%、分类≥90%、正确对照pass≥95%、长审核完整率≥95%及既有性能目标。人工兜底不补任何自动指标分子；分别报告自动完成、转人工、人工批准/拒绝/未处理及混合最终可发布。

对ADR-0011作已批准的**仅新链路补充**：原独立Prompt四组13次诊断不再是新架构的唯一前置，改为先跑离线门禁，再以新链路的8类诊断验证共享计划/多场景/人工路由；具体请求清单与预算后续另冻。分类错配在新诊断单独记录，不单凭类别立即停止后续独立诊断；正式分类≥90%门槛仍保留。泄漏、硬安全失守、具体严重漏检、重大编造断言、身份/预算/协议故障仍立即停止，未运行槽保留。该补充只用于新链路，ADR-0011历史批准及旧轮次判定不改。

新正式集继续独立冻结100目标生成槽、20严重错误/20正确对照/10长审核；适配新上下文不把预期标签发送给模型，人工先核对新标签，不能用旧诊断调参分数替代新例。旧T033/r01–r11失败、退休路线和账本不改，旧预算不继承；新架构不是给旧r11加Prompt的第三轮。

T043设计→T044计划持久化→T045计划生成→T046场景内容→T047动作/T048资源审核→T049一致性→T050案件持久化→T051维护CLI→T052混合原子发布→T053阶段界面/API→T054冻结离线验收准备→T040独立真实质量→T041端到端性能→T042退出。每项独立验收/本地提交，仍单工作区串行执行。
