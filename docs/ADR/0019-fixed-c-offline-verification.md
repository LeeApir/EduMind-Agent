# ADR-0019：固定 C 样本的离线验收与隔离（T065）

日期：2026-10-19。状态：**Proposed；具体 A–D 与附件待批准。未编译、未运行样本。**

依据：[PRD §0.3](../PRD.md)、[任务规划 §3](../acceptance/phase-1-review-binding-offline-plan.md)及根任务 T065。T056–T064 已独立完成，教学绑定最后提交为 `8a9b38f`。本设计不改变审核 v4.9、教学绑定、旧运行记录或生产默认 `catalog_only`。

## A. 固定样本准入与独立真值

只接收冻结清单里的两个样本：EduMind r02 头插法原程序，以及同输入 OM 封存课程的原程序。来源统一使用**已跟踪**的 `docs/reference/head-insertion-tests-20261019/`，不读取另一个未跟踪 OM 工作目录。准确来源和历史驱动摘要见 [cases.json](../acceptance/phase-1-fixed-c-design-r01/cases.json)。这些摘要只是限定可准入原件，不说明它们正确或准许现在执行。

T066 从原学习候选/OM manifest 复现提取并逐字节比较：不得补换行、补 typedef、改函数签名、修改调用或自动修复 HTML 中的 C 语句。记录源字段/场景、字符或块范围、实体/排版转换及输出字节摘要。OM 函数驱动中的测试别名与正确 Node** 调用是**派生测试环境**，必须与不可编译的原 main 分开。

原件、原程序、函数片段、派生驱动、独立规格分别有摘要。新驱动仅可实现附件固定接口和故障矩阵；T066 由本地维护者逐项审阅原件映射、驱动 diff、独立预期后登记身份、时间、文件摘要和准入版本。**缺审阅记录或摘要变化即拒绝执行**，不通过生成 manifest 自动预填 reviewed。该技术审阅不等于用户对课程的人工签核。

不提供任意路径/源码字符串/命令/编译参数入口，不从活跃生成结果自动领取代码。CLI 仅允许本批样本 ID 与已登记 case ID。后续接入新样本或接口需新的准入，不得通过模型 expected_output 或计划轨迹生成测试真值。

## B. 独立工具链与隔离

采用 Docker Desktop Linux VM 内的一次性非特权容器；仅面向本地维护者已审阅的固定样本。它不承诺抵御容器内核漏洞，也不是向不受信任公众开放的通用沙箱。

提议工具链为 **Linux arm64、Clang 19.1.7、C11、ASan+UBSan**。基础镜像固定为现有公开 `manimcommunity/manim@sha256:89ab433ce59134a4dcf351deb2511e067ab354393c0bb7d1859f3e8f0b2406a3`。只作为已固定 Linux 基础层；不调用 Manim，不复用应用镜像或含凭据的项目构建上下文。

本次只读取了未启动容器的包清单：存在 libllvm19，但没有 clang 编译器，故**当前执行环境不就绪**。拟在获准后的 T066 准备独立工具链层：从 Debian 官方签名的 trixie 仓库快照 `20251015T000000Z` 取得 `clang-19=1:19.1.7-3+b1`、`libclang-rt-19-dev=1:19.1.7-3+b1` 及解析出的依赖。官方当前包页确认这两个 arm64 版本存在（[clang](https://packages.debian.org/trixie/clang-19)、[runtime](https://packages.debian.org/trixie/libclang-rt-19-dev)）；这不证明该快照可下载或本地能运行。

准备阶段允许仅向官方 Debian 元数据/包源下载，验证签名、版本和 SHA-256；不得关闭签名验证、隐式使用更新版本或使用第三方镜像替代。缓存完整依赖包、记录其逐包摘要后，使用只有 Dockerfile/已核验 deb 的最小目录离线构建，`--network=none`；不向构建器传环境凭据、项目目录或样本。基础镜像应已本地存在，缺失只允许按同摘要取得原件。构建后固定最终 image ID、平台、包清单、clang/linker/libc/运行库版本与 controller 摘要，形成 T066 工具链锁；没有最终锁不运行样本。预检或下载失败记录 blocked，不自动改工具链。

**编译和运行使用同一隔离配置**，具体数值/命令边界见 [执行契约](../acceptance/phase-1-fixed-c-design-r01/execution-contract.md)：禁网、无端口、UID/GID 10001、drop ALL、no-new-privileges、默认 seccomp、只读 rootfs、只读最小包、无宿主 socket/设备/项目/凭据挂载、1 CPU、512 MiB 内存且不加 swap、64 PID、128 MiB 工作 tmpfs、16 MiB 临时 tmpfs、有界输出和强制超时。ASan 需要虚拟地址保留，不设置 RLIMIT_AS；物理内存由 cgroup 限制，不因此放开内存上界。

每个 case 使用新容器：可信 controller 在 tmpfs 编译并只运行该 case 的新子进程；二进制和 C 源均不在宿主执行。容器输出由宿主有界捕获，不用样本输出来驱动命令。超时/输出超限杀整个容器，保存结果后删除；不重试，不降级到宿主 clang。预检须验证实际 inspect/限额及禁网/只读/非特权/输出与超时负例，声明参数不等于隔离已生效。

## C. 检查矩阵与结果契约

[矩阵与独立预期](../acceptance/phase-1-fixed-c-design-r01/cases.json)固定：严格原程序、普通原程序、原 main 实际正常输出、main 包装和独立接口各 0/1/2/3 分配失败，以及三个受控反例。只检查从空表按 1、2、3 头插的固定域，不外推任意数据、并发或其他课程。

严格编译 `-Wall -Wextra -Wpedantic -Werror -Wnewline-eof` 与普通编译去掉 `-Werror` 分列；两者均 C11。Sanitizer 编译/运行与普通编译也分列，不用普通成功掩盖 Sanitizer 未运行。新 Linux Clang 的实际结果与历史 Apple Clang17 结果各自保存，不复制旧通过、不覆盖旧失败。

EduMind 保留原件缺末尾换行的严格失败，普通运行中数值 `[3,2,1]` 与原始 stdout `3 2 1 \n` 分别核对，模型的 `3 2 1` 只作被核对陈述，不作真值。OM 原程序若编译失败，其所有 main 运行均 `not_run: compile_failed`，不能把独立函数驱动通过算原程序通过。OM 失败路径应检出 NULL 解引用，但不能从未定义行为推导确定输出或未执行的释放数量。

每次插入验证 head/next、全部节点值、顺序、链长、失败保持旧链、每个实际分配恰好释放一次；明确区分 EduMind 调用者置空和 OM Node** 释放接口。显式 tracker 的覆盖证据不改名为 LeakSanitizer：本轮固定 `detect_leaks=0`，LSan 标记未运行。ASan/UBSan 无报告也只代表所运行路径。丢链、重复释放和错误调用者赋值的派生反例必须失败，并与原件分开。

结果字段、状态、限额和退出条件在执行契约中冻结。必须保存 stdout/stderr 原字节（有界）、退出码/信号/超时、完整命令数组、全部绑定摘要和实际分配释放证据。区分程序 `pass/fail/not_run/unsupported` 与 `expected_observation_matched`；“正确发现坏程序”不能变成“程序通过”。协议校验失败不能记通过。

## D. 实施、预算与批准边界

获准后串行 T066 准入/工具链锁 → T067 编译/输出 → T068 故障路径 → T069 证据整合 → T070 零 Provider 集成及真实验收准备。每任务单独验证、提交；不提前把本提案算 T065 完成。

单个离线运行上限：**64 次编译、40 次样本子进程、20 分钟总窗**；逐 case 无重试。原定负例/坏程序的预期失败是证据；基础设施/隔离失败或未预期的协议/断言失败则停止，保留已完成和未运行项。新一轮修复遵守“两轮实质修复失败求助”规则，不能反复扩额跑到通过。

新增模型调用、Token 和模型费用均 **0**。批准可包含上述官方包准备/离线镜像构建与固定域执行，不包含真实 Provider、自动人工签核、课程发布、掌握度改写、动态开放或线上执行入口。T040 原阻塞、旧路线及额度不改；离线通过不等于模型审核 pass。

请批准 **A–D 及 manifest 列出的准确附件**。隔离不可用时保持停止，不另请无隔离宿主执行作为替代。
