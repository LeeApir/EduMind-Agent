# ADR-0048：分开协议回显、实际修复与包装诊断

2026-10-29；**Proposed，供评估助手审查；未批准实施或真实调用**。PHASE-1.5-T086只做离线方案、准确示例和原始失败回归。依据用户新指令，当前Schema/严格校验、T085失败/停止及所有冻结包不改。

## A：三种任务使用不同成功判据

采用[任务与成功条件](../acceptance/phase-1.5-separated-protocol-repair-r01/TASKS.md)及准确输入示例。

- P0只回显expected_output，输入不带修复任务、旧候选或算法语义。成功必须是严格协议/JSON/当前Schema/本地规则通过，且逐值等于该目标。
- W0–W4继续执行同一个回显任务；所有附加字段明确为不执行的数据。只改变预注册的一个包装因素，不让模型同时做修复。
- R0才要求真正修复一条普通教学措辞意见；输入有完整手写合成旧候选/原始规格/准确意见，没有expected_output或指定修复答案。输出为完整B候选实例；通过当前严格校验和改动范围检查后，还必须独立教学复核。合规但不同的改写都可接受，不能用固定字符串相等判定修复成功。

R0将本次诊断允许改动限制为一段文字，用于单独验证修复行为；它不是原B整候选修复范围的等价替换，也不改变正式教学标准。新任务说明仅存在提案输入文件，不接线或替换现有Prompt。

## B：有限、可解释的包装对照

采用[matrix.json](../acceptance/phase-1.5-separated-protocol-repair-r01/matrix.json)。聚焦T085 S5所用B完整输出Schema；其余三种输出Schema保持原字节，只核对冻结，不把本诊断当整套角色准入。

P0→W0仅新增空role_input。W1/W2/W3/W4分别从同一W0独立分支，仅新增protocol_stage、original、issues或original_input。准确JSON Pointer和JSON Patch随矩阵冻结，不能累计添加字段后把差异说成一个变量。系统指令、目标、Schema、strict、模型/参数、上限与顺序保持一致。

每个因素是一个明确定义的字段/固定内容块的“是否存在”。整块增删同时影响长度/内容，不能据此区分块内某句话、长度效应或模型采样。每例一次且共享对照，不能给出因果证明、稳定失败率或统计显著性；不同任务R0不参与回显因果对照。新指令不同于T085，旧S4不能当新P0的对照分子。

## C：保持严格拒绝，加入实际失败回归

[原始文本与来源](../acceptance/phase-1.5-separated-protocol-repair-r01/fixtures/provenance.json)绑定T085 S5响应SHA和原message.text SHA。保存的是准确3306字符输出文本，不含传输ID/凭据；私有完整原响应不迁移到Git。另提供明确标为派生的合法Schema和解析前缀反例。

新增回归调用现有冻结的严格observer/解析器：原始非法文本、合法JSON却返回Schema、截取前缀、多个JSON、代码围栏、重复键、非有限数值和额外字段均继续拒绝。不能修括号、取第一个对象、删除字段或把Schema当答案。当前Schema/observer/校验器/旧断言不修改。

R0的结构/改动范围合格不保证新讲解正确；故意错误但符合结构的改写仍交独立语义审核，不能让程序用关键词或参考改写文本代签。

## D：仅设计；审查后才申请新包

本轮真实额度0、无Key/DNS/Provider调用、不重启T085。未来若评估同意，可另备最多7HTTP的S5聚焦诊断包：P0、W0–W4、R0；DeepSeek官方/deepseek-flash/none，参数沿当前配置，单例一次、无重试/自适应加样。新900秒、单HTTP60秒、DNS9秒；输入占额57344、总输出请求上限28672。费用/币种/费率和准确控制器在审查后另冻，旧7次许可、未用2次和金额例外均不继承。

任何协议/严格校验/回显/来源/用量/预算异常立即全批停止。R0收到后如只完成机械检查，则网络阶段终止为待独立语义复核；不能自动算成功。实际新入口尚未实现，不能用T085回显observer直接评判不同成功条件的R0。全量角色、课程实验及原10支持＋4拒绝/教学阈值不因本诊断解除。详见[审查入口](../acceptance/phase-1.5-separated-protocol-repair-r01/README.md)。
