# ADR0056：P2 学习界面与 OM 迁移、原 P2/P3 合并

日期：2026-11-09。状态：阶段归属与产品方向已由用户确认；具体迁移架构、接口及实现验收细则待设计。本次仅同步规划，不启动新阶段。

## 决定与来源

用户先确认学习页面使用三个标签切换；演示课堂先保留讲解动画、课件切页等基础功能，直接复用 OpenMAIC 的做法。随后明确要求：

> 放在新阶段P2，OM迁移设计任务完成有一定复杂
> 把原来的P2 P3任务合并在一起

据此，新 **Phase 2** 专门承接三标签学习界面与 OpenMAIC 演示课堂迁移；原 Phase 2、Phase 3 的需求合并归入新 **Phase 3**。这里的 OM 指 THU-MAIC/OpenMAIC，不把此前 MAIC-UI 交互参考与 OpenMAIC 播放器迁移混为同一项已完成能力。

旧 P2/P3 仍是路线图需求，尚无对应活动执行任务；本次合并需求归属，不创建任务完成记录。PRD §9.1 是现行阶段入口，历史文档中的旧阶段编号保留原时点含义。

## 新 P2：三标签学习页与 OM 演示课堂迁移

学生在同一门课程内切换三个标签：

| 标签 | 首版目标 | 复用基础 |
| --- | --- | --- |
| 演示课堂 | 课件切页、讲解动画、讲解文字及基础播放控制 | 优先复用 OM 原有课件渲染与播放实现，先验证适配范围 |
| 讲解详解 | 完整文字、代码、可步进动画、边界与收尾说明 | 现有 EduMind 课程内容及代码／状态演示 |
| 随堂练习 | 当前课程题组、提交、反馈与作答恢复 | 现有服务端练习接口、私有答案和课程内反馈 |

三个标签共享课程、场景、示例和准确版本。第一栏呈现的算法状态来自程序管理的事实和轨迹；课件展示效果不得改变这些事实。离开演示栏暂停播放，返回保留页码；其他栏保留阅读位置和未提交答案。刷新恢复的准确粒度、旧课程缺少课件时的呈现及版本失效处理在迁移设计中明确，不把这些细节写成已实现。

### 先设计再实施的交付顺序

以下为阶段交付分组，不是可领取的任务或第二份状态账本。阶段启动时再拆为符合项目粒度的执行任务。

1. **OM 迁移设计。** 明确并固定上游版本、源码与依赖范围及许可证；列出能直接复用的播放器／渲染模块、必须适配的部分。对照现有 Vue 应用与 OM React 实现，验证嵌入或组件接入方式，交付选型依据和可运行的最小验证。定义课程材料到课件／动作的数据映射、状态同步、生命周期、资源加载与错误处理。独立播放器嵌入只是候选方案，尚未选定。
2. **三标签页面及已有课程接入。** 确认页面设计后，以一门已有且经过教学评估的课程完成实际应用接线；来源明确，不新生成或改写教学事实。OM 课件和动作的映射同样须核对遗漏、顺序和语义，不能只验证页面可播放。
3. **完整学习体验验收。** 验证切页／动画／播放控制、三栏切换、课程版本绑定、阅读与作答恢复、服务端反馈，以及桌面／手机／键盘使用。验收实际应用中的整门课程，记录保留功能、适配差异和未支持能力。

P2 的基础范围不自动扩展为移植 OM 整站、运行框架、生成链或教师编辑器。语音讲授、角色发言和实时提问未纳入这次确认的基础范围。模型自动生成 OM 课件属于另行明确的生成输出与审核需求，不能在迁移过程中隐式加入。

阶段退出方向：迁移设计落实为可复用的接入路径，实际应用中的已有课程可完成三栏学习，内容和状态保持一致、既有课程及练习权限兼容。准确验收用例与性能要求在 P2 设计时细化；当前未宣称设计或实现通过。

## 新 P3：合并后的深度学习与扩展能力

保留原需求及原有约束，合并不等于取消或一批全部实施：

| 原归属 | 新 P3 保留内容 |
| --- | --- |
| 原 P2 深度学习体验 | 画像增强、画像驱动动态分级练习、真并行辩论、更多角色策略、教材问答／RAG、学习报告、更多课程 |
| 原 P3 扩展能力 | iOS、PPTX／离线 HTML 等高级导出、模板市场；“更多课程”与上一行去重合并 |
| PRD 中原后续能力 | 教师创作及大纲编辑等仍属后续范围，不因 OM 播放迁移提前进入新 P2 |

画像增强与动态分级练习保留原“优先细化”安排，练习仍按已登记需求动态生成，不能默认为仅固定题库。原深度学习体验的发布标准及小规模真实用户测试要求保留；iOS、导出和市场仍由真实使用需求决定，不成为 Web 迭代的强制前置。P3 启动前按实际需求细化批次与退出标准，不在本次新增一套庞大执行清单。

## 与当前 P1.5 的衔接

- 根 `task.json` 的活动阶段保持 Phase 1.5，现有 Task 对象、依赖、状态、验收条件与调用授权不改。本次只更新已有未来阶段摘要及旧阶段称谓说明。
- 三标签和 OM 迁移不加入 P1.5 的完成前置，不扩大正在验证的冻结范围。T038、T102、T111 等未完成项继续按各自证据处理，不因阶段重排解除。
- P1.5 保持 DeepTutor 提示词组织、MAIC-UI 交互要求、程序共享代码与轨迹的原方向；P2 承接新增 OM 展示迁移，不改写旧通过或失败结论。
- 本次不归档或切换活动账本，不领取新阶段任务，不调用 Provider，不修改运行代码或旧冻结设计。P2 实施在现行阶段门禁满足并获明确启动指令后进行；若要提前启动，须另行明确并行范围和任务隔离。
- 后续修改具体 API、持久化或安全边界时，基于准确迁移设计记录相应决定。本 ADR 仅确认方向与阶段归属，不预先批准未知技术契约。

## 交接与验证

本次同步 PRD §9.1、当前功能章节的阶段归属、AGENTS 路线图和根账本的未来阶段摘要。历史需求稿、旧任务规划、批准包与归档保持原字节；PRD 补充旧阶段编号和 P0/P1/P2 优先级标签的解释，避免把低优先级标签误当新 Phase 2 范围。

实际验证（2026-11-09）：

- `python3 scripts/check_catalog_workflow.py` 通过；`git diff --check` 通过。
- 本地 Python 逐值比较修改前快照：111 个 Task 对象、活动阶段、执行策略及授权保持；JSON 只变化 `/phases/2/goal`、`/phases/3/goal`、`/stage_scope/excluded/0` 三处路线图说明。
- 原 P2/P3 功能逐项映射完整；新增 ADR 链接可解析；历史 P1.5 需求稿与任务规划文件 SHA256 不变，执行日志只追加；运行源码、归档及旧冻结界面包无改动。
- 执行者复读确认阶段归属、首项迁移设计、未定嵌入架构和历史编号含义明确。另行发起的独立文档复读因评估工具额度限制未完成，不记为独立通过；本次未运行业务测试，也不新增课程质量成绩。

下一步由用户继续补充 P2/P3 需求；当前开发助手按原 P1.5 授权和任务边界继续。进入 P2 时首先交付上述 OM 迁移设计。
