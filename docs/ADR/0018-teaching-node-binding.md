# ADR-0018：目标、推荐与实际教学节点绑定（T060）

日期：2026-10-19。状态：**具体教学策略、API 和数据方案待批准，尚未实施。**

前置：[ADR-0017 批准](0017-approval-20261019.json)及 T057–T059 零 Provider 实施已完成。依据 [PRD §0.3](../PRD.md)和 [任务规划](../acceptance/phase-1-review-binding-offline-plan.md)，T060 的具体选择须批准后再实施 T061–T064。本方案不修改原头插法 r02 候选、待审案件、节点或评分。

## A. 选择规则：明确目标默认直接学，先修推荐可显式选择

区分：用户目标 `target_node_id`；路径在某个冻结版本上的推荐 `recommended_node_id`；当前课程实际教授 `teaching_node_id`。路径仍依据可信掌握度和图谱推荐，不因直接学目标而伪造先修已掌握。

提议共享计划请求新增可选 `teaching_mode: target | recommended`，默认 `target`。该默认来自“一句话指定本节学习目标”的语义，不把路径的推荐静默改成学生本节目标。旧 legacy 协议保留原路径行为，不悄悄改历史接口。

| 条件 | 实际教学与告知 |
| --- | --- |
| 目标歧义/未知 | 沿现有澄清，不选最长词、不臆造节点；不创建“已确定教学主题”的绑定 |
| target（默认），目标明确 | teaching=target；保留并展示路径推荐，如果不同说明“本节直接学习目标，路径另建议先修”；不声称具备先修能力 |
| recommended，目标明确且有有效推荐 | teaching=冻结路径当前推荐；以独立的前置分段教授该节点，并说明原目标尚未完成 |
| recommended，推荐就是目标 | teaching=target，按目标课验收全部原始需求，不人为缩小为“前置分段” |
| recommended，但无有效推荐/节点不在该路径/图谱失配 | 明确 `TEACHING_SELECTION_UNAVAILABLE`，不回退为 target 或其他主题，不发送生成请求 |
| 用户换目标/改模式 | 新请求与幂等键；不得覆盖旧操作、原单元或已发布版本的节点 |

用户自述“学过指针”仍是背景，不能变成 mastery；选 target 也不等于让 PathAgent 标记先修完成。一个单元只教授一个确定节点；多个并列目标继续澄清。

选择必须在 owner 锁内基于同一图谱/路径版本完成并持久化，在首次计划生成之前发出准确 `teaching_selected` SSE 告知。recommended 是用户显式授权系统按路径选择前置，不增加计划确认弹窗或额外模型调用。路径后来重排不改变已经冻结的教学节点；刷新/恢复只读该绑定，不重新选择或自动重发。

## B. 分段范围与原始请求

target 模式保持用户原文是本节权威请求，计划不能缩小要求。recommended 且 teaching≠target 时，用户显式选择的是“朝原目标学习当前推荐前置”，不是已经交付原目标课。必须保留两个层次：

- `original_request`：用户原文字节/应用现有输入规范化后的完整字符串，来自操作 goal，永不由模型改写。
- `segment_goal`：服务端由明确模式、目标/实际教学节点及冻结路径构造的本节目标；前置分段明确“不代表原目标完整交付”，不从模型计划反推选择。

输入快照同时保存两者，模型看见完整原文及明确分段授权。计划 `goal` 与 metadata.goal 使用 segment_goal，plan.node_id 使用实际教学节点；review_input 的权威原文从已绑定 teaching_context.original_request 取得，新请求同时提供 current_segment_scope，明确当前要核验什么、哪些目标交付尚待后续。未知或冲突要求仍留未决，不以“分段”自动删掉原文的事实/安全/明确约束。

默认 target 的 segment_goal 就是原文。前置分段不使用逐关键词自动改写原文的分类器，不预判所有自然语言约束已经合理分配；如果具体要求与当前分段适用性确实冲突，须明确澄清/留未决，不伪造目标已完成或自动 pass。它只是新模式下明示授权的范围，不能被候选/计划自行开关。

所有当前分段仍保留讲解/代码/练习三资源、四次基准审核、来源和安全检查。新教学范围版本须进政策摘要与 Prompt/输入版本；保持 v4.8 的证据强度、学情、资源职责和 unit 六检查。不得继续以旧摘要签核新增分段规则。

## C. 持久化与一致性边界

采用[具体数据/API 契约](../agents/teaching-node-binding-v1.md)。新增一项 Alembic 迁移：LearningOperation 增加 nullable `teaching_context JSONB`，旧行保留 NULL，不回填推断节点。仅共享计划新操作写入服务端教学上下文；首次选定后不可改写，使用数据库约束/触发器及应用绑定检查验证。原始请求、选择模式进入幂等请求摘要。

上下文同字节进入 PlanInputs 独立字段、plan.input_snapshot、publication.material 和 unit.outline 的明确显示摘要；input_digest 和 unit_digest 同时绑定它。计划本体沿 learning-plan-v1，不加模型自报的目标/推荐/教学身份字段；实际 plan.node_id 与 unit/resource.knowledge_point_id 均必须为 teaching。

输入、计划保存、候选生成/场景写入、案件组装、人工决定、原子发布、评分与重解释边界逐项验证，失败不得“择一个字段为准”。身份/版本/摘要/来源门禁不能由模型或人工豁免。完整三资源实际内容还须由语义审核核对是否真正围绕所绑定教学主题；字符串 ID 一致本身不证明语义一致。

目标与推荐留在路径命名空间；作答/掌握度从准确发布版本的实际教学节点获得，禁止使用此刻路径 current 或 unit 字段回退猜测。路径推荐可能改变，但旧题目、成绩和证据节点不变。先修分段通过不标原目标已掌握，直接目标通过也不自动标所有先修已掌握。

重解释/换示例必须从准确的既有 publication 继承原节点/模式/目标/路径选择快照，新内容重新审核；不能依据当前路径重新选主题。同一单元不得换 teaching_node_id；跨节点学习新建单元/操作。新候选失败或待人工时，旧已发布快照按既有规则保持可用。

## D. 兼容、历史处置与批准边界

目录课程和无计划的 legacy 资源继续走原签核/节点/评分协议；新参数不能暗中使旧协议采用新选择规则。共享计划旧请求未提供模式时，新请求按 target；但旧同幂等键必须只读重放历史操作。旧模式摘要没有新键，不能导致重试重新生成或改变旧绑定。

新绑定版本之前的 planned 单元缺 teaching_context：读取可保留，API 明示 `legacy_unverified`，不自动把 unit.node 当作语义已证教学节点。**建议对这类旧 planned 单元停止新掌握度写入**，返回 `TEACHING_BINDING_UNVERIFIED`；已存在的作答回执仍准确重放，不转移或删除历史证据。目录/无计划 legacy 不受此规则影响。已知错绑的原 r02 尚未发布，保留原待审和失败观察，不原地“修成成功”。

这是安全保守的兼容选择，不声称所有旧 planned 单元都错绑。以后如需恢复其新评分，应另有准确内容/版本/节点的核定与新发布迁移批准；本批不自动重算历史掌握度、不全库撤回旧课程。发现已发布明确错误须按既有受信撤回流程另行处理。

T061–T064 全部零 Provider：选择矩阵、绑定拒绝、隔离 PG、评分/路径、API/页面、重解释/刷新/取消恢复均用实际数据库与 Mock 验证；不能以此证明模型讲对节点。T040 仍需独立新组合/预算，catalog_only 不变。C 运行/隔离与 T065 不在本批准范围。

请批准 A–D 及附件，重点决定：**默认直接学目标、显式 recommended 才教前置；前置分段明示授权而非假称完整目标交付；新增不可改写操作上下文；旧无新绑定的 planned 单元暂停新增掌握度证据。** 具体批准后才完成 T060 并实施 T061–T064。
