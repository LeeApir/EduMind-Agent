# ADR-0024：自由课程身份、版本与所有者访问

- 状态：Proposed（T001具体契约待用户批准）。
- 日期：2026-10-21。
- 前提：[ADR-0023](0023-free-course-learning-and-ui-direction.md)已批准的A—F方向。
- 任务：PHASE-1.5-T001；本提案不构成实现或运行开放。

## 问题与决定提案

旧学习单元通过完整发布快照读取，固定三场景并绑定教学节点。直接取消旧发布审核会混淆历史签核与学生可学草稿，也无法安全表达渐进课程。

建议采用独立的 `free-course-v1` 协议和新增表，以不可变课程版本清单绑定准确场景版本；清单允许尚未就绪的场景。草稿内容通过程序硬门后可由所有者学习，普通语义意见不作为必经可见门禁。新课程与旧单元不共用发布指针，不给旧审核结果补签。

需批准的具体决定如下：

| 决定 | 提案 | 影响 |
| --- | --- | --- |
| A 身份与持久化 | 新建课程、请求快照、计划版本、逻辑场景、场景版本、课程版本清单、节点关联表；全部owner绑定 | 不改旧表身份与签核语义，增加存储及迁移成本 |
| B 版本读取 | 每次可见追加/替换形成新清单并CAS切换head；显式旧版本只读，不按场景最大版本拼课 | 首场景可学与整课完整分开；历史版本稳定，安全禁用另查最新事实 |
| C 权限 | 沿用服务端用户/匿名会话；草稿仅owner可访问，跨owner与不存在均404，无分享、管理员学习入口或草稿目录发布 | 新匿名会话不因设备相同继承旧用户课程；不新增账户找回能力 |
| D API与迁移 | 新 `/api/free-courses` 命名空间，独立OpenAPI提案；仅新增Alembic迁移，不回填旧内容为新课程 | 旧API/目录/历史记录继续沿原契约；回退先关入口并保留新数据 |

规范附件：[数据与兼容契约](../acceptance/phase-1.5-course-contract-r01/contract.md)、[OpenAPI提案](../api/phase-1.5-free-course.openapi.json)、[正负例](../acceptance/phase-1.5-course-contract-r01/examples.json)。准确字节由[manifest](../acceptance/phase-1.5-course-contract-r01/manifest.json)绑定；当前无批准记录。

## 边界与后续

T002冻结生成状态机、调度事件、规模、预算、取消与修订操作；T003冻结缺陷确认、题目答案与证据资格；T005冻结独立质量性能验收。本提案只确定这些能力必须绑定本契约的owner与准确版本，不替代其批准。T001批准也不使依赖T002/T003的实现自动具备条件。

实际仍catalog_only，Provider新增预算0，H继续封存。现有目录、密钥保护、输出清洗、Manim隔离及旧失败记录不变。此方案不新增任意执行、公开分享、自动正式发布或部署能力。

## 备选方案

扩展旧learning_units可少建部分表，但容易让旧发布、三场景和单节点约束泄入新链；全部放JSON而无复合外键难以在数据库阻止串owner和串版本。首版选择独立表与结构化清单，内容正文仍可使用受约束JSONB。

请批准或修改A—D及准确附件。批准登记保存用户确认来源、manifest SHA256及文件摘要，不代填批准人、不以“开始开发”追认尚未写出的具体契约。获准后才能完成T001；本次仅保存待批准设计。
