# ADR-0016：以学生可见证据判定教学目标覆盖

日期：2026-10-16。状态：**用户明确采纳覆盖标准及本例裁定；零调用落实。新诊断标签与付费执行仍待独立批准。**
来源：本聊天用户给出的覆盖标准表、跨载体条件、内部计划排除规则及三项执行要求。
补充ADR-0015 B1的一致性审核职责，不覆盖其不可变绑定、人工权限、预算或发布边界。
原PRD、ADR-0015及其批准manifest保留历史字节；本补充作为已采纳ADR明确其教学覆盖口径。

## 1. 已采纳标准

| 目标 | 覆盖证据 |
| --- | --- |
| 提供算法实现 | 正确代码及必要输入、输出说明可以满足；不额外要求所有实现都带逐步轨迹。 |
| 追踪、解释执行过程 | 学生可见内容明确展示关键状态变化与退出条件；可自行推导不等于已教。 |
| 检验过程掌握 | 题目必须要求使用相关过程知识；只问最终算术结果不足。解析可支持教学，但解析展示了过程不等于题目已检验过程。 |

证据可以分布在讲解、代码注释、关键步骤、练习解析或已交付动画中，无须在讲解重复。
内部计划的轨迹未展示给学生时，仅为审核上下文，不是交付证据。计划正确也不能代替代码正确。
先区分本次用户/单元/场景承诺的目标，不能因图谱还有其他目标而要求每个单元教完整个节点。
但不得通过缩小计划回避用户目标。对不清楚的目标类型或交付可见性，保留不确定。

## 2. 单元审核职责与严重度

资源审核检查本资源的正确性、明确的场景目标及补充需求；看不到兄弟资源时不得推断全单元
没有支持。单元审核在三份最终候选上独立核对：表示/示例/答案/动作一致，以及目标是否在
学生可见载体的合集中得到教学支持、练习是否真正使用目标过程知识。之前各资源pass不代替此检查。

纯教学覆盖不足与事实错误、安全缺陷分开。缺少明确过程教学支持，不推出算法答案错误，
不推出学生有某种困难，也不必认定为严重错误。单元没有revise，已知部分覆盖可用
needs_human + unresolved具体列缺口、相关内容位置与影响；不要求为了符合finding枚举硬填fact。
有据严重事实/安全reject仍优先，不得用覆盖不足把它降级为可人工豁免。

资源级补充需求应具体指出要补什么。当前finding只有fact/code_safety/difficulty/misconception，
纯覆盖缺口无合适类别时同样先needs_human + unresolved，不伪造类别触发revise。
若以后要自动定向补齐这种缺口，应另作finding协议扩展；本次不悄悄增加类别、数据列或修正循环。

## 3. 交付证据及当前产品边界

审核中的“学生可见”指候选被正式发布后实际提供的内容字段，不意味着待审内容已发布。
讲解markdown；代码source（含注释）、expected_output、key_steps；练习question及提交后反馈的
explanation均可提供教学支持。练习answer本身不证明测量了过程。练习解析支持教学时，应区分
它在提交后出现的时机，不声称学生答题前已看见。
若目标明确要求答题前讲授过程，提交后解析不能回补该阶段的缺口；一般过程教学可以在完整
学习旅程中聚合证据，但应如实注明出现时机。不能据“必须先讲再练”的未声明假设另加要求。

内部plan、reference_context、资源ID/digest、show_resource/highlight动作指令不是教学正文。
当前三场景快照没有已验证动画正文，不能把动画占位、请求、DSL或计划描述算已交付动画。
将来真正接入动画支持时，需要绑定相同单元版本、学生可访问的媒体/解释证据；不能靠模型自报。

## 4. 本例裁定与独立复核边界

用户明确裁定r03 missing-unit-objective：**部分覆盖，缺循环状态与退出边界的明确教学支持**。
正确代码及内部计划不足以满足其“逐步追踪”目标。单元宜needs_human，不必硬归严重错误。
该裁定绑定原案例实际摘要；原模型pass、冻结预期失败与持久halt仍保留，不回填正式成绩。
具体案例正文、注释/关键步骤/练习解析及摘要将在新冻结的reassessment.json逐项列出，
不能只引用本条文字就跳过对实际载体的检查。

其余案例按本标准重新阅读原始资源，分别记录实现、过程教学、过程测量及事实/安全结论。
助手的逐项核对与窄范围确定性算术校验，不等于新的独立人工签核；不能由同一模型自审变成真值。
本次只有上述案例裁定和标准是当前用户明确提供的。未再次人工核对的正反例标签继续标待复核。

## 5. 规则决定与新冻结

调整通用审核Prompt及服务端交付字段索引：明确三类标准、跨载体聚合与内部计划排除，
显式要求单元评估目标覆盖；保持五个既有检查项ID和统一结果Schema，不以新增字段冒充新能力。
交付索引只指向请求中真实候选的内容位置，不自动断言“已覆盖”，不执行或解析任意代码。
Prompt/标准版本进入政策摘要，使旧待审按原规则失效。

新冻结采用覆盖专项四对照：完整过程支持、支持分布在关键步骤/解析、只有内部计划的过程缺口、
题目只验证最终结果的过程测量缺口。实现-only正对照及原事实/安全例作为零调用重审控制，
不把这些专项当成严重错误召回测试。真值、同币种准确预算及实际执行另批；不继承r03余额。
Schema/Mock通过不证明模型遵守教学标准；正式100/20/20/10、原阈值与人工不补自动分子不变。
