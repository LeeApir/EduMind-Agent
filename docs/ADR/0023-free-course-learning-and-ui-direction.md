# ADR-0023：自由课程学习与界面重构方向

- 状态：Accepted（产品方向）；具体API、数据迁移、运行状态机及安全实现待设计。
- 日期：2026-10-21。
- 批准来源：用户对需求v0.1答复“A、AI生成草稿允许学生直接学习，仿照OM；其他都同意”，随后要求“继续下一步”。
- 范围：同步需求、确定职责与信息架构，不拆任务、不开发、不运行真实Provider、不切换生产模式。

## 背景

P1完成了生成、审核与发布工程，但真实诊断出现正确计划误拦，尚未证明原质量门槛。用户的产品目标仍是个性化生成教学系统，并要求参考OpenMAIC的需求驱动规划和逐场景学习体验。仅交付固定目录或维护者待审后台不能满足此目标。

## 已确认的决定

1. **学生可以直接学习AI生成草稿。** 新流程不以独立人工签核或普通语义审核通过为草稿可见前提。可学习与已签核是不同属性，不把模型审核失败改写成pass，也不复用旧正式发布资格。
2. **目标驱动课程，节点辅助关联。** 原始目标和有据画像直接参与规划；课程可关联零个、一个或多个知识点。图谱匹配失败本身不阻断生成。真实需求冲突、关键资料缺失和超出支持范围仍需明确处理。
3. **大纲默认自动继续。** 用户可主动查看和调整，不必批准内部计划。课程采用有上限的可变场景，首个完整可学场景就绪后进入课堂，后续追加。
4. **优先教学过程表达。** 首批使用受约束可视化、一个导师为主，保留讲解、代码和练习。任意HTML、全角色、TTS和所有媒体能力不作为本阶段必交付。
5. **保护掌握度证据。** 未可靠校验的生成练习先反馈并保存作答，不直接影响正式掌握度；无可靠节点关联时记录课程内表现。答案修订后须撤销或重算受影响的派生贡献。
6. **统一界面，先设计后实施。** 学习、图谱与路径、画像与掌握度、学习记录、模型设置形成统一信息架构。主要页面设计完成后实施；Phase 2模块仅预留接入方式，不伪装为可用功能。

## 职责边界

结构、身份、版本、权限、来源绑定、输出清洗、预算及执行隔离继续由程序校验。语义审核不得承担机械摘要比对，也不作为所有草稿可见的必经门禁。

普通覆盖建议与未证实模型意见不阻断整课；已确认错误须局部暂停、修订或撤回，依赖内容随之处理。模型的严重度标签本身不等于已确认事实。如何确认缺陷、后台检查的触发方式、引用与修订传播，以及何时停止相关练习，须在后续具体契约中定义。

本决定不授权执行任意生成代码，不削弱密钥、SSRF、XSS和Manim隔离规则。草稿直接学习也不意味着向所有用户公开分享或纳入签核课程目录；跨用户可见性和目录发布属于单独权限。

## 与旧规则的关系

本决定更新ADR-0022中P1.5的产品目标：从未承诺学生入口的待审草稿能力，推进为学生可学习的生成草稿。ADR-0022的P1退出事实、归档、旧失败和停止台账保持。

既有签核课程及旧发布接口继续遵循原规则。新流程必须有明确的新协议与可见性语义，不能在旧流程上关掉审核后冒用正式发布状态。实际运行在实现并验收前仍保持catalog_only。

原三场景及单节点约束不再是新自由课程的产品限制；旧版本记录保持可读，现有数据不能就地抹去绑定历史。P1质量阈值及失败不追认，新阶段独立设计验收。

## 尚未冻结的实现事项

- 课程、场景和版本的数据模型，多知识点关联及可靠掌握度证据条件。
- 草稿的权限、读写API、事件协议、持久恢复、并发与取消。
- 场景数量、时间及调用预算、重试类别、上游修改后的依赖失效。
- 已确认缺陷的证据与处理流程、语义抽检策略、练习答案可靠性判定。
- 主要页面视觉稿、可访问性检查和新链质量／性能阈值。

这些事项的细化不重新询问已确认的A—F原则；涉及新的重大取舍时再呈交具体方案。
