## 背景与代码事实

`backend/app/core/auth.py` 与 `api/auth.py` 使用 `auth_sessions.token_hash` 绑定 owner、绝对过期2h；每次创建 guest 是新User，无续期/账号找回/登出API。`core/provider_target.py` 已有云端公网HTTPS、管理员本地精确IP:port白名单、全A/AAAA校验及固定IP连接要求。现行系统Key只从服务端环境提供；数据库没有用户凭据表。T002须补足匿名BYOK生命周期及模型设置的安全边界，再由T003固定契约、T004迁移/加密、T005实现内存临时Key。

本阶段不增加账号、跨设备找回、会话续期或学习数据自动删除。生成/模型连接测试/模型列表刷新/回退均是实际出站，遵循单独预算；目录核心仍0模型出口。

## A. 匿名归属与持久化凭据的有限生命周期（推荐）

1. 连接owner只取经过认证的服务端User，保存 `user_id`、不可变的 `originating_session_hash`（来自创建它的 `auth_sessions.token_hash`）与 `credential_expires_at`。session关联在使用时检查，父会话缺失即禁用/清理；不要求永久保留auth_sessions行，也不因删除该行清掉既有学习数据。客户端不得传owner/session归属。读取、更新、解密、模型偏好、测试及每次出站均过滤owner，确认该创建会话仍有效；另一guest、无Cookie、过期/撤销会话均不能接管。
2. 本阶段“持久化”是**同一2h匿名会话内可刷新页面、跨API进程及服务重启恢复**，不是跨天保存承诺。凭据最大寿命为创建会话原始 `expires_at`，更新Key不延长会话；新增guest不能找回旧连接。批准后设置页必须在保存前说明到期需重新输入。
3. 会话过期立即逻辑禁用其连接/偏好；每次使用先检查时间与状态，即使清理进程停机也不能调用。T004提供幂等批次清理：启动后首次访问凭据服务前清理、运行期间每60s清理过期凭据；数据库可用且清理正常时，活动数据库密文/包裹DEK在到期后60s内置空。服务停机/数据库故障时不声称按时物理删除，恢复后先清理再允许新调用，故障固定错误并可观测。不因清理自动接触Provider。
4. 清理只移除本提案的密文、包裹DEK和凭据状态，保留非敏感连接元数据/既有学习历史的原归属，不决定匿名学习数据TTL。系统Key不受匿名清理影响。删除连接由当前有效owner确认的DELETE完成，清空凭据、失效偏好/同意、提升配置版本；服务不返回密文、Key片段或Key指纹。
5. 清Cookie无法由服务端感知，依原会话到期清理；用户若要提前清理应先删除连接。DB/WAL/备份可能仍含旧密文，活动表清空不是备份擦除；备份留存及主密钥离线销毁由部署者既有治理负责，本提案不承诺所有物理介质立即不可恢复。
6. 更新、删除、清理及调用授权使用数据库事务/锁与版本检查：删除/禁用提交后不得授权新尝试。授权与实际发送的竞态必须由T007出站门禁解决：每次尝试锁定连接/版本，重新检查会话与同意，锁保持至开始发送首个含认证/数据的请求字节；删除/禁用必须取得同一行锁后才能确认提交，不能把早先发放的内存许可当成永久发送权。会话到期计时器在发送边界前再次检查，过期不开始发送。已开始向Provider发送的数据不能收回；同进程立即通知活动operation取消，跨进程operation每1秒检查DB中的会话/连接/版本（单次检查timeout≤1秒），最迟2秒内触发撤销/DB不可用取消，不承诺远端已收数据擦除；后续重试/回退/新生成阶段继续同步门禁。所有阶段再次检查owner/session/配置版本，不复用撤销前解密缓存。具体API状态码由T003确定。变更provider_type或规范化目标时清空原持久/临时secret，要求重新提供凭据并重新同意；显示名等非目标字段更新不迁移凭据。

**选择理由**：无账号与续期时，无限期保存匿名Key不能带来可找回的持久体验，反而留下不可主动管理的凭据。备选“到期后保留密文等待账号找回”需要新身份/留存决策，不在本次推荐范围；“只支持临时Key”不能交付已规划持久化BYOK。

## B. 主密钥、信封加密与轮换（推荐）

1. 使用成熟加密库的 AES-256-GCM 实现信封加密：每次创建/替换凭据随机生成独立32字节DEK，Key正文由DEK加密；DEK再由服务端32字节主密钥KEK包裹。两层各用新的12字节随机nonce，绝不复用同密钥nonce，不自行实现密码算法。原生适配所需的多个secret字段也须整体放入同一版本化信封，禁止把API secret、认证header或secret参数藏入明文settings；非secret配置只接受明确字段白名单。T004按实现时支持Python3.11的明确版本锁定依赖，ADR不把官网`latest`当依赖版本。
2. PostgreSQL只保存有严格格式/长度上限的版本化信封：算法/信封版本、KEK ID、包裹DEK及其nonce、Key密文及其nonce。AAD以固定无歧义编码绑定用途域（Key或DEK）、owner、connection ID、创建session哈希、provider_type、规范化目标、凭据版本和到期时间。篡改/跨行复制/目标变更不能借旧信封解密到另一个目标。Key字段仅作为secret类型短暂存在，repr/日志/验证错误均不展开。
3. 主密钥从服务端秘密注入；建议配置接口为 `EDUMIND_CREDENTIAL_ACTIVE_KEY_ID` 与秘密keyring，不保存到数据库/仓库/前端/日志。所有API进程使用相同有效keyring，Key ID只用于查找，不泄露密钥。系统Provider API Key使用独立配置，不能借系统Key作为KEK或自动替代缺失用户Key。
4. 当前KEK缺失/无效、版本不支持、认证解密失败时，连接创建/更新/解密及轮换失败关闭、0出站；目录与health继续可用，不自动生成主密钥或降为明文。读取安全元数据/删除过期密文可不需要解密；不把错误直接回显库异常/输入值。
5. 轮换由管理员离线CLI显式执行，不开放学生HTTP入口：先把新KEK加入keyring，设为新写入active；旧KEK暂时只读。对未过期有效凭据按固定批次/行锁将DEK解包后用新KEK和新nonce重新包裹，原Key密文不必改；检查point-in-time行版本，不能复活已删除/过期Key或覆盖并发更新。
6. 单行原子更新，批次可中断/重入：失败行保持旧完整信封，输出只含计数/安全错误，不输出Key或DEK。全量核对有效信封不再引用旧KEK后方可退役旧KEK；先移除旧KEK会使遗留行不可解密，必须保留错误/重新提供凭据，禁止回退解密。数据库备份的恢复仍可能需要旧KEK；管理员明确处理其保留/销毁，不能把线上重包裹称为历史备份重加密。
7. 明文仅在单次处理/出站所需的有限作用域中使用，完成/异常/取消即释放引用并尽力清零可变缓冲区；Python对象/HTTP库副本不能承诺密码学级内存擦除，不将完整进程dump作为验收材料。错误、Pydantic输入错误、HTTP原始响应、SQL参数、队列和浏览器分析埋点全部禁止收集secret。

[Cryptography AEAD文档](https://cryptography.io/en/latest/hazmat/primitives/aead/)说明AES-GCM支持认证密文及AAD，并要求不复用nonce；[OWASP密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)提供认证加密与密钥管理依据。本方案的会话期限、AAD字段、信封结构和轮换流程是本项目提议，不冒充来源要求。

## C. 会话内临时Key与一次操作（推荐）

1. 临时Key不写任何数据库表/Redis/磁盘/队列/日志/浏览器持久存储，绑定**当前API进程实例、当前认证session哈希、owner、connection ID/版本及单次operation**。连接可持久化“不含secret”的元数据；临时状态只保存在该进程的内存注册表，以不可猜的短期handle关联。handle不能单独作为鉴权，不能写URL或浏览器持久存储。
2. 前端输入Key只在当前提交表单的内存，POST发送后立即清空输入；响应只返回凭据状态/到期时间/短期handle，不回显Key。尚未领取的handle最多等待5分钟，且不超过session剩余寿命；每session最多4个待领取handle，超额拒绝，不无限累积secret。有效会话下刷新可恢复持久连接元数据，不承诺找回临时Key。
3. 一次业务operation可包含该明确目标上的生成/审核/允许的有界重试，原子领取handle且不再供第二operation使用。不同目标的审核/回退须分别提供其凭据并获得相应同意，不能自动复用同一个Key。并发重复领取仅一个成功；新operation、旧handle重放、跨owner/session/进程、连接修改/删除都拒绝。
4. operation结束（成功、失败、取消、断线导致取消）时清除注册表条目及受控secret引用并关上游流；session到期由注册时绑定的绝对到期计时器主动触发同样取消，而不是只等下次HTTP鉴权。连接撤销按A6本进程通知/跨进程状态检查触发取消；从撤销提交起不再授权任何新尝试。后台扫除至多每60s进行，但读取/领取检查时间、到期即不可使用；180s目前仅是验收观察上限，不是现行HTTP流的总deadline。本提案要求T005为临时凭据operation新增从领取起最多180s的绝对deadline（session期限更早则取更早者），覆盖所有阶段、token持续到达和内部重试；达到期限主动取消并释放受控引用，不依赖HTTPX的分段read timeout，清理不等待无限阻塞。进程异常死亡或重启丢失全部临时Key，不能从持久化operation状态恢复secret。
5. 临时Key不支持跨进程转发或后台异步模型阶段；不通过Redis实现“临时Key共享”。T005在单进程及进程不匹配失败情形验证；多API实例只有请求落到持有实例才可领取，否则安全拒绝并提示重新输入，不能默默转持久凭据。API进程间亲和路由属于部署选择，本批次不添加新的基础设施。
6. 需要临时Key的模型生成/审核阶段在持有实例内完成后，只允许把**已经审核且不含凭据的DSL/Job ID**交给异步渲染Worker。尚需模型调用或恢复的持久队列工作不得接收临时Key/handle来“以后再解密”；返回要求当前会话重新提供凭据或显式选择有效持久连接，不自动换目标。T018/T022须继承此边界。
7. 清理临时Key不得影响同owner的持久信封、系统Key或已经批准的学习资源。内存清理的有限保证与B7一致；关闭日志请求体、异常局部变量/原始HTTPtrace是前提。

## D. 目标白名单、数据去向与显式回退（推荐）

1. `is_local`由服务端目标校验得到，不能信任客户端布尔值。云端模式只允许HTTPS公网目标；管理员本地模式与精确IP:port白名单共同启用时才允许已许可非公网目标，可含HTTP。云端不能靠学生输入URL开启本地访问，链路本地/元数据/未指定地址/组播一律不放行。“本地”只证明API连接目标符合本地白名单，不证明该服务不再向云端转发；无法验证的离线/上游厂商属性保持未知，兼容服务不能凭模型名推断最终数据接收厂商。
2. Base URL拒绝用户名/密码、query、fragment、控制字符与反斜线；连接及每次出站（含重试/列表/探测）验证所有A/AAAA。任一答案不合策略则拒绝；实际连接固定批准IP，同时保留原Host/TLS SNI与证书校验，不再次解析域名、不使用环境代理、不自动跟随3xx。T006继续验证DNS变化/IPv4映射IPv6/元数据/重定向等绕过。
3. 配置保存前做语法/目标资格检查，默认不测试连通性/下载模型/调用Provider。DNS属于出站目标安全检查，测试时用受控resolver；真实目标探测、列表获取/刷新及生成均需显式操作和预算，不能因设置页打开或CRUD后台执行。T003会区分纯元数据读取与实际刷新，不把产生出口的刷新藏在GET普通查询中。
4. 发出请求前展示实际Provider/模型、规范化目标来源（scheme/host/port及服务base path）、服务端判定本地/云端、发送的数据类别、凭据为系统/持久/临时。连接保存与调用同意分开记录；每次operation绑定已展示且明确接受的连接配置版本、模型/档位与允许的数据类别。目标/模型/策略变化使同意失效，不能只依据显示名相同继续发送。
5. 上下文只含当前任务必要的目标/知识节点、相关学习证据/画像字段与有限历史/教材片段；不把全画像、全部历史或凭据混入Prompt。审核模型也是接收数据的Provider，须列明；普通输出元数据只记录允许的目标标识/版本、耗时、用量/未知与固定错误码，不记录完整正文。
6. 默认禁止跨Provider回退。用户明确选择的回退清单包含具体connection/配置版本、模型、顺序、触发安全错误及允许的数据类别；每次回退重新验证资格/同意/预算/能力。无许可、已删除、过期、配置冲突或审核不支持即终止，不能静默使用系统Key/系统Provider。允许同厂商的另一个连接也不是自动授权；全部跨连接路由须遵循偏好与同意。
7. 现有网关同目标重试边界保留：默认一次；只有 `retry_safe=True`、尚无可见副作用时最多3尝试，流式永不自动重试。已输出token后停止该流，提供明确重试选择，不能拼接另一个Provider正文。每次实际尝试计入独立预算。
8. `catalog_only`不被设置页、连接保存、能力探测或偏好更新解除。后续设置API可管理合法连接；实际测试/刷新须独立能力入口与显式操作/授权，不能借它调用学习生成或绕过动态门禁。T035/T039–T041的独立质量/性能与开放批准仍为必要条件。

[OWASP SSRF指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)支持全地址校验及禁用自动重定向等措施；固定IP/Host/TLS策略沿用本项目已有Guard，具体本地白名单和同意流程属于待批准项目决定。

## 失败情形与验证矩阵

| 情形 | 要求 / 验证任务 |
| --- | --- |
| 跨owner/伪造user_id/session已过期 | 读取/修改/解密前拒绝，0 Provider出口；T003/004/005/009 |
| 清Cookie/新guest/过期后旧连接 | 不找回旧Key；到期逻辑失效/清理，仅清凭据不删学习历史；T004 |
| app/DB清理停机与恢复 | 过期不可调用；DB正常后先清理再使用，保留清理失败计数；T004 |
| 缺KEK/未知版本/篡改密文或AAD/错KEK | 安全固定错误，0解密后出口；health/目录仍可用；T004 |
| 主密钥轮换中断/重复/并发替换/删除 | 单行原子、可重入、不复活旧secret；旧KEK不能提前退役；T004隔离PG |
| 删除/禁用与在途生成竞争 | 提交后无新授权/发送许可/重试/回退，单进程通知与跨进程≤2s触发取消、会话绝对期限计时器；锁覆盖实际开始发送的竞态，不声称撤回已发数据；T004/005/007/009/012 |
| 临时handle等待超时/两个并发operation/旧handle重放 | 到期失效，原子领取仅一个成功，所有终止路径清理；T005 |
| 临时Key进程重启/跨进程/owner会话变化 | 不恢复、不队列转发、不用持久Key替代；T005/007/018 |
| 云端localhost/私网/metadata/多DNS混合/代理/跳转 | Guard在Key交出和每次出站前拒绝不合法目标；T006/007 |
| target/model更新与旧同意/回退目标变更 | 配置版本冲突，重新明确同意，0未授权出口；T003/012/014 |
| 输入校验/响应/SQL参数/日志/DB快照/队列/前端存储泄漏 | 有效/失败Key均不得出现明文；密文及DEK不回传，0泄漏；T004/005/009/013 |
| catalog_only下保存设置/打开页面 | 不自动模型出口、不开放学习生成；测试按钮与刷新显式且有界；T010/011/038 |

自动化使用明确标记的测试secret、Mock HTTP与受控DNS；隔离PG验证迁移/锁/轮换，不接生产或用户开发数据。外部官方文档读取只用于设计依据，不是Provider调用。T002本次只做设计/文档核验；具体实现、真实模型、清理时限及安全保证须由后续测试验证。
