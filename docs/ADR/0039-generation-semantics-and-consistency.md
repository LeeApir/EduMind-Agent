# ADR-0039：生成语义约定与跨内容一致性检查

2026-10-27。状态：按用户明确指令实施的内部改进，非新运行授权。来源：“完成你的修改，下一步主要修改的是生成请求／Prompt 的语义约定、跨内容一致性检查”。分别由T062/T063独立验证与提交；事实状态以根task.json为准。

生成请求升级v4，服务端提供版本化C语义约定：参数按值；返回新头的具体接口需要调用处接回；malloc不初始化成员；复杂度必须带表示/操作前提；题干、代码和答案不得偷偷替换调用/状态。仅必要上游中的真实代码供内存AST解析，接口提示绑定准确代码SHA及场景版本/摘要。语法提示不是语义真值，不用课程内容覆盖服务端约定。

采用锁中已有pycparser3.0并显式固定为直接依赖。只调用CParser.parse内存字符串；不使用parse_file/cpp/编译器/子进程，不读include文件或运行生成代码。只忽略允许的标准include声明，宏/扩展/过大/深层未知语法标未评估，不编造类型或模型知识。

一致性检查限定为可解释的语法模式及保守文字线索。每个发现保留准确字段指针、原文片段、关联接口来源和规则版本；遇到不支持语义明确保留coverage incomplete。检查代码注释/字面量不当作实际调用；函数改名仍根据接口模式关联，二级指针/返回值已接收/明确错误例子等区分处理。不得宣称完整内存安全、执行结果、答案正确或模型能力已验证。

为保持ADR0026草稿语义边界，T063在既有私有FreeSceneValidation.findings内按新规则版本只追加semantic_advisory报告；机械state仍只表示原结构/引用/清洗硬门。建议为needs_review，不自动变confirmed，不拒绝草稿、不授予评分/掌握度、不触发模型修复。普通语义建议不能成为mechanical_rule禁用依据。旧候选/答案/既有准入事实不改；无新表、迁移、公共API或权限。完整模型/人工审核仍必要。

本轮不调整审核响应兼容门禁，不实施审核→自动语义修订，不恢复任何停止批次，不进行真实Provider/任意C执行、独立集/H读取、生产开放或部署。现有错误仅用于已暴露开发回归，历史真实失败不追认为通过。
