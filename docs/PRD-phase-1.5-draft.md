# Phase 1.5 需求说明：个性化课程生成体验与界面重构

> 版本：v0.3，2026-10-21。
> 状态：需求方向与A—F取舍已由用户确认；具体实现契约尚未制定。
> 本文定义需求，任务状态由根 `task.json` 单独维护；已确认方向同步至 [PRD §0.5](PRD.md) 与 [ADR-0023](ADR/0023-free-course-learning-and-ui-direction.md)。文中“应”描述已确认的需求方向，不代表已经实现或已开放运行。

## 1. 本阶段要交付什么

让学生输入自己的学习需求后，直接获得围绕该需求组织、能够逐步呈现和交互的课程；同时重构导航与页面，使课程、图谱、路径、画像、掌握度、学习记录和模型设置形成可理解的整体。

参考 OpenMAIC 的需求驱动规划、可变场景、内容与授课动作分离、首场景优先及持续生成体验。保留 EduMind 的学习画像、知识图谱、掌握度反馈、Provider Gateway 和安全隔离，不照搬整个 OpenMAIC 产品。

本阶段目标不是继续扩大审核实验，也不是把产品永久收敛为固定课程目录。已有签核课程继续可用，新增自由生成课程作为需要明确质量边界的新学习入口。

### 1.1 当前基线与本稿的变化

- P1已按收敛范围归档：89项完成，动态质量T040和性能T041仍blocked；见[现行PRD](PRD.md)、[退出决定](ADR/0022-phase-1-contracted-closeout-and-phase-1-5.md)和[阶段交接](acceptance/phase-1-closeout-20261021/README.md)。
- 当前正式基线仍是 `catalog_only`。P1的动态能力定位为待审草稿，不等于学生可使用的草稿课程入口已交付。
- **用户已确认：仿照OM，AI生成草稿允许学生直接学习**，普通语义审核不再逐关阻断整课，不以独立人工签核作为草稿可见的前提。这是已确认的产品方向调整；后续需同步正式PRD并制定新可见性契约，通过新流程实现，不能把旧审核失败记录改签为通过。
- P1失败、停止记录和未验证能力继续保留，不因P1.5开放实验入口而改写为通过。

## 2. 目标用户与典型旅程

主要面向学习数据结构的大学生。首批继续以数据结构及必要的C语言基础为范围，不在本阶段承诺全学科。

典型输入：

> 我会C的基本语法，但不懂指针。想用15分钟学会链表头插，最好能看到指针怎么变化，再做几道题。

期望体验：

1. 学生在学习首页输入目标；时长、难度、代码语言等偏好可选，不要求先填画像问卷或选知识节点。
2. 系统结合明确要求和已有学习证据生成课程大纲，安排必要的指针铺垫、头插过程、代码对照与练习。
3. 展示可读的大纲和生成进度。默认继续生成，学生可以主动调整范围，而不是必须批准内部计划。
4. 第一段完整可学的场景就绪后进入课程，后续场景继续生成。
5. 学生可以暂停、切换场景、提问、要求更简单的解释或局部重新生成。
6. 学习进度与练习记录保存；仅符合证据要求的结果更新掌握度，下一步建议说明依据。

关键区别：节点匹配不成功时，系统仍应能够围绕明确的学习目标生成课程；确有需求冲突或关键资料缺失时，才向用户澄清。

## 3. 范围与非目标

### 3.1 本阶段包含

- 自由文本目标驱动的课程规划，不强制绑定单一图谱节点。
- 可变数量与顺序的教学场景，首场景优先、后续逐步追加。
- 讲解、代码、练习及受约束的过程可视化；清晰的授课动作与交互反馈。
- 课程进度、失败恢复、局部修订及版本可追溯。
- 已有画像、知识图谱、路径、掌握度和模型设置的产品接入。
- 全站信息架构、主要页面设计、统一视觉规范和移动端适配。
- 新链路独立的质量、体验与性能验收方案。

### 3.2 本阶段不包含

- Phase 2的画像驱动动态分级题库、真并行辩论、教材问答/RAG和学习报告。当前课程内练习与已有画像适配不因此取消。
- PDF教材解析、联网研究、通用课件编辑器、PBL项目教学和完整多角色生成体系。
- 任意模型HTML/JavaScript执行、任意C/Python在线执行或放宽Manim沙箱。
- 新增Provider厂商、恢复全部延期Provider真实验收、TTS/ASR作为必交付能力。
- iOS、PPTX/视频导出、跨设备账户系统、公网部署与运营。

已有功能在新界面中保持兼容；不为填满导航而扩展后端业务。

## 4. 自由课程生成需求

### 4.1 输入与个性化

- 原始目标完整保留，系统安排的铺垫不得替代用户真正要学的内容。
- 支持使用已有画像中的明确证据调整讲解深度、示例和节奏；未知字段保持未知，不声称学生“已经掌握”或“经常犯错”。
- 可见的默认选项应可调整。课程默认时长、场景数量上限、默认语言沿用关系在设计中明确，本稿不预设为已批准数值。
- 区分代码语言和教学语言。语言与能力选择只能展示实际支持项。
- 澄清用于解决真实歧义，例如互相冲突的要求、明确依赖但未提供的输入；不能仅因多个知识点命中或图谱没有匹配项就阻断。
- 超出当前课程范围时明确告知范围，不偷偷转换成邻近节点的课程。

### 4.2 课程、大纲与场景

- 课程拥有独立身份与版本，不再以单个知识节点作为课程身份。
- 一门课程可以关联零个、一个或多个已有知识点；缺少映射不妨碍生成，也不伪造节点。
- 大纲包含课程目标、场景标题、顺序、教学目的和预计内容形式；内部摘要、审核字段和模型参数不进入普通学习界面。
- 场景数量和顺序根据教学需求安排，不固定为“讲解—代码—练习”三个场景；总规模必须有明确上限。
- 原始要求是需求来源，生成计划是模型建议；计划中的数字、推演或额外目标不能冒充用户要求。
- 保持共享示例、术语、索引与状态约定，避免各场景讲的是不同例子。
- 建议默认自动继续，允许用户主动查看和调整大纲。调整生成中的大纲必须明确影响范围与额外生成成本。

### 4.3 渐进呈现与恢复

- 首场景达到可阅读、可交互的完整状态后即可进入课程；不得用HTTP首字节或空卡片作为首场景完成。
- 后续场景显示等待、生成中、可学习、失败或待修订等状态，不将未完成内容包装成完整课程。
- 刷新或离开页面后可恢复已保存进度；不能因刷新隐式开启重复生成或重复扣费。
- 单场景故障应尽可能局部处理；依赖该场景的后续内容明确暂停或失效，不能盲目继续。
- 停止生成后保留已有内容和真实状态。恢复、重试、补生成均遵守同一操作预算和明确的新操作规则，不能无限重试。
- 并发数量、重试类别、取消语义、持久化和调用上限在具体设计中冻结，不直接照搬OM默认重试次数。

### 4.4 课程内交互与呈现

- 讲解、代码、练习和动画是不同的教学表达方式，可以交替出现，而不是四个互不关联的文档。
- 代码支持清晰排版和讲解定位；逐步演示能对应当前代码或数据状态，不装饰性播放无关动画。
- 首批优先支持数组、链表、栈、队列的受约束状态演示；具体组件清单在主要页面与场景设计时确定。
- 现有Manim能力可按能力与任务状态接入；媒体未就绪时有可理解的静态说明，不让可选动画阻塞全部课程。
- 默认专注于导师与内容。已有互动能力按真实支持范围接入，不在本阶段扩展为完整多智能体辩论。
- 学生可针对当前场景提问、要求补充解释或更换例子。修改内容后保留旧版本，并使受影响的动作、练习答案及依赖内容重新校验。
- 保留正常的练习提交与反馈；对尚未生成、存在答案争议或已失效的练习，不给出假完成状态。

## 5. 内容质量与可见边界（需求方向已确认）

### 5.1 建议的产品分层

| 内容状态 | 学生侧含义 | 拟议规则 |
| --- | --- | --- |
| 已有签核课程 | 已按既有流程确认的固定版本 | 继续按原规则学习，不降级其历史签核含义 |
| AI生成学习草稿 | 可以学习，但可能有误、尚未独立签核 | 清晰标识；不要求普通语义审核全部通过才展示 |
| 明确缺陷内容 | 已有可信证据确认存在错误 | 局部暂停、替换或撤回；受影响依赖同时处理 |
| 结构或安全不合格内容 | 无法安全渲染、权限或版本失效等 | 程序阻断，不能以“草稿”绕过 |

“可学习”与“已签核”分开记录。草稿不能静默获得正式发布资格，也不能沿用旧API把审核失败改签为pass。

### 5.2 审核职责建议

- 程序负责结构、引用存在性、身份、摘要、版本绑定、输入清洗和执行安全。
- 普通教学完整性、措辞和难度建议不作为整课不可见的必经门禁。
- 模型自称严重或返回reject，不自动等同于缺陷已经被确认；需要区分有据缺陷与未证实意见。
- 语义审核的运行方式待确认：本稿建议首版主要用于离线抽检与学生反馈后的定位，避免立即建立新的全量后台审核链。
- 已确认错误必须处理；免责声明不能代替修正。用户应能对具体段落、代码或题目反馈问题。
- 本阶段先满足问题标记、局部再生成和记录追溯，不要求建设完整教师编辑后台。

### 5.3 掌握度与画像保护

- 学习进度、做过题的记录和掌握度证据分开保存；看完课程不代表掌握知识。
- 建议未经可靠答案校验的生成练习先提供学习反馈并保存原始作答，不直接影响正式掌握度和路径决策。哪些校验可以使其成为有效证据，需在后续契约中明确。
- 知识点映射不足时保存课程内表现，不强行归到最相近节点。
- 若答案、题目或关联知识点发生修正，保留原始作答，撤销或重算受影响的派生评分及掌握度贡献，并告知用户。
- 明确自述、模型推断和实际答题证据的来源，不将系统猜测写成学生事实。

## 6. 界面重构专项

### 6.1 信息架构初稿

建议桌面端采用稳定主导航，模型设置放在设置区域；移动端保持同一信息结构，不强行把全部入口挤入底部栏。具体导航形式在设计稿中核对。

| 一级区域 | 主要内容与入口 | 注意事项 |
| --- | --- | --- |
| 学习 | 一句话生成、继续学习、我的课程、已有签核课程 | 明确课程类型、进度和可用状态；避免多个同义“开始”入口 |
| 知识图谱与路径 | 图谱浏览、先修关系、推荐下一步、当前路径 | 推荐不强制替代学生目标；节点存在不等于已有可学课程 |
| 画像与掌握度 | 目标、已有证据、偏好、能力分布及可纠正项 | 未知如实显示，区分自述与观测，不制作无依据分数 |
| 学习记录 | 学过的课程、练习记录、修订与恢复入口 | 仅呈现已有记录，不提前包装成Phase 2学习报告 |
| 设置／模型设置 | 已有Provider连接、模型偏好、凭据管理与能力状态 | 未真实验收的连接不能标为已验证；不泄露密钥 |

页面内容与后端能力不一致时，以真实能力为准。没有实现的Phase 2模块不展示为可点击的可用功能。

### 6.2 主要页面

| 页面 | 必须解决的问题 |
| --- | --- |
| 学习首页 | 用户一眼知道如何输入目标、继续上次课程和选择已有课程；不被技术配置占据主视线 |
| 课程生成与大纲预览 | 看懂系统准备教什么、当前进度、可调整的范围及失败后可做什么 |
| 课程学习页 | 场景目录、当前内容、练习反馈与提问互不抢占；生成进度和内容质量状态独立显示 |
| 图谱与路径页 | 看懂节点关系与推荐理由，能返回具体课程；不让复杂图形成为唯一导航方式 |
| 画像与掌握度页 | 看懂系统知道什么、依据是什么，以及哪些信息可以纠正 |
| 学习记录页 | 找回课程与作答，能按准确版本恢复；区分完成、部分完成和生成失败 |
| 模型设置页 | 理解哪些模型用于哪些能力、连接是否可用及修改何时生效；运行中不静默切换Provider |

课程页建议桌面端为“场景导航＋主学习区＋按需展开的提问区”；移动端用抽屉或切换面板呈现辅助区域，保留足够正文空间。讲解、代码、练习和动画使用统一场景框架，但内部交互按类型设计。

### 6.3 视觉与交互规范

- 先完成信息架构、关键用户流程和上述主要页面设计，再开始前端改造。
- 统一页面宽度、间距、排版层级、中文正文与代码字体、颜色语义、边框和卡片样式。
- 颜色仅表达有限且稳定的含义，如当前、完成、警告、失败；不可只靠颜色传达状态。
- 全站统一加载、空数据、无证据、无权限、网络故障、生成失败和可恢复状态的表达。
- 键盘可操作、焦点可见，表单有标签；正文与控件具有可读对比度。
- 小屏幕下导航、代码长行、图谱和练习均可操作，不出现页面级横向溢出；局部代码区域可独立滚动。
- 动效用于解释状态和教学过程，支持减少动效，不为视觉效果延迟内容可用。
- 保留Vue 3、TypeScript、Naive UI和Pinia；本阶段不以换技术栈作为重构前提。

### 6.4 后续模块接入

统一导航注册、页面容器和状态组件，允许Phase 2模块按真实能力接入。个性化练习、辩论、教材问答和学习报告只在设计文档预留归属，不提前展示可用入口，不新增对应后端业务或假数据成绩。

## 7. 兼容与工程约束

- 已有签核课程、历史学习记录、模型设置和已验证目录入口继续可用。
- 新自由课程流程采用明确的新协议或版本，保留旧流程的来源与状态语义；不全局替换旧审核结果。
- 课程、场景、练习、动作、知识点关联和掌握度证据需要明确版本关系，但本稿不提前决定数据库表或具体API字段。
- 复用已有Gateway、PostgreSQL、持久任务、预算和取消能力；真实执行不能只保存在浏览器内存。
- 模型切换、回退和新增调用须有可见设置与预算，不静默向其他厂商转发学习信息。
- 密钥保护、SSRF防护、HTML/Markdown清洗和受约束执行隔离保持。
- P1延期的Provider真实接入能力继续标记未验；模型设置页面改版不能把这些能力变成已通过。

## 8. 本阶段验收方向

需求确认后再冻结具体样本、阈值、调用预算与失败处理；此处不虚构已获批准的成功率或时延数值。

| 维度 | 需要回答的问题 |
| --- | --- |
| 需求兑现 | 多知识点目标能否直接形成连贯课程？必要铺垫是否仍服务于原始目标？ |
| 个性化 | 同一目标在不同有据背景下是否有合理差异？未知学情是否被保留？ |
| 可学性 | 学生能否理解解释、使用代码对照、完成练习，并获得有帮助的反馈？ |
| 质量 | 事实错误、答案错误、覆盖不足分别出现在哪里？严重问题有没有被发现和妥善处理？ |
| 渐进体验 | 第一场景何时真正可学？后续等待、失败和媒体缺失是否中断学习？ |
| 恢复与成本 | 刷新、离开、取消、重试和局部修改是否造成重复请求、失效内容混用或超预算？ |
| 学习状态 | 进度、作答、画像和掌握度是否正确区分与关联？错误答案修订是否污染后续推荐？ |
| 界面 | 主要入口能否找到？桌面和移动端关键旅程能否完成？状态是否真实可理解？ |
| 兼容 | 原目录课程、历史记录、模型设置与安全边界是否保持？ |

性能至少分别记录首个完整可学场景、后续场景等待和整课生成时间，不将HTTP首字节或空大纲计为教学交付。质量评估保留失败与未运行项，模型审核结论不当作独立真值。

先使用开发材料改进体验，再以独立材料验证。H01–H08保持封存，新契约确定后重新判断适用性；不自动继承其验收资格。P1旧阈值和失败不改写，新阶段也不能用降低错误标准代替提升可用性。

## 9. 已确认决策（2026-10-21）
