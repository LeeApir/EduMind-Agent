# 单链表头插法微课

## 从结构体与指针到链表

大家好，欢迎来到今天的 C 语言课。前面我们已经把结构体和指针分别学完了，这节课就把这两样东西合起来，做出第一个真正有实用价值的数据结构——链表（linked list）。先看一下这节课的整体路线。 标题就是我们的起点：从结构体与指针到链表。整节课我会只用一个例子贯穿始终——从空链表开始，依次插入 1、2、3，后面所有的代码、指针变化步骤和练习，全都对得上这一个例子，请大家不要走神去记别的数据。 先看最基础的一块：节点（node）。一个节点由两部分组成，数据域 data 存我们真正关心的值，指针域 next 存下一个节点的地址。写法上就是 struct Node 里面放一个 int data，再放一个 struct Node *next，注意这里写的是 struct Node 的指针，也就是指向自己这种类型的指针，这是链表能串起来的关键。 把这块记成三句话就够了：第一，节点等于 data 加 next，数据域加指针域；第二，头指针（head pointer）永远指向链表的第一个节点，如果链表是空的，那 head 就等于 NULL；第三，next 保存的是下一个节点的地址，所以这些节点在内存里不必连续，可以分散在任意位置，靠指针一个个连起来。 那怎么把一个新节点放进链表里呢？今天先看最省事的做法——头插法（head insertion），一句话概括：新节点插到最前面，再让 head 指向它。听起来很简单，但赋值顺序一旦写反，链表就可能断开甚至整个丢失，这正是我们接下来几页要一步步拆开看的地方。

## 头插法的三步执行过程

上一页我们说过，头插法（head insertion）一句话就能概括：新节点插到最前面，再让 head 指向它。但这句话放到代码里，其实是三个固定动作，顺序一个都不能错。下面我们一步一步地拆开来看。 第 1 步，申请新节点并写入数据。用 malloc 向内存申请一块空间，让 newNode 指向这块空间，接着写 newNode->data = value，把要插入的数据装进去。注意，这时新节点还是一个与链表无关的节点，它的 next 是随机值，链表完全不知道它的存在。 第 2 步，让新节点先接到原来的链表上。执行 newNode->next = head，新节点的 next 就指向了原来链表的第一个节点。如果原链表是空的，head 就是 NULL，那么 newNode->next 得到的就是 NULL，正好表示这个新节点就是链表末尾。做完这一步，新节点已经接入原链表了，但 head 仍然指向旧的头节点。 第 3 步，头指针前移。执行 head = newNode，让 head 改为指向新节点，新节点就正式成为链表新的头（head）。到这一步，三个动作才全部完成。 这里有一个必须记住的注意事项：第 2 步和第 3 步这两条赋值语句的顺序不可颠倒。如果先写 head = newNode，head 立刻就指向了新节点，原来那条链表的入口就丢失了，后面的节点再也找不到，也 free 不掉，于是造成内存泄漏。所以口诀是：先接上旧链，再移动 head。 我们用同一组数据走一遍。一开始链表是空的，head 就是 NULL。现在插入数据 1：新节点的 next 接到 NULL，head 指向 1，于是 head → 1 → NULL。 再插入 2，就变成 head → 2 → 1 → NULL；再插入 3，变成 head → 3 → 2 → 1 → NULL。你可以看到，每插一次，head 就往左移动一个位置，最新插入的永远排在最前面，这就是头插法的特点。记住这三步：先建节点、再接到旧链、最后移动 head，顺序就是关键。下一页我们就用图示一格一格地看指针到底是怎么变化的。

## 指针变化可视化：单步看头插

上一页我们看到 head 一次次往左移，那只是结果。这一页换个角度：把代码展开，一行一行单步执行，看看每个指针究竟在哪一刻改变了指向。 先单步执行第一条 newNode->next = head。此刻链表还是空的，head 的值是 NULL，所以 newNode->next 直接拿到 NULL。这就是空链表插入第一个节点的特殊情形：没有旧链可接，next 只能指向空。 接着执行 head = newNode。注意，只有这一句执行完，head 才真正指向新节点；前一句只是把新节点挂到旧链上，head 本身没有动。你可以多点几次下一步，把 1、2、3 依次插进去，然后对比一下：插入顺序是 1、2、3，可从头往后读链表，顺序却是 3、2、1，最新插的永远在最前面。 把这三步在脑子里过顺了——先建节点，再接到旧链，最后才移动 head——下一页我们就把这段写成完整的程序，看看真实的 C 代码长什么样。

## 完整程序（上）：节点结构与头插函数

上一页我们把头插法拆成了三步动作：建节点、接旧链、移 head。这一页就把这三步真正写成 C 代码，先看整个程序的上半部分。 先看最上面两行：include 写 stdio.h 和 stdlib.h。stdio.h 是为了后面 printf 打印链表，stdlib.h 是给 malloc 和 free 用的。这里少一个，编译器就会警告，初学者最容易漏的就是 stdlib.h。 接着是节点结构。struct Node 里面有两个成员：data 用来存数据，next 是指向同类型结构体的指针，指向下一个节点。注意 next 的类型是 struct Node *，结构体里引用自己，所以必须带 struct 关键字。当 next 等于 NULL 时，就表示这是表尾，后面没有节点了。 然后是 createNode 函数，对应我们说的第一步：建节点。它接收一个 int value，先用 malloc 申请一块 sizeof(struct Node) 大小的内存，然后把 value 赋给 data，再把 next 置成 NULL。特别强调一点：malloc 有可能失败，所以申请完一定要检查返回值是不是 NULL，如果是 NULL 就直接返回，不然后面访问就是野指针，程序会崩。 最后是重点，insertHead 函数。它的第一个参数是 struct Node **head，是个二级指针。为什么要二级？因为我们要修改的是 main 函数里的那个 head 本身，而不是它指向的内容，C 语言里想改外面的指针，就得把指针的地址传进来。函数内部两步：先 newNode->next = *head，把新节点接到旧链上；再 *head = newNode，让 head 指向新节点。这个顺序千万不能反，反了老链表就找不回来了。 到这里，头文件、节点结构、createNode 和 insertHead 都写完了，这正好是头插法三步动作在代码里的完整落地。下一页我们补上遍历、释放和 main，让它真正跑起来。

## 完整程序（下）：遍历、释放与 main

上一页我们把节点结构、createNode 和 insertHead 都写好了，这一页把剩下的遍历、释放和 main 补齐，让这份代码真正能编译、能跑起来。 先看整体：这一页要补三个部分——打印链表的 printList、释放链表的 freeList，以及把它们串起来的 main。 第一个是 printList。思路很直接：先把 p 指向 head，然后用 while 循环判断 p 不等于 NULL。每进一次循环，先打印 p->data，再打印一个箭头“->”，最后 p = p->next 往后走一步。等 p 变成 NULL，循环结束，再单独打印一个 NULL，表示链表到头了。这样屏幕上就是完整的“数据 -> 数据 -> NULL”。 第二个是 freeList。这里最容易出错，顺序一定要记牢：先保存 p->next 到临时变量，再 free(p)，最后让 p 走到刚才保存的 next 上。为什么必须先保存？因为 free(p) 之后，p 指向的那块内存已经还给系统了，再去读 p->next 就是访问已释放的内存，属于未定义行为。循环结束后，还要把 *head 置成 NULL，也就是 head = NULL，防止留下野指针（dangling pointer）。注意参数是 Node **head，这样才能真正改到调用者的 head 本身。 第三个是 main，也就是整个流程的总指挥。第一步 head 初始化为 NULL，表示空链表；第二步依次用 insertHead 插入 1、2、3——还记得头插法的特点吗？每插一个都放在最前面，所以最终顺序是 3、2、1；第三步调用 printList 打印；第四步调用 freeList 释放所有节点；最后 return 0 结束程序。整份代码就这么闭环了。 运行结果应该和我们推演的一致：3 -> 2 -> 1 -> NULL。如果打印出来是 1 -> 2 -> 3，说明你用的其实是尾插的思路，那就要回头检查 insertHead 里的指针改动顺序了。 最后记住这条铁律：malloc 和 free 必须成对出现。每申请一块内存，就要检查它是不是 NULL；每用完一块内存，就要及时释放。养成“申请即检查、用完即释放”的习惯，后面写更复杂的链表、树，甚至做项目，都能少踩很多坑。下一页我们就一步一步追踪指针，把刚才这套代码真正“走”一遍。

## 逐步追踪指针变化与预期输出

上一页我们说了「申请即检查、用完即释放」，现在就把刚才那套头插代码真正“走”一遍——不跑程序，我们先用眼睛在纸上把指针一步步画出来。看这四个小图，就是同一段代码执行四次的快照。 ① 初始状态。这时候 head 里面装的是 NULL，意思是头指针没有指向任何节点，整个链表是空的。记住这一点很重要：空链表不是“head 不存在”，而是 head 存在、只不过它的值是 NULL。 ② 插入 1 之后。malloc 出来一个节点，数据域写 1，next 写成 NULL，因为它是目前唯一一个节点，后面没有别人。然后 head = newNode，head 就指过来了。现在 head 指向的这块内存，内容就是“1 加 NULL”。 ③ 插入 2 之后。新节点先是把自己的 next 指向原来的第一个节点，也就是 1 那个节点；然后 head 才改成指向 2。所以现在是 head 指向 2，2 的 next 指向 1，1 的 next 是 NULL。顺序一定要注意——先接 next，再动 head，这两步反了链表就断了。 ④ 插入 3 之后，同样的动作再来一次：3 的 next 指向 2，head 指向 3。现在整条链子就是 head → 3 → 2 → 1 → NULL。每一步都只改了两个地方——新节点的 next 和 head——其他节点一个都没动。 那遍历输出会是什么呢？从 head 出发，打印 3，顺着 next 到 2，打印 2，再到 1，打印 1，最后遇到 NULL，循环结束。所以输出就是 3 → 2 → 1 → NULL。你在这里可以提前用纸笔预测一下，再跟实际运行结果核对，这个“预测—核对”的习惯特别能帮你抓出自己的思维漏洞。 你有没有发现，我们明明是依次插入 1、2、3，输出却是 3、2、1？原因就一句话：每次都在表头插，最后插进去的自然站在队首，最先被访问。这就是后进先出，英文叫 LIFO（Last In First Out），和栈的行为一模一样。换句话说，用头插法建出来的链表，天然就是一个栈。 最后我们把几个最容易翻车的地方集中过一遍：忘记写 head = newNode，那新节点就挂不上，链表永远没变；先改 head 再接 next，原来的链子就找不回来了；free 掉一个节点之后还去访问它的 next，那是指向已经还给系统的内存，属于未定义行为；还有清空链表时忘了把 head 置回 NULL，下次再插就可能踩到野指针。这四条只要错一条，程序要么崩要么输出莫名其妙的数，回头调试时也优先从这四点上找。

## 总结与延伸：头插法 vs 尾插法

三道练习过完，我们这门课也走到最后一页了。最后这一页，我想把整节课的内容重新梳理一遍，把头插法和尾插法放在一起对比，帮你把这一块知识点彻底理顺，形成完整的结构。 先看左边这一排，就是我们的三要素记忆法：第一，建节点，用 malloc 申请一块新内存；第二，接 next，让新节点的 next 指向当前的 head；第三，移 head，把头指针（head pointer）挪到新节点上。就这三步，顺序不能乱，尤其是“接 next”一定要在“移 head”之前，否则原来的链表就找不回来了。 回忆一下，这就是头插法（head insertion）。它的好处在哪儿？插入只需要 O(1) 的时间，代码短、实现简单，很适合频繁在表头插入的场景。但你要记住它的“副作用”：因为每次都插在最前面，最终得到的是逆序链表。这也是为什么我们依次插入 1、2、3，遍历出来却是 3、2、1。 那如果我们希望顺序和插入顺序一致呢？那就换成尾插法（tail insertion）。思路正好相反：每次把新节点挂到链表末尾，而不是插到头部。代价是需要额外维护一个尾指针 tail，每次插入时更新它，否则每次都要从头遍历到尾，效率就变成 O(n) 了。它的结果是链表顺序与插入顺序完全一致，适合需要保持顺序的场合。 所以怎么选？一句话——想要逆序结果、或者就是频繁在表头插入，用头插；想要保持顺序、按次序输出，用尾插。两种方法没有谁更好，只有谁更合适，关键看你的需求。 最后留一个课后练习：把本课的代码改成尾插法，加一个 tail 指针，然后分别跑一遍，把两种写法的输出结果放在一起比较。你会发现，仅仅是插入位置的一个变化，输出的顺序就完全颠倒过来了——这个对比如果能亲手做出来，头插和尾插你就真的掌握了。 这节课我们从结构体和指针出发，一步步走到链表的创建、遍历和释放，又用图示追踪了指针的变化，最后做了三道练习。链表这一块最吃的就是“指针指向哪里”的直觉，大家课后多画几遍图、多跑几次代码，慢慢就顺了。这节课就上到这里，同学们辛苦了，我们下次见！
