# Phase 1.5 任务规划

2026-10-21，用户确认三页原型并要求“可以，准备task”。本次只准备任务，不领取或实施。根 [task.json](../task.json) 是唯一活动账本，现有 42 项全部为 `todo`；本文解释安排，不维护另一份任务状态。

## 输入与目标

依据 [PRD §0.5](PRD.md)、[需求说明 v0.3](PRD-phase-1.5-draft.md) 和 [ADR-0023](ADR/0023-free-course-learning-and-ui-direction.md)：学生可直接学习 AI 生成草稿；目标驱动规划、知识点辅助关联；大纲自动继续，按场景渐进呈现。程序保留确定性安全检查，普通语义审核不再阻断所有草稿。未可靠校验的练习反馈不直接计入正式掌握度。

[信息架构](design/phase-1.5-information-architecture.md) 和已确认的[首页／大纲／课堂原型](design/prototypes/phase-1.5-learning/README.md)作为设计输入，不重复建立原型，也不追认新任务已经完成。其余主要页面和完整状态设计仍需补齐。

## 任务顺序

以下编号均使用 `PHASE-1.5-` 前缀；具体依赖、范围、验收条件和验证步骤见根账本。

| 编号 | 交付内容 | 推进条件 |
| --- | --- | --- |
| T001–T005 | 课程与权限契约、持久生成状态、质量与学习证据规则、全站主要页面设计、独立验收口径 | 已确认 A—F 不重复审批；具体重大 API／数据／权限取舍及验收阈值须形成可核对方案 |
| T006–T021 | 数据与仓储、自由规划、可选节点关联、逐场景内容与动作、渐进生成、恢复修订、反馈与证据、API及兼容 | 对应契约完成；各任务独立验证，真实数据库检查不能用跳过代替通过 |
| T022–T034 | 统一框架、首页、大纲、课堂、代码与可视化、练习、导师、修订反馈、其余四个区域及移动端整合 | T022 依赖全站主要页面设计 T004；功能页面还依赖对应后端契约与实现 |
| T035–T036 | 零 Provider 集成与真实浏览器学习旅程验收 | 接真实隔离后端和明确 mock Provider；工程通过不等于生成质量通过 |
| T037–T038 | 有界开发诊断包及获准后的诊断 | 先冻结候选、材料、请求与时间预算、停止规则，再执行；不占用独立验收样本 |
| T039–T041 | 独立验收包、质量验收、性能验收 | 样本独立性、人工标签、准确配置和预算分别落实；质量与时延分别判定 |

按文件顺序、优先级和依赖串行执行，同一工作区最多一项 `in_progress`。首项为 T001。表中分组不是并行执行授权，也不要求把一组任务合成一个提交。

## 完成与停止规则

- 每项包含 3 条验收条件；完成实现、实际验证、记录证据并创建独立 `Task-Completed` 提交后才算完成。规划提交不带业务任务完成标记。
- 测试路径和检查器中标注“待建立”的接口是后续任务交付要求，当前不代表已经存在或运行。实现时建立并执行；环境缺失、跳过和 mock 结果不能替代真实数据库、浏览器或模型验收。
- T038、T040、T041 不以“采集完结果”为通过条件。未达到冻结的准入条件时保留失败并按阻塞规则处理，不启动依赖任务，不靠重复抽样冲淡失败。
- T037、T039 只准备执行包；本次真实 Provider 请求、模型试错和继承余额均为 0。后续真实执行必须有对应准确授权，所有失败、重试、取消和未完成均按冻结口径记录。

## 保持的边界

当前运行仍为 `catalog_only`。新草稿可学习是已确认产品方向，尚未实现或开放；已有签核课程、旧数据、凭据保护、输出清洗和 Manim 隔离继续保持。新链须有独立协议，不能直接取消旧正式发布门禁。

P1 账本只读，T040／T041 的失败或未验事实不变；H01–H08 继续封存，不能自动作为新链独立验收集。旧回归材料和开发诊断不构成泛化证明。

本阶段不增加 Phase 2 的动态题库、真并行辩论、教材问答或学习报告后端，不将未实现模块展示为可用。当前任务规划不包含新 Provider 接入、任意生成代码执行、生产部署、push 或 merge。
