# ADR-0049 可见审核视图：离线实现进度

用户已批准 [ADR-0049 A—D 及准确附件](../../ADR/0049-approval-20261031.json)作为隔离实现依据。旧候选和旧冻结包不变；本记录不是新冻结、独立评估、真实执行授权或 T102 完成。

`p15_visible_review_view_v1.py` 从经重建核验的 B/C 开发候选构造有序短 ID 可见单元，按原始字段逐项呈现讲解、代码、四题、答案、解析、模型／程序来源、状态、动作及完整参考。证据引文仅比较本次可见 JSON 严格解析后的目标字符串，并验证候选、视图及本地映射摘要；错误 ID、不可见文字、旧候选及篡改视图均拒绝。B 模型的原始答案和动作单独呈现，不由引擎补写；C 状态来自准确 catalog。每个单元的本地定位包含来源根、可解析 JSON Pointer 和具名投影规则，构造时从来源重建并核对。代码按既有高亮校验的 Python `splitlines(keepends=True)` 分行，保留行结束符且拼接无损；包括 CRLF、单 CR 与 Unicode 换行。

引用定义使用短 ID，每处一个独立可引用单元，附文档及该文档的解析结果序号；非空标签引用准确标签，空标签引用实际显示的派生类型。原始 Markdown 仍完整呈现。本地 source 保留解析树路径，不把序号称为原文字符或字节偏移。16 字段／15,840 处引用的开发样例，可见视图为 3,039,429 字节；该数不包括 Responses 外层请求，不代表支持全域上界、服务端 token 或费用限制。

当前 `build()` 仍使用固定合成开发任务的 `legacy.review_context()`，不是从受控生成／规划请求和收据重建的真实上下文；`validate_review()` 接收视图 JSON 字节，并未从实际 HTTP 请求提取，也不认证 Provider 来源。旧目标逐项机器映射、真实 Responses wire、容量证明、统一预约、B/C 完整修复及迟到／并发／恢复尚未完成。C 开发预览使用同一预分割行，Chromium 已核对逐行及 31 个动作、可见视图短 ID；另以有意与程序参考不一致的 B 合成状态和 Unicode 换行代码逐动作验证浏览器取模型状态。正文、题干和解析经安全 JSON 加载后使用 `textContent`，已验证 NUL、CR 和 CRLF 与目标逐字符一致；CRLF **代码高亮**的浏览器验证仍未完成。模型审核及用户教学标准均未通过声明。本轮真实 Provider 调用 0。

进一步构造的 B 臂边界反例：16 字段共 15,936 处非空引用，叠加结构校验允许的 20,000 字符／20,000 行代码，原始 payload 为 113,663 字节，而可见视图为 4,658,142 字节，已超过此前 4 MiB 开发门限。这是刻意构造的结构边界，不是合格教学课程；不能依据这一点从既有协议中静默排除，也不能将有限压力样例当作全域容量证明。代码行短 ID 数量和外层请求转义需要纳入容量方案。
