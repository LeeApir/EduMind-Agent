# 审核定位压缩：离线进展

本记录为 T102 开发证据，**不是最终容量策略、受批准执行包或真实接口通过**。旧候选和冻结文件不变，正式样本尚未选取。

## 已测的表示

`p15_compact_targets_v1.py` 对现有完整 binding 分配确定性短别名，普通目标保留路径，每份文档的逐引用目标按顺序成对记录。本地保留全部原目标 ID、路径、内容和绑定摘要；翻译前重建映射、核对候选和目标，翻译后继续原有 Schema、非空证据及精确子串校验。`p15_compact_review_v1.py` 已将**目标目录**压缩接入离线审核 wire；此 wire 使用新版本指令和别名，未经 Provider 验证。

`p15_compact_documents_v1.py` 另行实验可逆文档投影：定义使用索引，occurrence 路径从 token 树恢复；本地解压必须重建完整原文档、摘要和定义，并要求再次压缩完全相等。独立复核发现的额外影子字段会在还原时丢失的问题，已增加规范往返校验与回归。**此文档压缩尚未接入实际审核 wire**。

## 样例与边界

在既有支持范围内，16 个文本字段各 4,000 字符、每字段 990 个空标签引用，原 payload 约 65 KB、15,840 处引用：旧审核 wire 约 8.84 MB；只压缩目标目录后的实验 wire 为 5,631,586 字节，仍超过 4 MiB。一次在测试进程内把可逆文档投影替换进去的**尺寸实验**为 1,672,993 字节，31,884 个目标均在本地映射中。该数不是当前审核 wire 的大小，也不是对全部支持域、上游 token 或模型理解的证明。

另一个 12,800 引用样例中，原目标目录 2,800,309 字节，短别名目录 253,777 字节，未压缩完整 artifact 为 3,402,562 字节。两项实验均不使用正式选样或人工真值。

独立审查指出：原有部分目标指向完整祖先文档对象及其 canonical JSON；如果审核端只看到压缩对象，虽然本地可以无损还原，也不能直接假设审核模型看到的对象或可摘录字符串与原始目标相同。需先设计并验证审核端目标解释、特殊字符转义、所有祖先目标覆盖、候选与引用映射，再决定是否接线。构造中仍多次物化完整 binding；峰值内存、解析树深度及全域请求上界未证明。`bytes + 8192` 只是本地占额，不能保证中转追加内容、实际 token 或费用。

独立只读样例核对：直接把文档替换成 packed 形式时，原 155 个非 occurrence 目标中，143 个在 wire 上仍相同、2 个路径缺失、10 个对象内容不同。新增回归也确认，即使本地无损解包，模型可见的祖先对象并不等于原 canonical 目标。不能把当前压缩文档简单接入后宣称目标覆盖或证据语义等价。一次本机压力观察约 3.5 秒且会反复生成完整 binding；这不是 CPU/内存上界。

## 下一步及决策界线

先在不减少当前支持范围的情况下解决压缩后可见内容与所有目标的等价性，并推导请求字节和中间资源上界；将单次/全批本地预约、超限和未知结算规则与上游能力分开记录。若仍不能在可接受的接口容量下覆盖范围，须形成具体的引用数量、解析深度或其他限制方案：明确超限时拒绝而非静默截断、两臂同等适用、对原支持域及教学内容的影响，并按项目协议取得具体决定。不能通过挑选正式样本规避边界。

容量和表示尚未确定，因此依用户指定顺序，完整 B/C 真实执行器、受控响应/预约/修复链、并发和崩溃恢复尚未接线或声称通过。本轮真实 Provider 调用 0。
