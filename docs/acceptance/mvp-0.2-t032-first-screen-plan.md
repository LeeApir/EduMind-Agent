## 已核对的缺口

PRD §8.1：首字节 P95 ≤2s、首段 P95 ≤10s。
ADR-0002 仍为 Proposed，描述了计时起点（身份及请求 schema 通过）和
第一个有效 token，但“完整教学段落”只有自然语言定义，没有批准的可执行判定。
backend/tests/manual_provider_acceptance.py 的 first_content_ms 实际只记录第一个非空
delta，不验证完整段落。旧 MVP 0.1 报告把该值称为首段；
这不能作为当前 Pro 的完整段落证据，不改写旧报告或猜测旧 delta 的长度。

因此不直接执行旧脚本，不把首 token、HTTP 响应头或 agent_start 当作首段。

## 建议的段落规则（需要用户确认）

1. 累积真实 temporary token；在 Markdown 代码围栏外寻找第一个正文段落，
   排除空白、标题和纯代码，不用单个字符/状态事件替代。
2. 段落以空行结束；若临时模型流只有一个无空行段落，
   则在临时流结束（本接口 stage_changed/reviewing）确认该段落已完整。
   状态只提供结束边界，仍必须已有正文，不把状态本身当内容。
3. 正文至少包含一句以中文或英文句末标点结束的完整教学陈述。
   不临时指定字数阈值。不能确认教学意义的段落标记未满足，
   不凭短字符串碰到标点就视为通过；执行者按预定规则核对公开首段。
4. 无匹配段落、异常断流、失败/超时逐样本保留，不当作成功首段。

## 有限样本计划（待确认后冻结）

- 当前服务端配置读取但不修改 .env，不切模型/Provider；目前 Pro/Responses。
- 20 个正式样本，单并发；固定同一句单链表学习目标，新匿名 owner、新操作各一次。
- 0 个计费预热样本；第一个样本包含在分布中，不能事后当作预热丢弃。
  记录服务端进程/依赖启动状态及 Provider 冷热未知，不宣称所有层冷启动。
- 每请求最多180秒，计划一次执行；无客户端重试、不补跑失败样本。
  完整消费学习 SSE，记录正式生成结果，不在首 token 后断连省掉失败。
- 全局最多240实际 Provider 尝试（含 Gateway 重试、审核修正）。
  常规20轮约160次，但不是费用保证；预算耗尽时记录未完成/未发样本，
  停止，不扩额或重新开账本挑结果。
- 计费授权：现有同 key 必要验证直到用量耗尽仍可用；
  240是B建议的有限硬预算，不沿用A已耗尽的30计数器。
  遇余额/配额错误停止；费用与余额无法推算。

## 测量口径

沿用 ADR 描述的校验后起点：请求体、匿名身份及 schema 通过后进入学习处理；
验收服务记录同机 monotonic 时间，用于后续客户端到达时刻相减。
另记录客户端发起 POST 的端到端时延，明确它包含上传/代理/鉴权，不混用两套起点。
只用验收仪表层采集，不修改产品 API、安全校验或 Provider 请求。

分别记录每个样本的：

- HTTP 响应头到达。
- 首个 SSE 状态事件到达。
- 首个有效 temporary token 到达（首字节目标的有效内容口径）。
- 满足确认规则的首段到达/结束边界（首段目标）。
- scene_ready 正式资源发布总时长、done 状态（另列，不作为首段）。

取最近秩 P95=排序第 ceil(0.95×N) 位，报告每个里程碑样本原始数值。
失败/超时保留 null 和分类；缺失里程碑按未达标，不悄悄过滤后宣称通过。
同时列成功样本条件分布（若有），清楚标记不能代替全计划结果。
完整资源失败率与首段失败率分别报告；任何缺失均明确影响通过判定。

记录 configured/returned model、文本/结构化传输、资源/审核/画像指令版本，
以及首段提示源码版本/摘要（现有首段提示没有独立版本常量）；
macOS/浏览器或HTTP客户端/后端版本、实际前端代理和Provider网络、
隔离PG、并发、样本、计费账本、预热、超时、状态/用量元数据。
不保存 API key、Base URL、Cookie/CSRF、私有画像或完整模型原文。
