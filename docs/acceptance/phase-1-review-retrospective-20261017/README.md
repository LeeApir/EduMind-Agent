### 已能下的结论

1. Schema与压缩错误采集可以通过工程修复改善；官方明确strict不支持`uniqueItems`。投影去除此词并裁剪defs后，当前完整审核已实接成功；服务端去重约束没有删除。历史400的唯一根因仍不能追溯断定。[官方关键字表](https://help.aliyun.com/zh/model-studio/qwen-structured-output)
2. 扩到8192解决过一个明确2048截断单例，但另有Schema违规和完成后的语义失败，不能把全部问题归结为Token不足。
3. 模型能检出具体安全/事实问题，但在已检出主错后仍可能产生不受证据支持的附带结论，或漏掉另一类职责；“发现一条错误”不是可发布审核意见的充分条件。
4. 输入契约v4.4对完整/分散覆盖误拒已有正面观测，纯教学缺口也出现过正确needs_human；这不是“模型完全不会审教学”，也不证明覆盖路由稳定。

## 4. 自动系统必须承担什么，人工可以承担什么

现有依据是[ADR-0015 B/C](../../ADR/0015-shared-plan-and-hybrid-review.md)与[正式验收方案](../phase-1-om-redesign/acceptance-plan.md)。这里的“保证”先指可执行的权限、状态与校验不变量；**不把LLM对任意课程事实/C安全的判断描述成100%保证**。

| 要求 | 自动系统的不可转移职责 | 可交人工的部分与限制 |
| --- | --- | --- |
| 数据/权限/版本 | Schema、去重、owner、来源/摘要、依赖/动作引用、失效/撤回/取消、预算、SSRF与隔离；失败不能发布 | 不可豁免；不能请人工“同意忽略”技术/安全硬失败 |
| Provider与响应 | 准确选定路由、限时限量、完整性/用量检查、禁止静默回退、失败关闭；错误和未知保留 | 人工可诊断故障，不可把无响应/坏Schema补签成模型pass或课程发布 |
| 严重事实/可达安全缺陷 | 对已证实严重错误保持reject；不能因教学缺口全部转needs_human，也不能发布已知错误 | 人工可核定真实缺陷与审核误报；当前**有据严重reject的候选不可人工豁免**，需修正新版本后重审 |
| 无法证明的一般事实/安全判断 | 自动审核要通过独立验收、报告具体依据和未知；程序静态规则不能声称穷尽所有C错误 | 仅对合法进入needs_human的语义案件，合格复核者检查完整单元、可信参考与反例；无能力验证就拒绝/等待 |
| 教学目标覆盖 | 绑定原始目标/显式承诺，区分内部计划和学生交付，不把背景目标/可选动画扩成必达；未知进入未决流程 | 深浅、分散覆盖是否足够、是否已教未考、过程题效度和歧义可交人工；仍需完整学生资源，而非只看模型摘要 |
| 审核引用 | 程序校验ID、资源digest、字段及UTF8片段；不能把ID合法当论证成立 | 每个condition/impact及每个主辅引用的命题支持关系；引用错位/借邻字段要保留为质量失败 |
| 最终状态与发布 | 当前模型严重reject优先；needs_human完整案绑定、真实allowlist操作者、不可变决定、原子发布和完整读取门禁 | 人工只签准确版本的案件，不修改历史自动结果；无审核人保持等待，不让学生自己批课程 |

**诊断数据集的人工作答，与产品中的人工审批不是同一件事。** 用户确认某个“含错样本被正确拒绝”的测试通过，不等于允许这个含错课程发布。当前“继续”确认记录也没有证明进行了独立教师计时审查。

### 不改动的验收要求

- 正式T040仍是100个生成目标＋20严重错误＋20正确对照＋10长审核，另有混合路由专项。
- 首次完整Schema≥98/100、自动正式生成成功≥95/100、具体严重错误召回和分类≥18/20、正确对照自动pass≥19/20、10份长审核完整返回。
- 自动误报包含全部附带发现；人工通过不补自动分子。若实际需要20%甚至100%人工，不能把它说成满足95%自动成功。
- 若产品改为人工主导课程库/受限课程工作台，可以另作范围与PRD/ADR决定；**本报告不实施这种修改**。T040不通过时，T041/T042和动态发布继续受阻。

## 5. 人工逐项核对的工作量

估算参数、公式及未批准信封另存[规划假设](planning-assumptions.json)，与真实结果分开。

### 5.1 已知事实和估算假设

现有记录没有复核者开始/结束、暂停、查证等独立计时；聊天时间差包含工具执行和等待，不能当人工分钟数。以下是**规划估算，不是实测或SLA**：熟悉数据结构/C的复核者，一份短单元，三资源、3道题，单一简单示例；需要查陌生算法、长证明或新课程事实时可达45–90分钟以上，仍不能保证一定判对。

必须分开记四种劳动：数据集正确标签的制定；正式验收的独立内容评分；产品needs_human案件处理；开发者排查模型接口。不要把AI助手的分析耗时当真人效率，也不要把点击“继续”当完成了逐项专家审核。

### 5.2 只检查模型审核意见

令A为需要核实的独立断言数（含condition与impact），C为引用实例数（同锚点出现在不同finding仍分别核实）：

`T_opinion = 熟悉材料3–5分钟 + A×0.4–0.8分钟 + C×0.2–0.4分钟 + 记录决定1–2分钟`

| 实例 | 规划计数 | 估计工时 | 边界 |
| --- | --- | --- | --- |
| 当前fact例 | A约4，C=2 | 约6–11分钟 | 要检查源码推导16，而非只看模型reject |
| 当前mixed例 | A约10，C=5 | 约9–17分钟 | 除主错，检查not16、返回保证、教学缺口及引用支持 |
| high长意见 | 更多断言，C=9 | 通常更高，需逐项计时 | 多输出不是免费质量提升；不自行假定所有句子为真 |

上述A为规划拆分，不是冻结评分分母，不能把一个错误拆成多个“样本”来放大成功率。只审意见不能发现模型没提到的全部课程错误，因此不能替代完整课程审查。

| 核对原目标、计划及约定 | 2–4 |

### 6.3 预登记材料与淘汰规则

4条既知回归：UB推理强度、事实矛盾引用、混合教学缺口＋严重错误、完整正确对照。原失败输入/输出保留，不能把样本改得更容易。

8条新材料至少两个主题：2正确对照（含分散覆盖）、2纯教学不足（过程支持缺失/已教未考各一）、2具体严重缺陷（事实/安全）、2混合缺陷。先由合格人依据实际内容定标签和引用范围，后冻结，模型看不到期望标签。不得拿当前一直未运行的8例冒称通过，也不得只改数字就称独立跨课程测试。

任一条件发生即淘汰该唯一候选、停止付费：

1. 越权、泄漏、许可外回退、安全硬门禁被绕过、预算/计数异常；立即停止，不尝试补一次。
2. 非完整响应、Schema/业务协议失败或用量未知；保留失败，技术修复留给下一阶段，不在本信封中反复重冻重试。
3. 严重错误未具体检出，或因教学缺口而全部降待人工；正确对照被无据拒绝；纯教学不足被编造成事实/安全错误。
4. 任一附带重大无据断言、UB数值排除、无效语义引用；单个主错检出不豁免附带失败。
5. 混合样本遗漏独立教学缺口或不满足冻结报告结构；发现一处错误不等于完成所有职责。
6. 8工程小时、10小时候选人工准备/评分、12请求、164元任一上限到达即停；不得用新名字重启同一候选来重置上限。
