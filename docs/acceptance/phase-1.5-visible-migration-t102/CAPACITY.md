# 可见视图容量和本地预约：开发证据

这些数值用于隔离开发，不是已批准的实验预算。旧冻结文件不变，也没有据此调整正式样本或教学标准。

## 已有边界与计量

原模型输出的 canonical JSON 上限为 128,000 字节；每个段落、题干及解析最多 4,000 个 Unicode 码点，最多 8 段和 4 题，共最多 16 个此类正文位置。B 代码最多 20,000 个码点；B 的原始动作最多 64 个状态、180 个总动作，每个状态最多 7 节点。C 的代码、状态和动作来自受限 3+4 规格引擎。这些限制不能简单相加当作可同时达到的样本，因为还需同时满足 128,000 字节总上限。

审核实际请求通过 [完整外层构造器](../../../scripts/isolated_diagnostics/p15_visible_request_budget_v1.py)测量：最终 JSON 包括两段实际 `input`、版本化审核指令、完整 Schema、模型/推理参数以及用户消息的第二次 JSON 转义。开发预约按 **最终 UTF-8 请求字节数 + 8,192** 计算，输出请求值按 8,000 预约；共享账本对所有已预约调用保留占额并求和。它是可重算的本地记账规则，不是服务端 tokenizer 上界、上下文保证或费用保证。

项目锁定 Mistune 3.4.0；本地源码中的 block 和 inline parser 默认 `max_nested_level` 均为 20。它限制各自解析器的一部分嵌套过程，但还不能单独推出组合解析树深度、节点总数或整个审核视图的大小上界。不能将该默认值当作已证明的项目契约或在运行中静默收紧。

在已生成可见视图后，若该视图的 canonical UTF-8 长度为 `V`，将其作为 JSON 字符串放进外层请求时，字符串内容的保守编码长度不超过 `6 × V` 字节；还须加实际系统指令、Schema、JSON 字段名、其他参数及引号。这个关系只解释二次转义，**不证明**从原始合法 payload 到可见视图的 `V` 上界，也不等于模型 token 数。现在用增量编码在超过请求字节门限时终止，不截断教学内容；单个 JSON 字符串片段仍可能先整体分配。

下列结果取自 [capacity-evidence.json](capacity-evidence.json)，含原 payload、修订后 payload、每次外层请求及本地预约。参考/代码/动作均为合成结构数据，不能据此判定教学质量。

| C 密集引用 | 64,914 | 10,656 | 21／61 | 2,466,392 | 2,466,488 | 5,094,282 |

B/C 不同定义样例的静态本地输入预约合计 26,954,729，输出预约 72,000；若仅作算术演示，10 对完全相同的此类支持槽分别为 269,547,290 和 720,000，**不是**全域上界或实际收费预测。脚本中的 13,000,000 是**单次请求**估算门槛，而 B 单槽四次合计已达 15,549,898；不能把该数字直接当作全槽或全批预算。B 的 worker 完整结果为 19,722,308 字节，仍低于开发期 32 MiB 输出门限；非空修订意见重建的 worker 输入为 21,189,934 字节，低于开发期 64 MiB 输入门限。

同规模 B/C 合成材料另经共享控制器走完 9 次 Mock HTTP；实际登记的本地输入预约合计为 26,954,741，输出为 72,000，与上面的静态计算相差 12 字节，来自模拟审核意见的具体文本。完整请求和响应保存在[压缩证据](stress-mock-flow.json.gz)，可用独立脚本重放；其中的 10／20 token 使用量由 Mock 夹具提供，不代表真实服务。旧 4 MiB 已被合法结构样例超过，不能通过正式选样避开。

以当前开发门限作保守记账算术：单次请求最多 12,000,000 字节，对应本地输入预约不超过 12,008,192；B 每支持槽至多 4 次、C 至多 5 次，分别是 48,032,768／60,040,960，本地输出预约分别为 32,000／40,000。10 对支持槽至多 90 次，因此仅从这些门限可推出全批本地输入预约不超过 1,080,737,280、输出预约不超过 720,000；8 个拒绝臂槽本地处理，0 HTTP。这只是乘法上限：不证明所有合法输入都能通过 12 MB 请求或 worker 门限，也不证明账户上下文、token 计数和费用可接受。真实包仍须明确各槽及全批的实际授权预算。

## 资源停止行为及未证明事项

开发 worker 先限原 payload 和合法角色结构，再在子进程中解析 Markdown、重组候选与视图；使用 CPU/墙钟限制和采样 RSS 监测，视图展开及审核重建都在该子进程。开发参数为 worker 输出 32 MiB、输入 64 MiB、采样 RSS 1 GiB、CPU 25 秒、墙钟 35 秒。macOS 不支持此环境的地址空间硬限制，RSS 每 0.1 秒采样可能超冲；父进程序列化和解析也不是硬内存界。采样 `ESRCH` 只有在有界等待确认子进程退出后才视为退出竞态，仍存活或无法确认时停止。

控制器开发响应上限为 2 MiB，按流累计；超限仅保留前缀及其摘要、登记 `unknown` 并全批停止。正常范围内保留原响应；用量缺失、无效或超预约时保留原始证据及全部预约并停止，迟到响应不恢复运行。服务可能忽略输出参数或报告不同 token 数，取消客户端不证明上游停止。

**尚未证明**：原 payload 的所有合法 Markdown 在现有解析器中对解析深度、节点数、引用数、重复标签、view/binding/job 输出与重审增长的全域上界；因此尚不能确认上述 32/64 MiB、12 MB 请求开发门限或任何正式 token 预算覆盖既有支持域。需先完成静态推导和极端正反例；若合理预算仍无法覆盖，应提出具体引用数/解析深度或其他契约边界及影响，取得决定后才能实施，不通过筛除正式样本解决。真实 Provider 的上下文、计费和取消行为仍需按单独准确包验证。
