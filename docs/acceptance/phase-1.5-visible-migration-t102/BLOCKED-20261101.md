## 两个已复现问题

1. **停止与实际派发仍有竞态。** 已依次尝试在线程中检查停止标志、在底层传输入口按互斥锁登记派发，并增加已排队任务再次检查。独立评估者在最终检查读到未停止后暂停该线程：调用方先收到 `MOCK_HTTP_TIMEOUT`，账本为 `stopped`、Mock 底层发送数为 0；恢复线程后，底层首次发送数变为 1。已登记为 `sent` 并保留 unknown 预约，但不能说物理发送一定发生在停止结果之前。
2. **凭据编码回显可能进入原始响应账本。** 曾增加 JSON 结构遍历、嵌套解码和 bearer 字符集限制；独立评估者构造自然语言中的双层 Unicode 转义合成密钥，检测未识别，控制器在后续响应校验失败前已持久化原始响应。这个示例只含合成密钥，临时账本自动删除；未读取或泄露真实凭据。

[复现脚本](reproduce_blockers.py)实际只使用合成 resolver 和 MockTransport，并额外钩住 `getaddrinfo` 与 `socket.connect`；这些钩子不是操作系统级网络沙箱。成功复现上述两处缺口时故意以 **2** 退出；这不是通过测试：

## 建议的一次限定离线修复

按 [AGENTS.md](../../../AGENTS.md) 的“两轮有实质区别的修复仍失败”规则，本次停止追加同一问题的修复，先请用户决定是否允许以下一次独立离线修复与复审：

1. **隔离发送。** 保留现有唯一账本、固定分母和预约状态机；每次单独由受监督子进程执行 DNS、固定公网 IP、Host/SNI 和 HTTP，只向其提供当前角色的合成凭据，不通过 `fork` 继承另一角色的密钥、环境或无关文件描述符。跨角色凭据检查须由单独的受限可信组件承担，不能单凭进程隔离推断。只在预约与 `sent` 持久化后启动；到期／停止时终止并有界等待子进程，确认退出才报告本机发送进程已停；无法确认退出则明确返回 `STOP_UNCONFIRMED`，保留 unknown 占额，不再派发。增加父进程崩溃后对子进程的监护及恢复测试，无法确认子进程终止时继续按 unknown 处理；不得因恢复而补发。超时前已到达的回包可结算；终止后到达服务端的结果不可恢复，已入内核或网络的数据不可撤回，远端仍可能处理或计费。父进程的同步文件系统调用、系统调度和无法终止的内核状态仍不承诺硬实时。
2. **凭据与原件。** 在子进程内对常见字面、JSON、Unicode 多层转义做有界检查；对所支持的解码路径超界或无法确认时停止。为保留原件且避免不可信明文直接进入账本，离线样例采用 AES-256-GCM 封存原响应，并用批次、槽位、阶段及请求摘要作为附加认证数据；同一密钥下 nonce 由先持久预约的单调计数生成，崩溃后不对旧批继续加密，密文文件与账本失配或存在孤儿文件时保留并停止。账本只保留密文位置、摘要、状态和用量，校验器解密后核对原件与父链。仅使用临时目录中的合成测试密钥，目录／文件分别限制为 `0700`／`0600`。真实批次的独立密钥保管和访问方式须在准确执行包中另行确定；不能把测试密钥用于真实批次。原文加密也不能自动保护从中解析的候选、审核意见、错误、日志或跨供应商转发；这些路径均须单独检查，且不能以扫描保证发现恶意服务的任意编码或拆分。
3. **离线反例与独立复审。** 保留本页两个复现作为失败对照，新增慢 DNS、最终检查暂停、慢首包／流、杀进程及不可确认退出、编码／未知响应、迟到结算、回包解密与篡改、崩溃恢复，以及 28 臂槽分母测试。B/C 完整生成→修订审核→一次修复→重审仍须复用同一状态机，独立评估者复验后才考虑冻结和选样。

该提案不授权真实调用、真实凭据读取、发送课程、补样、放宽验收或恢复旧批次；如果本次限定修复仍失败，重新报告而不自动追加修复。若用户不选择该方向，可改为暂停该实验或提出其他隔离方案。
