# 正式测试后的方案重评

本次规划v2通过，两个场景的已读答案未重现先前返回值/自环错误，但第二场景缺actions使整次流程停止，sol未运行。因此结论是：已有定点修复在本样本有改进，端到端可靠性仍未成立。失败已包含教学语义、规划引用、场景结构等不同层面，继续逐例补Prompt不能充当可持续正确性保证。

建议保留目标驱动、可变场景、正式审核与现有持久化/权限/界面工程，重新划分模型和程序的职责。本文件仅为待决方案，没有实施契约变化或批准新调用。

| 部分 | 下一版建议 | 必须保留的边界 |
|---|---|---|
| 规划结构 | 将编排约束与学习目标分离；程序分配ID、管理版本与合法引用，模型提供目标和真实覆盖关系 | 不能机械补引用掩盖漏学目标；当前v2仅为请求约定，尚非此结构改造 |
| 场景外壳与动作 | 模型生成教学内容；程序构造其负责的固定外壳，基于已校验锚点生成有限动作或明确无动作状态 | 先定义职责/API及缺失语义；不在当前失败响应上偷偷补actions=[]宣告通过，不放宽原Schema |
| 可信练习 | 先选少量数据结构题型，用受限状态IR/模板从同一状态派生题干、答案、代码与动作 | 明确支持与拒绝范围，不能用通用静态规则承诺任意C程序正确；自由题仍待核验，不自动可信计分 |
| 模型审核 | 保留原教学标准、原始证据和独立审核；协议兼容单独验证 | sol本次未运行，不据此判断其能力，不把两个模型一致等同真值，也不扩大元数据兼容例外 |

优先准备一个最小“单链表头插”垂直切片设计：定义约束/内容/动作/答案各自的数据所有者，给出正常链表、自环、丢返回值、未初始化指针的支持/拒绝例子；先离线验证同一状态导出的一致性，再决定新的正式验证范围。新增IR、评分权限或API/持久化边界需要具体ADR和验收，不在本轮直接开发。

不建议立即换模型或再跑完整T038。现有证据无法证明换模型就能消除这些错误；先降低一次自由生成所承担的确定性责任，才能判断剩余讲解质量与审核效果。当前动态路线保持停止/catalog_only；旧失败、unknown、课程签核与H封存不改。下一步等待用户决定是否进入上述具体方案设计，不自动补Prompt、重发、开始其他课程或推进T039。
