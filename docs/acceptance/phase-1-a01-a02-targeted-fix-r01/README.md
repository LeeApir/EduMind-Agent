# A01／A02 定向修复与离线回归

用户只授权这两处具体改动和零调用回归。分为 T071（生成）与 T072（审核上下文）串行交付；历史失败、未运行项、模型答案、标签和三份停止台账保留。没有新的真实调用授权；T040仍blocked，生产catalog_only保持。

## A01：每一道题如何落实过程要求

详见 [生成改动](generation.md)。生成提示从无条件“2–4道”改为明确题数优先；在承诺N道过程题时，逐项核对题干要求学生使用的状态变化、更新顺序或退出判断。下标范围事实不会因解析讨论过程就补成过程题，选择／判断题仍可使用。

实际练习生成与已有修正请求现在收到摘要绑定的原始请求、精确分配目标及完整上游正文。原始要求不从模型生成计划中反推，快照篡改在请求发送前拒绝。版本为生成指令v9／场景v2，进入政策摘要。既有内容输出Schema、评分题型和调用上限不变。

这次没有基于关键词自动判定“过程题”的算法，也没有把原A01三题修成新课程。离线回归保留原失败正文并捕获实际请求；该失败的正确处理仍是待人工，不能用Mock回答补自动成功。

## A02：完整上下文已传，补精确定位及作用域核对

对上次实际18-request的正文重读确认，单元审核已经收到完整代码：`free_list(Node **head)`、函数内 `*head = NULL`、调用 `free_list(&head)` 都在同一source字段中。原问题不是服务端漏传代码。证明与新请求索引见 [上下文证据](A02-context-evidence.json)。

新增服务器构造的 `program_context`：

- 给出实际代码source及其他讲解／练习主张字段在当前请求里的JSON路径、资源摘要和现有锚点ID。
- 来源为已核验的完整候选；资源级只给了讲解时，不会虚构兄弟代码。候选位置缺失、资源摘要不匹配时拒绝索引。
- 索引只定位正文，不解析C、不声明程序一定完整或安全，也不替独立讲解片段推断函数和调用者作用域。

仅增加一段针对指针更新影响的核对步骤：先读实际形参、调用点和赋值位置，引用支持这些前提的原锚点；单独片段没有建立函数边界时，具体列出缺失前提并 `needs_human/unresolved`，不能断言调用者必然悬垂。有据可达严重错误仍拒绝。原通用证据强度规则没有扩写。

审核Prompt版本为v4.10；`review-program-context-v1`进入政策摘要，完整输出Schema与原A02逐项比较一致。新摘要沿既有机制阻止旧待审政策直接发布，旧已发布内容及历史评分不回写。原v4.9冻结文件保留；当前源码已换版，旧运行授权不能重用。

A02仍有此前已裁定的细化状态测量缺口。完整源码支持指针实现的事实核对，不会替它补教学测量。当前原材料适合 `needs_human`，并不因此整课pass。
