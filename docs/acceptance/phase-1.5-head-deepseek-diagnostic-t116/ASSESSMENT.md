## 四项阻断

| ID／位置 | 原句及影响 |
| --- | --- |
| T115-F01 `paragraphs[1].text` | “必须先写 data，再写 next”。第6和第7行确实按该顺序执行，但有效的新节点也可以先写next，再写data。访问时应保证所读字段已初始化。trace_step_01/06及展示证据只支持本例分配状态和执行顺序。该句复发了原F01，将模板顺序说成C语言限制。 |
| T115-F02 `paragraphs[4].text` | “t0 和 t1 虽然已经分配并互相连接”。两个调用都丢弃返回值时，caller始终i0，因此两次局部head均为i0，t0.next和t1.next分别指向i0，两新节点之间没有边。该句与所引 `head_evidence_v1.discard_return_comparison` 直接冲突，误教丢弃路径的拓扑。 |
| T115-Q01 `questions.unreachable_count.stem` | “那么从 caller_head 出发无法到达的动态分配节点有多少个？”题面只限定丢弃，mask=1仍允许malloc失败。成功分支为1，失败分支为0。程序参考及解析覆盖成功，题干缺少成功前提，复发原Q01。 |
| T115-Q02 `questions.normal_values.stem` | “正常执行并接收返回值后”没有明确这道题的malloc成功。“正常执行”可指成功路径，也可指按给定代码正常返回。代码对p=NULL明示返回旧头，因此成功时接收得到[11,30,40]，失败时接收得到[30,40]。参考答案只覆盖前者。 |

## 13帧与返回边界

从程序独立推导状态，并对装配逐帧断言行号、caller、head、p、返回值、节点data/next和局部活动状态。`?`为未初始化。

| 帧与行 | 独立状态及说明核对 |
| --- | --- |
| f00／无 | i0{5,NULL}，caller=i0，head/p未活动。 |
| f01／4 | head=i0，p=t0，t0{?,?}，caller=i0。 |
| f02／5 | p非NULL，条件为假，继续第6行，状态保持。 |
| f03／6 | t0{-2,?}，尚未连接，head/caller仍i0。 |
| f04／7 | t0{-2,i0}，旧链与caller均保持。 |
| f05／8 | 返回t0的地址值，caller仍i0。模型说局部“即将失效”，符合尚处于返回过渡的活动帧。 |
| f06／15 | caller接收t0，遍历-2→5→NULL。局部活动已结束。 |
| f07／4 | head=t0，p=t1，t1{?,?}，caller=t0。 |
| f08／5 | 第二次条件为假，继续第6行。 |
| f09／6 | t1{9,?}，head/caller仍t0。 |
| f10／7 | t1{9,t0}，旧链接t0.next=i0保持，caller尚在t0。 |
| f11／8 | 返回t1地址，caller仍t0。说明说局部“即将失效”，与尚未进行main赋值的返回边界相容。 |
| f12／16 | caller接收t1，遍历9→-2→5→NULL，局部不活动。 |

13个说明与对应程序帧一致。正常接收后t1→t0→i0，两次忽略时是两条分别指向i0的边。后者未展示于13帧，错误只在F02段落。

## 四题独立推导

迁移初始i0{30,i1}、i1{40,NULL}，尝试插11一次。逐题对比相应固定代码、输入格式、题干与解析。四道题没有直接答案或带答案的格式示例。

| 题 | 成功路径、失败路径及答案 |
| --- | --- |
| link_target | 该行执行时head=&i0，因此p->next保存i0地址，答案i0，解析准确。失败时该行不执行。题意取赋值效果，见N03。 |
| normal_values | 成功时caller=t0，完整遍历[11,30,40]。失败时caller收回原i0，遍历[30,40]。解析正确推导了成功分支，题面不唯一，见Q02。 |
| discarded_values | 两种分配结果都不会更新caller，遍历[30,40]。参考值正确。解析只叙述分配成功，见N02。 |
| unreachable_count | 成功后唯一动态t0不可达，计数1。失败时无动态节点，计数0。自动i0/i1均不计。题干缺少成功前提，见Q01。 |

原F01和Q01在派生正文中均仍存在。四个尾LF使冻结迁移代码匹配通过，教学结论仍为停止。评估者Provider调用0，应用写入0。本报告只覆盖全文静态诊断与本地装配，浏览器学习与反馈未运行。
