生产APPROVED_PLAN_VERIFIERS为不可变空映射，政策IDs/版本映射同为空。没有环境开关、模型字段或维护CLI能启用验证器；当前真实计划缺陷仍交人工，不宣称已解决A01或具有自动纠错质量。

只有origin_operation的初次plan_check、完整覆盖、无未决、全部局部计划finding获得批准验证器确认时才可预约一次。验证器ID与版本绑定政策及proof，预约前对不可变源快照重新计算验证器前提摘要/锚点/涉及finding。模型自称machine_checked、相邻字段或未知验证器不构成授权。复用已有计划、已生成正文/审核、用户要求不清、严重拒绝及缺前提均不进入此路径。

## 执行机制

操作/owner锁下持久预约rebuild_count=1及reserved事件，保留9个后续槽（新计划/重查/三资源及各审核/最终单元）。网络在事务外。生成plan-rebuild-prompt-v1/2048，修正上下文与原请求分列；再次锁定后确认计划版本没有被别的操作推进，保存v+1并复制原始输入/参考/政策快照，completed仅表示新计划已保存，不表示重查或质量通过。失败保存failed；同一操作唯一预约和唯一终态不退款。

新计划必须plan_recheck/8192，只运行一次。仍有问题立即终止，不进入第二次重建。通过后全部三类内容重新生成，不复用旧候选或审核。旧计划/审核保持不可变，以版本/摘要绑定和最新版本检查阻止继续授权；旧版已发布课程的历史读取保持原有规则，不偷偷撤回既有发布。正文阶段不回到重建循环，待人工修改需新操作。

正式发布入口新增当前owner/operation/plan的accepted检查门；plan_recheck还需对应completed事件与旧计划授权链。人工完整单元批准也不能绕过这一门。早期计划无法判断不产生半单元人工案件。完整单元私密历史同步展示旧/新计划检查、版本源快照、重建事件和新候选；维护plan show --body也含同操作事件，无批准/续跑权限。
