## 1. 范围与证据

本例说明的问题是：讲解审核因未提供兄弟资源而留下覆盖未知，完整候选实际已有程序和三题；代码/整课审核漏掉释放函数置空的教学表述问题；目标为 `linked-list-insertion` 而单元/计划/资源绑定 `c-pointer`。普通编译与内存路径通过不消除这些问题，严格编译缺末尾换行的失败也继续保留。

这些都是单样本观察，不是新质量基准、模型排名或因果结论。原候选、审核、人工案件、调用记录及历史评分保持原样。

## 2. 已采纳的审核原则

| 层级 | 自身职责 | 与其他层的边界 |
| --- | --- | --- |
| 讲解 | 概念、术语、指针过程、相关边界及自身明确承诺 | 完整程序/练习已分配其他场景时，不要求重复提供 |
| 代码 | 接口与调用、实现、正常/失败路径、所有权与释放、输出、注释/关键步骤与实现一致 | 不要求代码场景包办整节课的概念教学 |
| 练习 | 题目前提、唯一正确答案、解析及指定考查目标 | 答案/解析能解释过程，不代表题目已经考查过程 |
| 整单元 | 原始需求和计划承诺的完整覆盖，跨场景接口/术语/示例/答案/动作一致，明确承诺的交付时序 | 汇总学生实际可获得的证据，不以内部计划代替教学，不要求每场景重复全课 |

所有资源实际包含的事实陈述、代码片段和安全主张仍须审核，职责分工不构成豁免。资源通过仅表示完成自身职责，不能取代整单元覆盖检查；计划不能通过漏分配或缩小目标回避原始需求。兄弟资源尚未提供，不等于已证明整单元缺失；本资源自身确实缺失承诺、存在真实错误或判断所必需的前提未知时，仍应报告。

未知学情本身不阻止发布。审核应检查内容是否尊重明确背景和有据学习证据、是否编造个性化判断，而不是要求证明课程一定适合某位学生。用户说“刚学完结构体和指针”可以作为自述背景，但不等于已掌握。没有错题/偏好记录不能单独成为待人工理由；声称“你经常混淆二级指针”却无依据时，应修正。具体结论确实依赖缺失/冲突的学习者事实时，保留明确的未决问题。

本地身份/来源/版本/Schema 等硬检查与严重缺陷拒绝保持；资源真实未决不能由整单元 pass 覆盖；纯覆盖不足不伪装为事实或安全缺陷。四次独立语义审核、现有生成修正上限与总调用/时间上界保持，不增加自动全课重生成循环。

## 3. 后续必须冻结的具体设计

以下是待办任务的设计产物，不是本次已经批准或实现的新契约：

1. **T056 审核契约**：把场景职责、跨场景待核验事项与真正未决项分清；明确五个资源/单元必检 ID 的含义，是否需要新增必检 ID 或结果 Schema，以及政策版本/旧案失效方式。不能仅追加 Prompt 后宣称模型已遵守。
2. **T060 教学节点契约**：区分用户目标节点、路径推荐当前节点和本次实际教学节点。冻结“直接学目标”和“先学前置”的选择/告知规则，不简单把所有 current 改成 target，也不把用户自述背景当作掌握证据。明确输入快照、计划、资源、发布、评分、路径及重解释的一致性规则；需要 API/持久化变更时先形成可批准设计。
3. **T065 离线执行契约**：只支持明确批准的固定 C 样本及审阅后的测试驱动；绑定来源/原字节摘要、独立检查规格、工具链、隔离和限额。编译/执行均在受限环境，不向程序传入真实凭据，不挂载整个项目，不给网络或任意宿主路径访问权。不开发通用生成代码执行器或学生在线运行入口。具体隔离机制与限额需先批准；环境不可用明确记未运行，不回退到无隔离执行。

任务已存在不等于允许实施。用户后续授权开发后，依赖满足的设计任务才可领取；其具体设计中涉及审核协议、API、持久化或执行安全边界的选择，经明确批准后才实施对应任务。

## 5. 验收必须区分的正反例

- 讲解无完整代码/练习但其他场景足额交付，可以满足整课需求；整课真的缺代码/题目仍被拦截。
- 自身场景真的缺少承诺不借“分工”放行；真实错误不能通过移到讲解/练习中逃避安全检查。
- 无画像与明确初学背景不误判困难；编造学情、已知证据冲突和确实依赖未知前提分别处理。
- `free_list` 教学归属错误、跨场景接口混用、只有内部计划的过程教学和只考最终值的过程测量缺口分别保留，不能只测容易通过的场景。
- “先学前置”时课程真的讲前置且明确告知；“直接学目标”时内容和元数据都属于目标。路径重排、重解释、刷新、旧发布版本读取不能改变既有作答证据的节点归属。
- OM 原程序编译失败与独立函数驱动正常路径通过分别记录；EduMind 原字节严格编译失败与普通编译/运行通过分别记录。派生测试驱动不能冒充原程序通过，禁止自动补 typedef、改函数签名或补换行后声称原件通过。
- 编译成功不等于内存安全；追踪本例全部分配/释放不等于 LeakSanitizer 已运行；输出按批准规则比较，格式差异与数值差异分列。
- 故障注入覆盖 malloc 第 1/2/3 次失败及正常情况，对可编译样本分别检查实际 main 和登记的原函数接口驱动。EduMind 等可编译样本可执行 main/接口共8场景；OM 原 main 编译失败后运行项记未运行，函数驱动另行执行并报告，不凑执行数或替代原程序。有意丢链/重复释放/错误赋值等派生反例应使检查失败，原件不改。
- Mock/脚本化审核验证契约、编译/故障注入验证固定程序，都不能证明真实模型已理解新职责或达到正式质量阈值。
