## 统一计时与失败规则

客户端单调时钟记录动作开始 t0，服务端阶段耗时另外报告。HTTP 首字节从请求发出到原始响应首字节（含头），HTTP 头完成、首 SSE 状态与首非空 delta 单列，不能替换该指标。UI 指标从用户提交/点击到可观察 DOM 或媒体事件；两种时钟不混算。首次UI动作计时包含匿名准备/会话创建，不剔除；wire指标以对应业务请求开始为起点，匿名HTTP另列。

| 指标与 PRD 来源 | 终点与阈值 | 固定样本 |
| --- | --- | --- |
| 一句话首字节 §8.1 | wire 首字节，P95≤2s | 20 个固定目标，单并发，无计费预热 |
| 完整首段 §8.1、§10.1 | 最早完整且有教学意义段落在 DOM 可见，P95≤10s | 同一 20 槽；保留原始正文、全部候选时刻及 hash 绑定人工审计 |
| 教学正文首 token（收尾决定） | 合格教学段落对应最早正文 token，P95≤2s，仅优化 | 同槽独立列报，不充当首段或阻塞门槛 |

| SSE 恢复率 §10.2 | 断线后同 Cookie/游标恢复状态且无重复发布占计划槽，≥99% | 100 次受控断线，Job/课堂各50；包括终态、过期游标和重启，过期游标须410后GET快照并重订阅到一致状态才算恢复成功；预期410本身不算成功 |

完整段落沿用 已批准的首段规则（本地材料 `docs/acceptance/mvp-0.2-t038-frozen-plan.md`）：空行或临时流结束构成候选边界；须是完整教学陈述，导语/标题/孤立代码不算。保存所有候选与原始内容，禁止只留首个候选或事后补推时刻。独立审计不自动将首非空 delta 判定为教学正文。

P95 使用 nearest-rank，即排序第 ceil(0.95N) 个计划槽。失败/超时/不合格或缺失终点记为 +∞，保留原错误与原因；不剔除、不替换、不挑样。模型请求超时180s，渲染请求观察上限180s（与执行器超时分开）；失败亦进入成功率分母。取消/安全拒绝专项不冒充正常合法样本成功。每项报告全部槽、分母、重试、错误、缓存分层及运行环境。

## 质量、预算与证据边界

§10.2 schema≥98%、Review 严重错误召回≥90%、正式生成成功率≥95%、密钥泄漏0起仍保留；T033 运行前固定至少100个 schema/正式生成评估槽及至少20个独立严重错误基准，schema通过率以每个业务操作首次完整候选为分母，无候选/超时算失败；最终发布的schema合规必须100%。正式生成成功率以全部计划业务操作为分母，允许有限内部修正，但只有审核后发布才算成功；重试尝试数另列，不用内层重试扩大成功分母。真实用户激活≥80%、路径开始≥60%、单元完成≥50%是产品目标，自动化小样本不证明这些行为指标；§10.4 全部发布门槛在T034逐项核对。

本次执行预算为 **0 Provider 调用、0付费**。后续真实 T033 的目标清单、模型配置、实际尝试硬上限（含生成/审核/修正/重试/画像）、费用上限必须先形成冻结附件并获用户授权；预算不足停机并记录未运行槽，不减小分母。这里的样本计划不授予240次或其他历史调用额度。动画验收使用本地可信模板，不应调用模型；容器资源成本与环境可用性分别记录。

采样前冻结 Git SHA、模板/规则/Prompt/模型/Provider/协议版本、输入顺序、样本清单、缓存状态、机器/浏览器/容器限制和报告路径。不同模型和配置独立报告；Pro质量/闭环与Flash性能历史证据不得合并。所有失败报告保留，新报告不得覆盖历史文件；mock/离线与真实Provider分开。阶段退出不能仅靠旧阶段结果推定新增课堂或动画通过。
