# 头插法多 Agent 协作小型验证任务交接

2026-10-28：用户要求加入任务列表，由开发助手完成，当前评估助手负责效果评估。本文件仅为规划；唯一活动状态见根 `task.json`，不领取、不开发、不调用模型。

## 目标和交付顺序

验证“统一示例与确定性校验 + 职责分开的生成协作”能否减少结构缺项、接口漂移和答案/动作矛盾，同时衡量调用、时延与修复成本。范围仅单链表头插，不扩展通用题库、任意C解释器或生产多角色课堂。

| 任务 | 独立交付 | 交接对象 |
| --- | --- | --- |
| PHASE-1.5-T066 | 具体契约、支持范围、对照与评估协议 | 开发助手设计，用户批准具体重大契约 |
| PHASE-1.5-T067 | 受限示例/答案/状态轨迹引擎与独立测试 | 开发助手 |
| PHASE-1.5-T068 | 内容与动作分离的隔离协作原型、Mock故障验证 | 开发助手 |
| PHASE-1.5-T069 | 获准后的受控实验及完整证据包 | 开发助手采集，不自评为质量通过 |
| PHASE-1.5-T070 | 独立效果评估及采用建议 | 当前评估助手，收到交付后开展 |

开发助手从T066开始，后续按根账本依赖串行；用户仍需向开发助手下达执行指令。本次没有发送其他聊天消息或创建后台任务。评估助手不会自动监控，开发交付后用户回到本聊天提供提交和证据入口即可。

## 职责设计要求

- 规划 Agent 负责真实学习目标与覆盖关系；示例 Agent 选择受支持的题型与参数。
- 内容 Agent 解释冻结示例；动作 Agent 绑定已有锚点与轨迹，不重新发明算法状态。
- 教学审核 Agent 定位解释、歧义和教学适配问题；修复 Agent 仅按明确失败证据产生有限新版本，不改验证规则。
- 程序负责ID/版本/装配、确定性状态与答案、预算和停止门禁。逻辑角色可以共用模型；不强制六次调用或新增编排框架。
- 引擎自身须独立验证，同源输出一致不等于正确。正常插入、自环、丢返回值、未初始化指针、分配失败和未知语法须明确支持或拒绝，不猜测未定义行为的确定结果。

## 评估协议在实施前冻结

T066确定样本量、指标定义、阈值和修复限额；本规划不伪造尚未批准的数值。开发样本与评估样本分离，独立参考答案不得由待测生成器或同一状态引擎自行充当真值。已见D02仅用于回归，H01–H08继续封存。

对照应固定目标、模型/参数、资源条件并记录架构造成的额外调用。记录首次结构成功率、端到端成功率、严重事实/答案错误、审核漏检/误报、未知范围拒绝、修复后成功、降级比例、耗时及token/费用。失败、unknown、取消、未运行均按预先定义口径保留，不只展示成功课程。小样本只说明可行性，不宣称达到正式泛化成功率或稳定P95。

若未获准同条件基线，只报告绝对结果与历史差异，不报告可靠性提升百分比。区分确定性引擎与多Agent分工的贡献；缺少消融证据时明确无法归因，不擅自追加实验。

## 开发交付给评估助手的材料

交付README应包含候选commit、实际命令/退出码/测试证据、契约批准记录、运行配置和精确执行授权；提供全量课程可读内容、代码/题目/答案/动作、角色调用链、共享示例摘要、每次原始生成及修复历史、验证/审核意见、耗时/用量/费用和失败清单。敏感原件保留在受控路径并提供摘要清单，去敏结果可入Git。T069须建立只读核验入口和篡改拒绝测试。

T070输出 `EVALUATION.md`：逐项问题定位、独立判断与模型判断的差异、冻结指标复算、对照限制、采用/修改后复评/停止建议。开发完成不预填评估通过，评估报告完成也不等于方案质量通过。
