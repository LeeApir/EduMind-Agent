# 职责及数据契约 r01

提案，不是已实现功能。所有对象采用 UTF-8 规范 JSON（排序键、紧凑分隔、禁止NaN）SHA256。每次产物含 schema_version、run_id、slot_id、arm、revision、parent_digest、spec_digest、engine_version、template_version、prompt_version、payload_digest；程序生成这些字段，模型只返回角色 payload。旧版本只追加保留，不覆盖原响应。修复 revision=1，原件 revision=0。

| 所有者/角色 | 输入 | 输出 | 禁止权限 |
| --- | --- | --- | --- |
| 程序调度 | 已冻结目标、槽位、预算 | 角色调用、ID、摘要、停止事实 | 不能改原件、补模型首轮成功 |
| 规划角色 | 合成目标、允许学习目标枚举、支持范围 | 目标枚举及 coverage、观察要求 | 不能把场景数量当学习目标；不能造新语义 |
| 示例角色 | 规划、允许规格 | 一份符合SPEC的规格 | 不能提交自定义代码或答案 |
| 示例引擎（程序） | 精确规格、模板版本 | 节点状态/终止分类/标准观察、C模板展示、动作轨迹 | 不解释任意C，不调用模型 |
| 内容角色 | 规格、准确轨迹/代码/标准观察、目标 | 讲解段落、题目叙述、解析、事实引用 | 不改代码、参考答案、节点或轨迹 |
| 动作角色（程序） | 内容块锚点、已冻结轨迹 | 绑定状态的展示/高亮/步进动作 | 不创造状态；无锚点则失败 |
| 教学审核角色 | 完整准确候选及参考事实、原教学标准 | pass/revise/unknown、严重性、字段指针、理由 | 不自改答案/准入规则，不直接发布 |
| 有限修复角色 | 原内容、准确失败意见及不变参考事实 | 内容替换 payload 新版本 | 不改规划/规格/轨迹/规则；最多一次 |

协作臂把规划与示例选择合并一次模型请求，再由引擎构造事实，内容单独一次请求，审核一次；动作不调用模型。内容使用有类型事实引用，例如 `observation.final_head`、`trace.steps[1]`；程序验证引用存在及每项 fact_refs={path,value} 中的 value 等于引擎值。自然语言自由解释的正确性仍依赖完整教学审核和独立评估，不宣称程序穷尽检查。

内容 payload 固定字段：paragraphs[{key,text,fact_refs}]、questions[{key,stem,observation_key,explanation,fact_refs}]；程序补命名空间锚点和答案。最多8段、4题，每段/题文本最多4000字符，禁止额外字段。questions 必须一一覆盖冻结题目；模型遗漏字段或写错误 fact_refs.value 均拒绝原件，不补默认值。代码和动作由程序显式构造，记录 provenance=deterministic，不列入模型返回Schema首轮指标。动作仅支持show_state/highlight_code/advance_step，不执行脚本。

候选经过角色Schema、引用/事实值、装配、原有安全清洗、教学审核四层。原有生产数据类型若不适配，则原型内部保存专用格式，不放宽生产Schema。动作失败保留静态阅读候选并标 degraded；涉及题意的状态/步骤丢失则该槽失败，不能用降级计端到端成功。草稿、审核状态和可信评分资格是三件事，本原型全部无生产评分/掌握度资格。

普通教学 revise 可触发一次内容修复及一次重新审核；unknown/协议异常/事实错误/预算耗尽立即停止该实验。结构格式失败不修复，避免掩盖首次结构问题。每个角色响应独立保留用量/耗时/原始请求响应摘要和父调用；没有回显不能编造模型版本。Gateway既有兼容规则不自动扩展到新入口，若不适配先离线提出准确兼容取舍。

目录只写隔离运行输出，拒绝已存在输出路径、符号链接及生产数据库参数；不读真实学生/H样本，不读任意用户文件。原件权限0600，Git只存去敏摘要与受控路径。没有计费/执行批准不加载Key、不做DNS/HTTP。
