# 证据强度与逐项引用：零调用修复方案

状态：待评审方案，未生效。当前源码、生产Prompt v4.4、输入契约、结果Schema及默认catalog_only保持；本目录没有真实调用包、运行批准、标签签核或预算。旧review-remaining-r01继续ADMISSION_FAILED停止，已用3/5、后两条未运行，旧剩余预算不转入新轮。

## 1. 结论不能强于证据

| 判断 | 所需证据 | 允许的表达与处理 | 禁止推断 |
|---|---|---|---|
| 确定错误 | 在明确前提内存在直接矛盾或有效反例，能解释条件和影响 | 如定义良好的固定求和得到16却声称18；按事实/安全严重度判断 | 把局部反例泛化为未检查条件下的全部结果 |
| 无法保证 | 能证实保证缺失或某项前提失效，但不能确定某次运行结果 | 如越界导致未定义行为：不能保证返回16或正常返回 | 不能从“无法保证P”推出“非P”；不能断言返回值必不等于16、固定值或必崩溃 |
| 证据不足 | 必要前提、可靠来源或定位材料缺失，无法支持所需判断 | 具体说明缺什么，放入unresolved，需要时needs_human | 不能把“未证实P”当作“P错误”，也不能凭未决内容放行 |

判断对象须拆开：长度3却在源代码可达路径读a[4]，安全错误有确定证据，应保留severe code_safety/reject；该未定义行为的实际返回数值则无法保证。不能因数值未知把已证实严重越界全部降为needs_human，也不能靠已证实越界为附带数值断言背书。condition_or_counterexample和impact的每个断言都受相同规则约束，不能只核对类别、总verdict或第一条正确finding。

逻辑边界：未获P的保证，不等于已获非P的保证。回归用两个抽象可能状态（P真/P假）展示该推断无效；它不是预测未定义C程序会实际返回哪些值，更不会运行不安全C代码。未定义行为依据[LLVM项目说明](https://blog.llvm.org/2011/05/what-every-c-programmer-should-know.html)。

## 2. 逐项核对引用

对每条finding先拆分具体论据，再为每个锚点核对原候选版本、resource_id/content_digest、JSON pointer与UTF-8范围，读取实际片段。内部明确该引用的角色：定位被审核声明，提供反证/推导前提，或仅提供背景。列入finding.anchors的每个引用必须对该finding中某个具体论据作出贡献；“同一字段组”“主题相关”“ID合法”“附近有相关文字”均不足。

引用被审核的错误声明，不等于该片段本身必须证明审核结论。例如讲解a1定位“返回18”及它自己的total16，代码/source可提供实际求和16的独立前提，两者可以联合支持矛盾。反之，合法主锚点不能抵消无关辅助引用：历史事实样本a15只锚定/items/2/answer的F，不能给“返回16”作直接数值证据；也不能借其他位置的题干偷偷补充该锚点的含义。它可以为“该题答案为F”作证，故规则不是禁止a15或F。

锚点目录成员校验只能排除伪造ID，不能证明自然语言论据获得支持。离线脚本可以确定解析字段/范围与摘要绑定，不能一般化自动证明语义支持关系。新Prompt应要求生成者在返回前逐项自查、只保留确有贡献的引用；已存原回答一律保持原样。若所需引用确实不可得，说明具体证据缺口，不伪造引用；独立成立的严重错误仍保持拒绝。

## 3. 历史证据与回归矩阵

本方案绑定两个完整原响应及其原学生材料，不修改finding、锚点或历史分数。第2条用户曾在知悉a15局限后确认继续，这是当时的继续授权，不会把a15变成准确数值引用，也不使该响应成为“引用全部精准”的正例。第3条结构/类别门禁完成，但独立语义复核失败，停止事实保持。

| 回归 | 应保留的区分 |
|---|---|
| 原越界响应第三条fact的“不等于16” | 核心越界拒绝正确，附带数值排除不成立，整体诊断失败，不静默改原文 |
| 同材料的方案对照“不能保证16” | 只在明确标注的合成新对照中使用；安全严重度和reject不降低，不声称实际模型已输出 |
| 定义良好的数组求和，声称18 | 可以证明16与18矛盾，保留fact/reject；修复不能让所有确定事实变成未决 |
| 仅缺来源/前提 | 证据不足而非确定错误，具体未决；不凭关键词生成fact |
| 原事实响应a1+a15 | a1主证据有效但a15不支持返回16，引用质量负例；不能只因存在一个好引用判整体引用合格 |
| 同一a15用于“该题答案F” | 允许的引用角色对照，防止按ID/值封禁 |
| a1声明与正确代码/source联合支持18/16矛盾 | 引用支持关系应正确，不要求每个锚点单独证明整个复合结论 |
| 可达越界＋其他未决 | 保留严重reject，不全部转人工 |
| 正确完整内容、分散覆盖、已教未考、过程支持缺失 | 沿用原pass/pass/needs_human/needs_human判据，不引入调用示例、动画或其他目标要求 |

regression-cases.json保存证据、预登记期望和来源摘要；它是人工编写的回归规格，不是模型语义评测成绩。离线检查只验证原材料绑定、原finding保留、锚点解析、反例逻辑与对照完整性，不靠“有某词就通过”、也不宣称机器已学会逐项引用。
