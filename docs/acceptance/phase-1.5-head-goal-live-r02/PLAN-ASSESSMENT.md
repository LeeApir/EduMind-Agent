## 阻断语义点

1. `plan.scenes[0].purpose`写“头插两步（new_node->next = head; head = new_node;）”。`new_node`与`p`的名称区别本身可以只是别名，不单独作为缺陷。问题是计划没有区分此处被赋值的head属于哪个作用域，而同版固定C函数实际执行`p->next = head; return p;`，**函数局部head始终指向旧头，不存在head=p这一步**；调用者执行`caller_head = insert(...)`后才更新自己的入口。在本任务专门讲清局部参数/返回值的目标下，不能把未限定作用域的head赋值当作本例准确步骤。若把这段理解为另一种抽象伪代码，也必须补充其与调用者变量的明确对应；当前规划没有这项约定，不能替模型补上后判通过。
2. `plan.objectives[1].description`写“调用者不接收返回值会丢失链表入口”。本例起点非空，caller_head指向自动存储节点i0。忽略返回值不会清空或破坏该指针：原链表仍有入口；丢失的是从该调用者入口到新分配头节点/前缀的可达性。原表述未限定“新头/完整新链表入口”，把不同后果合在一起，影响本次要学习的核心区别，不能直接作为准确教学目标展开。

独立手算（从给定C文本推导，未执行C）：第一次调用前caller_head=&i0，值12、next=NULL；函数参数head复制&i0，malloc成功得到新节点，写4、next=&i0，返回新节点地址。接收返回值则caller_head指向新节点，序列[4,12]；忽略返回值则caller_head仍为&i0，序列[12]，新节点不可从caller_head到达。两次均接收才依次得到[4,12]及[7,4,12]。因此“旧头链接”“局部head不自动更新调用者”“返回新地址由调用者接收”应分清，当前规划对后两者的表达不足以通过同版一致性核验。
