# 待审：计数一致性与最终上下文核对

状态：**提案，未获契约批准、未接入运行执行器、真实调用 0**。依据 ADR-0027 的预算／安全／准确执行包约束；不改 PRD 质量阈值，不改 r02/r03 历史。`audit_p15_input_count.findings` 只是离线证据分类器，不是可发请求的准入器。

## 具体决定

| 决定 | 建议规则 | 离线证据与待解决边界 |
| --- | --- | --- |
| A 保留数值相等 | 未来单独获准的兼容性包仍要求同一冻结模型／上下文／Schema 的预计数等于生成 input usage；不加固定偏移、比例或“在 32k 内就接受”的例外。两端不同或不能验证即停，未知预约保留。 | 实际原件重放触发原异常。没有证据证明相等要求应取消；即使报告数值在预约内，也没有独立事前界。 |
| B 最终上下文一致性另设门禁 | 只有事前能核对最终有效上下文来源和计数覆盖范围，才能把该计数用于预算准入。system 合并允许预先冻结的精确双换行拼接；追加／替换任何未冻结指令必须拒绝或保持未验证。响应回显只能发现矛盾，不能独立证明服务端未隐瞒追加。 | 本次完整前缀＋21,336 字符后缀；反例显示计数修正后旧门禁仍会接受它。需供应商可核对的实现／最终请求证据，不以“新版模型”代替。 |
| C 输出限制分别验证 | 保留本地 8,000 总输出预约和报告 usage 的拒绝边界；另要求可核对的上游强制 max_output_tokens 映射与包含推理 token 的语义。回执上限 null／缺失／不同不能当作已验证；不能仅在输出已越界后检查便声称事前封顶。 | r03 实际回显 null；输出 480 不证明 8,000 上限被强制。离线分类器独立标记 null，不伪称证明服务实际移除了限制。 |
| D 补齐观测证据 | 若后续另行批准实现与执行，发送前分别保存两端方法／公开 origin/path／准确 body SHA／安全参数摘要；收到后先保存 HTTP 状态、响应 SHA、安全白名单字段和具体停止原因；原始失败先留证再校验。禁止 Authorization/Cookie/凭据写入；回执未知字段不作可信证明。 | 本次只有单份 body、错误类型无具体原因、失败 HTTP 状态缺失；Mock 可验证同体和失败路径，不能回填历史。需后续实现脱敏／失败持久化测试，当前未实现运行修改。 |

不建议“丢弃额外模板后本地重计数”、直接相信 usage 替代预检、按单次差额增加预算、把 alias 名称相同当作 tokenizer 相同、或换模型／Provider。这些都没有本轮证据支持。

## 离线验证如何解释

实际冻结 `CountedTransport`＋明确 `httpx.MockTransport` 重放三种情况：

1. 实际 r03 计数／回执：停止，保留 32k／8k unknown 占额。
2. 仅让计数等于 6,507，保留回执追加指令和 null 上限：旧传输器会通过，离线提议判据另报两项未验证；这是旧门禁充分性的反例，不能当作供应商修复验证。
3. 合成干净对照：计数相等、instructions 恰为两段 system 的冻结拼接、上限回显 8,000、Schema 相同：旧传输器通过，离线分类无矛盾。它只说明检查逻辑能区分这些已知异常，不证明中转实现或真实强制上界。

另有各维度独立异常对照。所有测试拦截真实 DNS／socket connect／.env 读取，不运行批次入口，不导入任何旧预算为执行权。

## 批准与执行边界

本提案推荐收紧证据要求，**没有给当前候选证明输入／输出事前硬上界**，也没有批准其继续。若采纳重大预算／上下文契约调整，先形成准确 ADR／附件批准登记，再实现新版本并做完整离线验证；之后仍须独立准确真实执行授权。此次仅交付可审查方案，不申请运行批准、不创建 r04 包。

当前无需付费探测即可判定 r03 应停。将来只有在用户明确要求且服务商只读资料无法解决的具体问题存在时，才设计能够区分假设的最小合成探针和准确预算；普通“继续”不替代该预算批准。不得把旧批次余量视为探测预算，也不得将探针结果自动扩展到完整课程诊断。
