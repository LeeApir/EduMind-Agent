## 1. 本轮目标与结论边界

验证当前简单版本的关键生成、审核和发布门禁是否在小规模样本中正常工作。复用已有工程证据，不重新筛选模型，不围绕失败样本修改Prompt或追求连续通过。

- 正常44次项目Provider请求，全轮硬上限60次；未用额度不追加样本。
- 全轮不超过5小时，包含准备、必要检查、模型运行、GPT评分、报告和清理。
- 取消120分钟真人核对和逐条Lee确认，改用明确标注的GPT评测记录。不得伪造原执行器要求的human confirmation或复用旧continue文件。
- GPT评分不能替代产品中的人工审批；`needs_human`课程继续待审，不能由测试者GPT签署人工发布决定。
- 通过只表示“当前受限版本小规模验收通过”，不证明原100目标的98%/95%/90%指标或总体错误率。

本次属于T040范围调整方案。执行前同步PRD、对应ADR/验收计划和活动任务的适用完成条件，保留原大样本要求为延期事项及历史记录。仅写本文件不改变T040状态，也不代表P1自动退出；T041/T042另按批准范围处理。

## 3. 测试清单与调用分配

### A. 完整课程生成：4个目标，正常32次

固定数组、单链表头插、栈、循环队列各一份明确需求。每份要求讲解、完整C示例、三题及答案解析，使用一致示例。头插旧输入可作回归，但必须标注已见材料，不能冒充独立新例。

每个目标走实际计划→三类生成及各自审核→整单元审核，正常8次。检查：

1. 背景与教学目标正确区分；目标、路径推荐和实际教学节点符合已批准规则。
2. 讲解、代码、关键步骤、预期输出和练习一致。
3. 静态核对接口、调用者赋值、边界、分配失败及释放逻辑；有疑点保留未决。
4. 自动资格、待人工、拒绝及失败状态真实保存；如测试隔离发布，记录准确来源和版本。

不额外生成课程做浏览器演示。浏览器仅复用这四份结果，检查阶段显示、待审隔离及按准确版本读取；不把待审正文暴露当作正式课程。

只调用整单元审核，不对每份再机械增加三次资源审核。

| U02 | 可达的严重代码安全错误 | 具体检出、reject，不从UB推断确定数值 |
| U03 | 严重安全错误与教学缺口并存 | 保留严重reject，同时具体报告教学缺口 |

| U05 | 过程已经教过，题目未考过程 | needs_human，准确限定测量缺口 |
| U06 | 完整正确内容 | pass，无无据附带意见 |

本次材料在[阅读册](materials-review.md)中完整列出，来源和内容摘要在[索引](case-index.json)中固定，具体反例/适用scope/预期集合见[标签](labels.json)；模型看不到标签。它们是新写内容，但沿用已知历史诊断结构，不因换数字而声称独立、未受既有经验影响或双盲。原失败栈样本不复用。标签由测试者GPT及静态程序/数学事实建立，不是独立真人真值；材料有歧义须冻结前处理，不能开跑后根据模型回答改标签。

| R01 | 正确讲解，完整代码/练习明确分配给其他场景 | 不要求本讲解包办整课；只审核自身承诺 |

### D. 额外请求：最多16次

正常调用合计32+8+4=44。另16次为共享余量，主要用于A组原生有界修正；不得新增测试样本或重测失败槽。一次修正生成和一次复审分别计数，其他新增项目模型调用同样占用余量。

44个基础槽先保留**容量**，不是提前创建44条“已发送”预约；实际每请求仍须发送前持久预留，失败/不确定均占实际槽。余16槽不能侵占其他未运行项的基础容量，也不能把某例未用容量改作重复调用。保守基础包总输出上限491,520tokens（60×8192），各角色仍分别遵守2048/4096/8192；这不是实际输入＋输出总用量或费用估计。

每资源最多两轮修正及每操作20次/180秒限制保持。全局额度不足以完成后续步骤时，不继续发送该目标的请求，记录未完成。不得为了凑修正覆盖而注入错误或强制模型revise；没有自然发生修正就报告未观察到，复用已有工程回归说明路径实现情况。

## 4. 必要工程检查与代码验证

复用T070及相关任务的既有证据，先核对源码、契约、工具链和依赖是否匹配。仅对发生变化或缺证据的关键部分补跑：

- Schema、来源/版本、节点绑定、引用位置、输出与调用上限。
- 待审、拒绝、失效、取消、跨owner内容不能取得发布资格；原子发布及准确版本读取。
- GPT评测记录与产品人工决定隔离，不能借测试修改正式审核结果。
- 已批准固定C样本的编译、分配失败和释放证据有效；相关实现变化时补跑登记样本。

不重跑整个后端/前端测试库，不新增通用代码执行器。新生成代码若只作静态检查，必须记录“未实际编译/执行”，不能借固定样本通过证明它也运行正确。

## 5. GPT评测与计分

每个目标或独立审核样本完成后，先封存原始候选和回答，再由测试者GPT核对，决定是否进入下一例。不要在180秒操作中间等待真人或测试者逐条批准revise；自动修正按实际原流程运行，并记录实际上下文和版本变化。

所有候选在隔离环境处理。发现错误意见已进入修正，报告实际传播并停止；不声称提前阻止过传播。不让评测者给生成器补提示、改答案、改路由，或删除不合格finding后重新计分。

每例记录：

1. 技术完整性、模型/配置/准确请求绑定及用量。
2. 核心缺陷检出、分类、预期路由是否符合。
3. 全部condition、impact、unresolved断言是否有据。
4. 每个主辅引用是否支持对应命题。
5. 实际修正输入、版本差异、发布资格和最终状态。
6. GPT结论、理由、机械证据、未判定项及评测者身份/配置。

编译、故障注入等确定性证据在其适用范围内优先；GPT不能凭自然语言覆盖真实失败。无响应、未执行、无法判断均不计通过。原始模型结果不改写。

### 受限验收通过条件

- 关键工程门禁全部通过，必要检查无未完成项。
- B组3份严重样本核心缺陷均具体检出并拒绝；3份正确对照均正确pass；2份教学不足准确needs_human。
- C组4份材料核心职责与路由判断均符合预先标签。
- A组至少3/4自动完成且GPT核对实际内容合格。剩余1份可以是有依据的needs_human或明确隔离的非严重失败，必须留在4份总分母；原模型pass但GPT查出实质错误的目标不能计自动成功。
- 全部16个测试项中，低风险附带意见错误最多涉及1项，且没有进入修正或影响发布。该项完整质量仍记失败，不能写成16项全通过；各项核心检出与完整质量分别计分。
- 没有任何红级事件，且未超过时间/请求上限。必要项目未完成时，结论为“未完成”，不得补签通过。

## 6. 停止规则

| 级别 | 事件 | 动作 |
| --- | --- | --- |
| 红 | 预标严重缺陷被应负责的审核scope放过或最终取得自动资格；错误意见实际进入自动修正；错误导致无据严重拒绝；权限、身份、版本、隔离、预算或发布硬门禁失守；配置漂移；发送/接收状态未知 | 立即停整轮，停止后续预约，保存原件与未知项；不换模型、不调参、不重试 |
| 黄 | 核心拒绝正确但存在未参与修正的低风险附带错误；合理待人工；已明确可隔离的技术失败；其他非严重质量失败 | 该例对应指标失败或按预期记待人工，GPT核对后可继续不同的冻结样本；不重复本例 |
| 绿 | 核心预期、实际内容、全部断言和引用均正确 | 保存后进入下一例 |

当已不可能满足受限通过条件，可以按预登记的不可达判定提前停止，不为凑数运行余下样本。报告保留完整固定分母和未运行项，只声明失败/未完成，不用已运行子集推断总体错误率。
