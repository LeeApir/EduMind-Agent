# 新版审核视图契约提案

状态：待独立审查与准确决定；不是可运行 wire。版本拟定 `visible-review-view-v1`。适用于隔离头插法小型实验，既有课程、旧批次和正式教学标准不变。

## 请求的可见内容

下列内容均是审核模型在该请求中直接接收的字符串或结构，不依赖本地解压、外部文件或调用工具：

| 区域 | 直接可见的完整材料 | 所有权／来源 |
|---|---|---|
| 任务 | 原始目标、目标 ID、槽规格、题型约定、适用教学审核规则、允许假设 | 同槽 B/C 相同 |
| 讲解 | 按原顺序的每段完整原文、原始 Markdown、非激活的引用文字和定义 | 两臂模型各自生成；正文与原文引用均不得删节 |
| 代码 | 完整 C 代码、稳定行号或可确定的行顺序 | B 模型；C 程序 |
| 题目 | 四题各自完整题干、答案、解析和题型；答案按准确类型及值呈现 | B 全由模型输出；C 答案为程序事实、题干解析为模型 |
| 状态与动作 | 每一步完整状态、节点、指针、未知／循环标记及顺序；每个动作和代码高亮/锚点关联 | B 模型原始状态和动作；C 的准确引擎状态和动作；不以 C 数据代填 B |
| 参考与上下文 | 该槽完整受限规格、程序参考轨迹及其明确来源、必要上游材料；标注参考并非模型内容 | 审核两臂同一参考政策；不把独立评估真值发送任何模型 |

准确提交原目标、`plan_constraints`（当前规格）、允许上游（即使为空也显式表示）和 `catalog.example` 全部代码、轨迹及观察；它们是旧审核请求中的参考，但原先不全部属于候选目标。拟为可见参考新增带来源与原值绑定的短目标，不冒称这些是原有 target ID。B 的生成/修复仍不接收引擎参考，B 审核可依据既定策略看到参考。

引用定义如为共享文本，可集中发送一次，逐处标明位置和定义；不得只给不可读的数字或要求模型自行解压。原文中的空标签、未知状态、无动作或空链必须明确呈现，不能因为为空而遗漏。**预览中显示原始 Markdown 字面内容**，与旧 Markdown 展开显示不同；任何后续渲染或动作展示必须与审核所见绑定，说明其具体语义。

引用的解析树标签属于 parser-derived 数据，可能因反斜杠转义或实体解码而不等于原 Markdown 的连续子串。原始 Markdown 与派生标签须作为不同来源的实际可见目标，不能把派生标签声称为原文摘录；解析树路径也不能冒充原文字符或字节位置。若需要原文坐标，须另行证明其准确性。

## 证据目标与输出

1. 构造最终用户消息的精确可见视图：有序文本单元格式为 `{"id":"t0","kind":"...","text":"..."}`，按确定的展示顺序递增编号 `t0`、`t1`……，同一视图不重复、不允许非规范编号。完整局部数据本地保存 `short_id → candidate_digest、view_digest、字段路径、可见文本、来源/类型`。同一内容出现在多个位置时分别绑定，不能仅凭字符串值去重。引用每处有独立位置，空标签可定位其非空的显示描述，但程序生成描述须标作结构信息而非原文。实际 controller 应从请求字节重新解析并重建这个映射；模型不必在现有 Schema 中回传 view_digest，受控收据必须将其绑定到此次响应。
2. 纯文本单元的证据目标是**实际传入该视图的原始字符串**；数字、数组、对象或状态若提供为 canonical JSON 字符串，则目标是**该实际发送字符串**，转义规则与消息中的该字段一致。不得以本地解压后的祖先对象、未发送的 AST 字段或哈希预映像作为 quote 目标。对于承载为 JSON 字符串的文本，证据校验针对接收方解析该 JSON 字段后的值，而非传输层反斜杠；展示给模型的字段和值必须精确且可复原。
3. 审核输出继续使用已有严格 Schema：`candidate_id`、`pass/revise/unknown`、`uncertainty` 与最多 20 条 issues（严重性、领域、短目标 ID、非空 evidence_quote、非空 reason）。短 ID 必须存在于当前**实际已发送**视图；引文按 Unicode 原样、区分大小写做目标文本子串比较，不隐式解码、正则、语义推断或跨单元拼接。
4. 不存在的 ID、错臂／错槽／旧版本／错视图、目标文本未出现在发送消息、空引文、仅本地可见引文、错误 severity/area、非法 verdict 与矛盾 uncertainty 一律拒绝；不截断或替模型更正。多个相同原文单元仍有不同 ID。编码错误、重复键、重建失败或用量未知按执行包停机规则处理。
5. 问题可以引用每个段落、题干、答案、解析、完整代码行、各状态／动作及引用定义；必要时以多个 issue 分别指示多个目标。聚合对象旧字面引用的变化见迁移表。自然语言事实正确、可教性及难度仍由原审核和独立评估核对，ID 合法或引用存在都不证明教学正确。

代码按准确原字符分行，行终止符及末尾换行也必须通过明确的可见单元或格式字段无损保留，拼接后必须逐字符等于原代码，不能用 `splitlines()` 静默丢掉差异。空字段、缺失步骤等问题应引用实际可见的相邻题目／代码／动作并在 reason 解释缺失；不得构造未实际存在的证据文本。若没有任何适当的可见证据，应返回 `unknown`。视图与审核响应均严格解析 UTF-8 JSON 后按 Unicode 码点原样比较，不做 NFC、空白归一或 Markdown 重渲染。

## 程序证据与修订

每次尝试先保存实际请求字节、模型身份及参数、输出原始响应和用量；以受控响应严格解析原模型输出，再构建候选、共享文档、可见视图、逐单元映射和摘要。保留完整本地解析树／定义／旧目标清单、组装算法版本、所有历史版本和事实来源。摘要只能证明一致性，必须与实际受控请求、响应收据及顺序/权限日志一起重放，不能单凭散列证明 Provider 来源。

修复版必须由本次审核通过校验的具体意见触发，绑定准确父候选及该次审核收据；修复后重新生成候选、视图、短 ID 映射与审核请求。旧 ID 即使恰好相同，也不能跨候选复用旧审核意见。B 修复反馈需具名独立复核并记录与候选、意见、收据及反馈摘要的绑定，避免向 B 泄漏程序参考答案；不能用恒真回调代替。严重事实／安全问题或 unknown 停止，不按普通问题修复。

## 非目标和未决

本提案不更改生成模型的所有权、不为 B 程序补答、不减少直接可见的教学内容与可定位覆盖、不放宽教学验收，也不授权真实调用。旧的可引用目标集合和跨字段 quote 的接受范围按迁移表改变；并不声称新旧目标集合等价。细化视图、局部容量／参考总量、每槽及全批预算、长度/转义、解析深度和上游用量限制尚需以真实实现及完整边界离线验证；如不能覆盖现有支持域，须明确另提具体限制及影响，不能凭样本筛选掩盖。
