## 入口是否仍受已知反例影响

| 已知问题 | 此入口的实际关系 |
| --- | --- |
| 检查后暂停、stop_unconfirmed后新建发送进程/迟发 | 没有supervisor→spawn路径，但**等价的检查后暂停迟发仍存在**；进程启动由人工shell/工具负责，不能证明停止后不启动。不是修复，只提请更弱语义 |
| 非法JSON先解析导致丢原件 | `collect()`先逐块加密/fsync，回读后才wire.validate；有实际同入口Mock反例检查，完整非法JSON仍能解密还原 |
| 普通/迟到原件缺失却汇总verified | 无总汇verified；body receipt只记录当时观察，后续缺件则证据不完整；实际真实后由评估助手重查原件，不相信旧汇总 |
| 模块同名替换、跨角色Key继承 | `-I`＋绝对入口/显式repo路径避免工作目录同名模块；不fork也无第二角色Key。但本机repo/venv被篡改、同用户访问和环境之外的祖先状态无完整证明 |
| 本地账本/锚共同回滚 | 本批无独立锚，仍无法防御。异常不恢复续发；用户若仍要求原保障，则本包不可启动 |
