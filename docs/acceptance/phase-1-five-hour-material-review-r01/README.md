新版本 [R02-v2 学生正文](R02-v2-student.md) 在同一讲解中提供并解释 `int value = 21; int *p = &value; return *p;`：

| 原要求 | 新版直接交付的证据 |
| --- | --- |
| 取地址 | 第2步说明 `&value` 取得对象地址，并用它初始化 p；区分地址和值21 |
| 解引用 | 第3步说明表达式 `*p` 访问所指对象；明确已初始化且 value 仍存活的前提 |
| 返回值 | 第4步区分返回 int21 与返回局部地址；末段区分返回和打印 |
| 未知学情 | 使用通用说明，不声称学生已经掌握、不会或经常混淆 |

语义变更只有讲解正文；原始目标、计划内容、代码和练习正文保持一致。新材料使用独立 `R02-v2` 身份，离线重建资源／依赖／单元摘要、动作、锚点及实际适配器请求，避免只改正文却沿用旧绑定。完整材料见 [R02-v2.json](R02-v2.json)，[请求捕获](R02-v2-request.json)只经过 MockTransport，不访问外网；[pass 预标签](R02-v2-label.json)是下一版静态预期，实际结果仍 null，未被模型验证。新讲解中的 C 仅静态阅读，未编译运行。

## A02：原请求满足，细化计划的过程测量不足

来源是上次实际生成内容，完整快照与原文路径见 [A02-evidence.json](A02-evidence.json)，逐题裁定见 [A02-adjudication.json](A02-adjudication.json)。没有修改 A02 的计划、练习或旧输出。

**裁定：三道题都算过程题；但按冻结计划的更具体承诺，当前测量覆盖不完整，宜 `needs_human`，不应作事实错误拒绝，也不应以一次 unit pass 认定整课完成。**

| 层次 | 承诺与实际证据 | 裁定 |
| --- | --- | --- |
| 原始请求 | “恰好三道过程题及解析” | q1重连顺序、q2空表边界、q3头插后遍历顺序都要求过程知识，满足这一要求 |
| 过程教学 | 讲解给出空表→[3]→[8,3]的 head／next 变化；q3解析也解释两次头插 | 这段轨迹已教，不能说只有内部计划或只有最终数值 |
| 更具体的计划目标 | `obj-trace`：“对空链表依次头插3和8，逐步写出head指向、各结点data/next与最终链表顺序，并解释头插导致逆序”；练习场景分配了该目标 | 需核对其具体状态追踪测量，不能只核对通用“过程题”数量 |
| 实际测量 | q1选 `n->next=*head` 后 `*head=n`；q2判断是否必须特判空表；q3只选择最终 `8 3`，没有题要求产出或辨认完整逐步状态序列 | 对原始过程要求有覆盖，但对这项细化的逐步状态追踪目标只有部分测量证据 |

这里的 `逐步写出` 是当前明确目标中的状态追踪能力，不将“必须开放题／新输入控件”作为通用门槛；选择、判断题只要确实要求辨认完整状态序列，也可提供相应测量证据。多个场景可以共同教学，不要求每题或每个载体完整重复全部目标；但**教学文字已经展示状态**不能替代**练习要求学生处理这些状态**。本例只需补齐一处针对该细化目标的测量，不要求三题都重复轨迹。若目标仅是一般过程掌握，也不能无中生有地要求完整逐步书写。

q3不是“只问最终算术结果”：从头插3、再头插8推出遍历8、3，要用重连和逆序知识。因此，旧单元回答的“缺第三道过程题”表述过强；旧资源回答更具体的“没有要求逐步状态”指出了真实的细化测量缺口。二者不能混为一谈。

下一版若保留当前计划，最小修复是细化或替换一道题，要求对两次头插产出或辨认 head／各结点 data、next 的状态序列，并设置“最终顺序相同、但中间链接错误”等可区分项；本次只裁定，不代改实际 A02。不能删除旧计划中的目标来追认旧通过。

建议沿现有契约输出 `needs_human`，`findings=[]`，在 `unresolved` 明确：三题均使用过程知识，但尚未测量计划承诺的完整逐步状态。实际事实／安全缺陷仍独立检查。这是本次窄范围覆盖裁定，不宣称其余计划目标均已全面考过，也不改变旧无据 major 拒绝及单次复测结果的历史分数。
