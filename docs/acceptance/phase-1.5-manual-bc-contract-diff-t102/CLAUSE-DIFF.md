# 单组 B/C 探索：执行契约差异提案

状态：**待决定，不是执行包或调用授权**。本提案响应用户 2026-11-01 的新指示，只修订单组探索的拟议执行条款；不改写[原方案](../phase-1.5-manual-bc-exploration-t102/PROPOSAL.md)、旧失败或冻结包。T102 和 T038 继续 `blocked`。不实现、不读取真实 Key、不调用 Provider。

## A．截止与本地停止

| 条目 | 原提案 | 新提案 |
|---|---|---|
| 截止承诺 | 实际首次派发不得晚于批次/单次截止中较早者，即使监督进程未运行；未验证的内核机制是前置 | **发送前检查**批次与单次截止；未到期才允许启动一次发送。检查后到实际发送之间可能遭遇系统调度暂停，因此**不承诺实际首次物理发送一定发生在截止前**。这是一项明确的执行契约变化，不把原时隙说成已修复。 |
| 串行 | 一次一个在途请求，逐次人工放行 | 保留：每次只派发一个经登记的请求，不后台排队、不自动推进；仅当前请求正常完成、证据核对通过且发送进程确认退出后，才可判断是否进入下一请求。一旦停止，无论退出是否确认，均不得继续该批次；出现异常即全批停止。 |
| 监督和停止 | 独立监督，终止后确认进程退出 | 保留独立监督。到期或收到停止要求时，监督者尽力终止本次发送进程及可确认的后代，并在有限等待内核实退出；**只有确认全部相关本地发送进程退出，才报告 `local_stopped_confirmed`**。无法确认时在有限等待后报告 `stop_unconfirmed`，全批停止、不再派发。有限等待和截止的准确数值及计时方式需在未来准确包固定，本提案不声称硬实时返回。 |
| 已发与未知 | 已进入网络的数据不可撤回 | 保留：`local_stopped_confirmed` 只表示本机发送进程已确认退出，不证明 Provider 未收到、未处理或不再计费。已启动而结果不明记 `unknown`，保留占额及记录；不重试、不补发、不回退、不重启旧批。即使进程在截止后才首次发出，也须如实记录，不事后改成截止前发送。 |

用户要求暂停内核级截止研究；未来该单组探索**不把完成内核级绝对截止机制作为前置**。普通进程调度、监督者延迟或系统暂停都可能产生检查后、停止确认前的迟发；这项风险不能通过人工看表、事后日志或 Mock 测试消除。若可观察到首次发送发生在截止后，或回包完成时已过截止，须如实留存事实和可保存原件并停止，不因响应核对通过而继续；实际派发时间无法确认时记 `unknown`，不得编造。子进程、继承发送描述符或逃逸后代无法枚举、确认关闭时必须报告 `stop_unconfirmed`，不能报告 `local_stopped_confirmed`。停止确认后不得由该批次继续派发，无法确认则保持 `stop_unconfirmed`。

拟沿用的待冻结资源建议是最多 16 HTTP（7 次合成角色准入＋B 最多 4 次＋C 最多 5 次）、批次 120 分钟、单次 60 秒、DNS 9 秒；这些数值仍是提案，不是本次真实调用授权。具体截止起点、预留及发送进程的确认范围必须在准确包中给出；若采用单包先准入后课程，还须明确处理 ADR-0047 D 的原先后要求，不能继承旧例外。

## B．保留可信启动、凭据隔离及证据完整性

1. **可信启动不因 A 放宽。** 以已核对绝对路径与摘要的解释器、入口及依赖闭包启动，可信工作目录不得被不可信对象遮蔽；不能从不可信当前目录、用户 site 或 `PYTHONPATH` 隐式导入同名模块。准确实施方式须在后续以合成材料离线验证。
2. **仅当前角色凭据。** 每次只向受信发送进程提供当前角色 Key；该进程及其祖先进程、环境和继承描述符不得残留另一角色 Key。Key 不进入命令参数、日志、请求证据或另一角色进程。合成 Key 测试不能证明真实凭据的 OS 级隔离；同用户访问限制和管理方式须如实披露。
3. **先登记，后发送。** 发送前在独立侧持久登记并核对请求编号、槽位、阶段、请求 body 摘要、父候选/审核收据、预约及截止；失败不得发送。每次候选、审核和修复继续绑定同臂实际父版本与收据。
4. **普通与迟到原件同等核对。** 收到完整 body 时，安全封存解析前原始 body，记录长度、摘要、HTTP 状态及可安全保存的用量；普通 `responded` 与 `late` 均须可找到并核对其原件、记录和独立副本。缺失、篡改或冲突一律 `evidence_incomplete/unknown`，不得标 `verified`；独立登记或终态缺失也不得因重算本地 seal 而视为完整。只记录确实观察到的迟到回包并结算已知用量，不推进后续请求；没收到的回包为未知。原始 body 不是完整 HTTP wire，敏感头和 Key 不写证据；超限或疑似凭据回显时保留安全的有界证据并标 `partial/unknown`，不伪称完整原件。
5. **失败与未运行保留。** 本次两臂和七个准入阶段按实际执行状态记录；原正式 10 支持＋4 拒绝双臂实验的分母、教学标准和独立评估要求不变。模型 pass 或引文准确不等于教学正确。B 不代填答案；B 到 C 前的独立评估及允许的一次普通教学修复仍保留。

这些是待实现/验证的要求，现有 Mock、合成密钥库和存在缺陷的旧完整性汇总不能作为通过证明。未来准确包须列出请求及响应容量、用量未知、可信目录与密钥来源、加密/副本保存、删除与核对方法，完成必要离线反例和独立评估后，再就准确包另行决定真实调用。

## C．费用边界：待选择其一

### C1：可核验硬额度

先核实两家服务的账户币种、实际费率及其独立、可执行的费用约束；须有足够证据证明本批两侧合计不会突破准确包中约定的金额上限，包括在途、延迟入账和取消后的计费。拟议金额可从原方案的 **总 USD 5、生成 USD 2／审核 USD 3** 起审，但账户实际币种、能否分别隔离额度及该数值是否合适均未核实。已有算术情景中的审核侧约 USD 3.69，已超过建议的 USD 3；它只是依公开价格和本地预约的假设计算，不是费用预测或上限。若不能事前验证实际硬额度或币种换算，则 **C1 不可启动**，不得仅凭充值余额、本地预约或请求 token 参数宣称硬上限。

### C2：无法核验硬额度时的明确风险例外

准确包仍固定 HTTP 次数、逐次本地预约、请求字节、输出参数、时间及停止条件，但**实际金额不设可验证硬上限**。实际账户费率、币种、模型隐藏上下文与上游输入/输出限制可能未知；服务端可能超出请求的 token 边界，取消或本地停止后也可能继续处理、延迟计费。本地 token 预约不是上游硬限，也不是金额上限。实际已知用量和账单分开记录，未知结果保留占额；本选项必须在未来准确包中逐项披露，并由用户**明确接受该批费用例外**后才可真实执行。旧批次的例外不继承。

**待用户决定：选择 C1 或 C2。** 本提案不推定选择，不记录任何新批费用例外；无论选哪项，准确模型、接收方、外发内容、实际费率依据、请求预算和新窗口仍需在独立准确包中列明并另获真实执行授权。
