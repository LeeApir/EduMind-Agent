# 开发诊断逐项评测方法

以已批准 ADR-0027、其准确附件和 PRD§0.5 为准；本包不变更发布、权限、留出隔离或质量门槛。唯一预算例外是用户对本次提案明确免除货币上限，依据 `user-direction-and-material-approval.json`；请求、token、时钟与停止边界保持，不能推定任何真实请求已获授权。官方参考价不是中转实际收费承诺。

1. 支持域固定 12 课程、6 画像对、至少 4 主题。顺序和输入完全按 manifest；2 个负例另列。每份逐一核对原始目标、显式要求的形式/C语言/场景数、全部场景能否从讲解到练习独立学习、引用/图示能否显示、边界与前置是否完整。完整率、需求遵循率、可学率均 ≥95%，固定分母 12 因而各需 12/12；失败、unknown、未运行不剔除。
2. 第一份课程输出进行单份画像真实性检查；第二份后同时查该对差异，保留两份准确 SHA。已知自述必须影响真实前置解释、例子、节奏或练习难度，不能只换称呼；未知不能补造基础或掌握度。有效差异需 ≥90%，6 对需 6/6。图谱 0/1/多个提示只作辅助，节点未命中不得阻断或冒充核定关联/掌握度。
3. 每份计划确定 n 时冻结场景分母（1–8 范围）；失败计划使用原输入范围上界列出未运行槽，绝不按成功场景重算。逐一检查原始首次主响应的 Schema：以 PG attempt 的 purpose=primary、准确 request/schema、首次 settlement outcome 和实际 wire 原件判定，格式修复不能补首轮分子。首轮 Schema ≥98%；仅生成12份计划加各自 n 个主场景，最多少于/等于60个主槽，无额外“凑100次”调用。
4. 对所有可见原文穷尽列出可判定原子事实，定位到场景/块/行并写证据、true/false/unresolved。事实准确率 ≥99%，不可把 unresolved 当正确；代码安全、定义、过程、复杂度、边界和跨场景约定均需检查。未运行原件保持未完成状态，不声称已检查。自然严重错误必须为0，一旦发现立即停发；严重与否须写理由，禁止通过拆分轻微事实稀释严重错误。
5. 穷尽所有题目，核对题干、选项、正确答案、参考解、允许输入、评分规则与已教内容的一致性，答案正确率100%。只对契约支持的精确评分输入检查可判定适用性；主观/不支持输入保持未决或人工，不把它们硬改为“精确正确”。每份报告明确全题覆盖，不执行任意模型生成的 C 或网络操作。
6. 自然质量先经人工判断，随后20个审核探针的模型观点只作为被测意见。10严重/10正确真值为助手起草且Lee采纳的开发标签，不属于独立留出评测。每个被报告问题由人核对引用是否匹配真实缺陷，记录 TP/FP、漏检及正确对照误阻断；严重召回≥9/10，全部报告问题精确率≥90%，正确对照误阻断0，未解决争议0。原文不能定位/只泛泛警告不得算TP。输出中预植入的严重错误不属于自然生成严重错误分子。
7. 工程项（鉴权/owner隔离/持久化/幂等/协议/usage/公开私有边界/可恢复证据）必须全通过。PG 真实产品链路和独立预算账本均保留原件；任何失败/未知都不补分。执行器采用保守提前停止：人工自然质量 fail/unresolved 或工程失败即停止；对审核召回允许一个漏检，第二个漏检停止。此保守停止不会降低上述判定门槛，也不保证用满额度。
8. 最终汇总同时呈现 planned/attempted/completed/failed/unrun/unknown、主 Schema 与修复、HTTP计数请求与生成请求、输入/全部输出、墙钟、参考费用和实际收费未知状态。所有正式率按冻结分母和原始证据计算；不使用 Mock/T035/T036 的通过率替代本轮质量。T038人工决定可继续/需修改/放弃候选，任何后续重跑需新包及明确批准；没有自动第二候选、自动发布或自动产品质量签核。
