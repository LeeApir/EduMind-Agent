# 校准判据 v1：草案，待独立人工核对

权威原始目标仍为：**用C实现并明确追踪数组{3,8,4}求和循环的关键状态和退出条件，并用题目检查是否掌握这个过程。** 不承诺完整数组节点，不要求动画，不从未知学情推定能力。

1. 实现：正确C代码、必要输入和返回/打印说明可以满足实现要求。不能从“代码存在”直接推出已完成“明确追踪”的教学承诺。
2. 过程教学：学生可见材料须明确展示初值、关键轮次的累计状态、首次条件失败及不再执行循环体的边界。本例为s=0→3→11→15，i=3时i<3为假，不访问a[3]，返回15。证据可以分布在讲解、代码注释/步骤、练习解析或实际动画，不要求讲解重复全部内容；内部计划不是交付。仅给F答案、未展开的解析和待学生自行推演的题干不能当成已展示的正确轨迹。
3. 过程考查：题目应明确要求学生依据代码推演中间状态、条件判断和退出边界。判断题、选择题、填空题均可，评分答案格式不决定是否考查过程；草稿推演不要求提交开放式长答案。不因学生可查讲解或存在答案解析就一概否定题目，否则所有带解析的练习都会失效。
4. 最终算术和不依赖执行语义的加法练习不足以检查过程掌握。不能把“求和结果正确”自动当作中间状态/退出边界考查。
5. 缺教学或缺测量具体进入needs_human，指出是哪一层、哪个证据缺口；不得捏造fact/安全错误、不能把“未交付讲解”误写成代码逻辑错误。事实或可达安全缺陷另按证据判断，严重reject优先，不由教学未决抵销。
6. pass要求六个必检ID完整、unchecked/findings/unresolved均为空且全部附带断言无误；needs_human须准确说明目标相关缺口，不能声称已交付的轨迹未教、不能按题型直接拒绝。每条引用只能支持其实际包含的命题，不能借用邻近字段内容；结论不强于证据。

新材料不是为了证明学生已真正掌握；它只检查课程是否交付了承诺的教学与过程题。真实掌握度依赖学生作答证据，本例无此证据。

上述三轮轨迹是本次固定微型示例的核对依据，不扩展为所有算法都必须穷举每一轮；其他目标按其关键状态及退出边界判断。

旧screen-complete的判断题、原pass标签、真实needs_human及CORRECT_CONTROL_NOT_PASS全部按原样保留。本草案不重新裁决旧样本为pass，不删除或抵销那次失败。
