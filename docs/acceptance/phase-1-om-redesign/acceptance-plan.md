# OM式课程重构：验收提案

状态：设计/零调用实施范围已批准，绑定[ADR-0015](../../ADR/0015-shared-plan-and-hybrid-review.md) A–D。T043交付设计，不是T040通过。真实Provider请求/费用授权均0；下文样本规模不构成预算批准。

## 1. 测量对象

每个冻结组合包含计划生成、三场景生成、资源审核、一致性审核、动作模板、本地规则、发布器、人工路由政策、Provider/模型/推理和采样配置。配置改变新开独立轮次，不拼接旧轮次成绩。

同一目标只有一票资源级成绩。把一堂课拆成三个场景、多个声明或多个模型调用不增加成功分母。模型审核pass不等于人工事实检查通过；真实验收仍对实际内容独立核对。

## 2. 验证顺序

### 2.1 零调用工程验证（T044–T054）

使用明确标合成的结构化结果，禁止真实出站。最小字段/不可变性与兼容矩阵按[契约附件](data-and-compatibility-contract.md)及[Schema](minimum-contract.schema.json)冻结，T044先建同义校验与关系。覆盖：计划缺约定/伪参考/跨owner、三场景示例或答案冲突、前序修改使后序失效、动作悬空、审核pass却有未知项、显式needs_human、两轮修正耗尽、模型不可用和预算耗尽、人工准入/过期/取消/重复/争抢、原子发布和所有读取门禁。另覆盖legacy intro与planned explanation入口、别名/旧收据重放、同发布快照关联代码、缺语言不默认Python、换示例全失效、simpler/deeper重绑复审、等待/失败保留旧发布、原子切换课堂revision及并发409。当前有据严重reject不能转人工批准；失效待审案使操作failed/REVIEW_CASE_INVALIDATED，取消仍为canceled，已发布后撤回不倒改历史终态，均须明确回归。

数据库部分须在实际测试PostgreSQL验证Alembic、复合约束、事务回滚、审批/取消竞争和重启读回；Mock不能替代。前端有真实浏览器的Mock接口旅程，再另做真实服务E2E。现有catalog_only、owner/CSRF、Provider出站、旧课程签核/撤回、测验与Manim规则完整回归。通用动态代码执行仍不在范围。

### 2.2 新链路诊断（准备于T054，实际在T040另批）

事前固定8类：一致的计划与三资源、代码内存安全缺陷、知识事实矛盾、跨场景表示冲突、含无害冗余头文件的正确对照、前提不足需人工、两轮修正仍未解决、长内容完整返回。每类至少一份不同输入，具体材料/标签/实际请求依赖由可执行轮次逐项冻结；这里不是“只需8次调用”。

使用新架构完整上下文，人工标注应检出的具体错误/反例与路由，模型不能看到预期标签。预制不确定或修正耗尽结果只证明路由工程；若想声称模型会在真实未知输入上正确请求人工，必须另列真实模型观测，不由合成tape推断。

具体严重漏检、重大无据断言、安全失守、越权/泄漏、预算/协议错误立即停止。仅分类错配单独报告，可在本组其他条件安全时继续固定独立槽；不得因此开放发布或免除正式分类阈值。此诊断补充已随ADR-0015 D获零调用实施批准，真实预算仍需另批，旧13次四组与r01–r11原判定不改。诊断不是正式抽样或课程级合格证明。

### 2.3 正式质量（T040）

保留原独立新例规模：100个生成目标、20严重错误、20正确对照、10长审核。全部具体材料、人工标签和判定先冻，正式新例不进入调参；任何调用失败不替换。新增混合路由专项至少20个离线案件（人工/硬拒绝/失效/正确自动流转分层），人工真实审批另按实际发生件数报告，不伪造20次人工操作。

每个目标允许最多20次正式调用，若临时画像/临时流参与则最多22次；100目标最坏为2200次，仅为理论上界，不授权执行。单独50份审核基准的调用数按实际资源审核+整单元审核固定，不能默认每份1次。HTTP探测、重试（若未来明确允许）、修正和取消前已发请求都计费。实际计划必须以总次数、总输出及可证明输入界给出具体同币种上限；不能仅按“一个目标一次”估费。

### 2.4 学习旅程与性能（T041）

只在新组合T040通过且范围/预算另批后做真实服务/浏览器/Worker流程。至少覆盖：一句话→计划/生成→自动发布→练习反馈；明确待人工→流结束→重入仍待审→真实人工批准→正式读取；人工拒绝与取消；重解释旧批准失效；按需DSL维持原独立审核/隔离。人工等待使用实际维护者操作，不用助手脚本预签事实正确。

HTTP首字节P95≤2s、完整教学首段P95≤10s、普通课堂首字节P95≤3s及原动画门槛不变，使用既有固定分母/nearest-rank/失败+∞口径。教学首token仍单列非阻塞。人工排队时间不混入自动模型耗时、不从端到端等待中隐藏；分别报告人工等待、实际复核、自动生成/审核、最终发布。无人工SLA，不能宣称任意用户即时得到人工正式课程。

## 3. 自动指标与人工指标严格分开

| 指标 | 判定 |
| --- | --- |
| 首次完整schema | ≥98/100；计划与三类首候选都有效才计一次；修正成功不回填 |
| 自动正式生成成功 | ≥95/100；本地资格、三资源及一致性自动通过，独立人工事实核对通过，可原子发布；转人工/人工兜底不是自动成功 |
| 具体严重错误召回 | ≥18/20；自动具体定位原缺陷才计，泛泛reject、只说needs_human、无响应/截断不计 |
| 分类准确 | ≥18/20；仍用20全分母，只有具体检出且类别正确计，单列混淆矩阵 |
| 正确对照自动pass | ≥19/20；错误拒绝或不必要转人工均不是pass；重大无据错误断言触发立即停止 |
| 长审核完整 | 10/10完成且schema有效（≥95%在10分母的结果）；内容正确和自动资格另报，不用结构完整代替事实 |
| 自动意见误报 | 附带发现同样逐条核实，记录有据/无据数；不隐去other_findings来提高成绩 |
| 人工依赖 | 转人工目标数/100、未处理/批准/拒绝/失效件数和比例；本提案不凭空制定人工占比目标 |
| 混合最终可发布 | 自动发布数与人工批准后发布数分别列出，再列合计/100；未处理留在分母，不替代≥95自动门槛 |
| 人工发布安全 | 待审/拒绝/过期/跨owner/取消后发布必须全部拒绝；人工不能覆盖硬门禁 |

正式审核集里的人工判断是评分依据，不是系统自动能力；混合流程里维护者实际批准是产品行为，两者分别记账。即使所有内容最终经人工修好，也不能因此宣称原自动审核≥90%或自动生成≥95%达标。

本次不下调原质量标准。若新策略需要超过5%的目标人工处理而未达自动成功门槛，T040依旧不通过；后续如用户希望接受更高人工依赖，必须另作产品范围决定并新冻标准，不能事后调整分母。
