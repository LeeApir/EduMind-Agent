# 方案重评：收紧模型与程序的职责

本次最终D02复测未通过，按用户最后一次机会的要求停止追加Prompt补丁。本文件是基于现有证据的设计建议，不批准或实施新产品范围、API、数据模型、评分权限或真实调用。

## 证据能支持什么

原r05和d01分别出现指针传值/调用约定不一致、循环与有限答案不一致；T064的受限离线规则能定位已暴露错误，但不证明任意新题的可靠性。本次d02在规划器v1的目标覆盖检查处停止：JSON合法，却把“组织2个场景”作为未挂到场景的学习目标。场景v5尚未执行，不能由此评价自环修复的真实效果。sol及新协议也未调用，不能据此评价审核模型对新课程的判断能力。

这些证据不足以证明所有自由生成课程都不可行，也不足以证明换某个模型就能解决问题。它们足以说明：目前不应再把“继续补Prompt＋再跑一次”作为端到端可靠性的主要方案。要先重划谁负责可确定的结构，谁负责开放的教学表达，以及哪些答案可以进入可靠评分。

## 建议优先采用的下一版设计

| 部分 | 建议职责 | 验收原则 |
|---|---|---|
| 规划 | 编排约束（数量、语言、形式）与可教学目标分开表达；服务端统一管理ID、引用和版本，模型只在明确契约内提出内容与覆盖关系 | 场景数量直接按约束字段校验；目标覆盖仍须真实成立，不给漏项自动补一条虚假引用 |
| 计分练习 | 首个数据结构/C领域采用经过审核的题型模板或受限状态IR，从同一状态推导代码片段、题干、允许输入和参考答案 | 在声明支持的语义范围内由确定性规则核验；遇到循环/非终止/不确定/不支持输入明确表达，不把任意LLM答案当真值 |
| 讲解和互动 | 模型继续负责讲解、风格与节奏、基于已核对状态的解释；自由内容仍可作清楚标记的待核验草稿 | 保留原ReviewAgent及安全/质量要求，不把模型互相同意或助手通过伪装成独立真值 |
| 审核接入 | 把供应商协议兼容与教学质量分别验证，使用固定边界和原始证据 | 兼容例外不自动推广生产，不为过关反复扩大未知字段允许清单 |

这不是全面推翻现有工程。已有鉴权、快照/版本、持久化操作、前端课程与播放器、记录与掌握度边界可继续保留；主要重评自由规划契约与可靠练习内核。模板/IR只约束需要可信答案的部分，不应未经用户同意取消目标驱动或可变场景等已批准需求。
