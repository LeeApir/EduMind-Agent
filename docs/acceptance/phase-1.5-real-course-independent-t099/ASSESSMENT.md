## 独立手算与题目

前提：初始节点 `i0` 为栈上节点，值 9、next 为 NULL；两次 `malloc` 实际成功。规格 `allocation_success=true` 只允许实际调用 `malloc`，不能保证成功。

| 时点 | 手算的调用者链 | 依据 |
| --- | --- | --- |
| 初始 | `caller_head → i0(9) → NULL` | 代码初始化 `i0` 与 `caller_head` |
| 插入 1 返回后 | `caller_head → t0(1) → i0(9) → NULL` | 先写 `p->next=head`，函数返回 p，调用者接回 |
| 插入 2 返回后 | `caller_head → t1(2) → t0(1) → i0(9) → NULL` | 同一步骤再次执行 |

`t0` 和 `t1` 是轨迹对两次动态分配结点的标签，并非源码中的 C 变量名；实际函数的局部指针都叫 `p`。

| 题目 | 独立手算 | 与候选比较 |
| --- | --- | --- |
| 最终调用者头 | `t1` | 一致；题干要求的是轨迹结点 ID。 |
| 遍历分类 | `terminated` | 一致；按三个 next 到达 NULL。 |
| 可知值前缀 | `[2, 1, 9]` | 一致；本例已到 NULL，故它也是本例完整遍历。 |
| 合成分配失败次数 | `0` | 与两个成功假设一致；并非保证现实 malloc 成功。 |

四段讲解中的初始链、首次与二次头插、调用者接回、终止分类与前缀均与上述前提吻合。四题解释分别复述了同一关系，未发现与对应参考答案直接冲突的事实错误。评估不声称对所有语言、代码路径或模型结果的普遍正确性。

## 发现与建议

1. **语言可读性：** 四段讲解和四题均为英文。中文产品用户可能难以学习；但已发送的 C 内容请求未指定中文，所以不能将其记为违反已发送语言要求。建议在后续版本明确语言需求并验证。
2. **范围表述：** 讲解末段及第 3 题解释强调“仅为已知前缀、不是完整遍历声明”；本例已观察到 NULL，可以确定 `[2,1,9]` 就是完整遍历。原文不是直接断言错误，但过度保守可能误导初学者；应区分本例确定终止与循环/未知指针的情况。
3. **轨迹作用域：** 初始状态 `local_head`/`p` 尚未进入作用域；caller 步 5、10 保存的是函数返回前的局部快照，不能当作仍活跃的局部变量。播放器明确标注了这两种情况，但候选原始状态没有作用域标签。
4. **动作与覆盖：** 11 次 `show_state`、10 次 `highlight_code`、10 次 `advance_step` 的引用和代码行静态一致；高亮路径为分配、赋值、链接、返回、调用者接收，跳过了代码第 5 行的成功路径判空检查。本例也没有演示分配失败，不能单凭它宣称失败分支已讲解。是否补充步骤属于后续教学改进，不把本次单例判为覆盖全部变体。
5. **资源生命周期：** 示例未展示释放两个动态结点。若增加释放说明，应释放对应动态结点，不得释放栈上的 `i0`。这是教学覆盖缺口，不单独认定为本次指针事实严重错误。
