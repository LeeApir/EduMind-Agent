# T102：人工监督的单组 B/C 串行探索方案

状态：**供独立评估的方案**。本文件既不是准确执行包，也不是实施、读密钥或调用 Provider 的授权。T102 继续 `blocked`；旧冻结、失败记录、已停止批次及其余额均不变。方案目的仅是判断：在不建设完整自动实验平台的前提下，能否安全地采集一组可复核的 B/C 课程证据。

## 1. 范围和结论边界

- 一组是同一合成目标、同一受限头插规格下的 B、C 各一个支持槽。B 独立生成正文、代码、四题答案及状态/动作，不给 B 的生成和修复输入提供引擎正确答案，也不由程序代填；C 使用受限引擎的代码、事实和轨迹，模型负责规划及教学内容。两臂使用相同审核标准和同一个审核配置；C 获取引擎事实是明确披露的干预。
- 拟在同一新包及窗口先对本次准确版本运行七个纯合成角色接口准入，全部通过并完成核对后，才开始课程；课程固定先 B 后 C，每个阶段逐次人工放行。这项合包顺序与 ADR-0047 D 要求的“准入通过后另备课程包”不同，须以后单独准确批准；若不批准，便保持先准入、后另备课程包，不能凭本方案或 T094 的旧单次例外合包。第一版审核为普通教学 `revise` 时，每臂最多修一次并重审；`pass` 时不人为制造问题或强行执行修复。已确认的事实/答案/代码或安全错误、`unknown`、协议错误等立即全批停止，首版事实、答案或代码核对失败不得用修复后的版本掩盖。
- B/C 的第一次与修订后产物、独立核对和所有失败均保留。一个支持样本不能覆盖完整的正常、失败和拒绝类别，也不能计算改进率或证明可靠性。它是独立探索，不冒充 ADR-0041 原定的每臂 10 支持＋4 拒绝实验；原实验尚未运行的槽仍为未运行，不用本次结果填充原分子或分母。T038、正式教学验收、`catalog_only` 和 H 封存不变。
- 真实材料限本次合成规格、课程与必要审核/修复上下文，不含真实学生、旧签核课程、封存 H 或独立评估真值。发送的确切字段和接收方必须在将来的准确包中逐项列出，不靠本方案推定授权。

## 3. 人工职责与发送顺序

建议设一名**真实操作者**负责终端和每次放行，一名独立评估者负责选样、真值与逐槽评估。用户此前已授权独立子助手评估全部内容，该身份如实记 `assistant`，不冒充 human；此项授权本身不开放真实调用。操作者不得由同一自动循环代替，也不能通过“批准全部”让剩余请求在后台排队。操作者可借助经审计的离线构造与校验函数；任何检查失败、拿不准、人员或密钥不可用都停止。若实际无法安排真实操作者，本方案不具备人工监督执行条件。

1. **冻结后独立选样。** 将来先冻结具体代码、依赖、指令、Schema、请求构造、可信启动方法、检查表与预算；随后由独立评估者选择一个支持规格并独立手算参考，记录其身份、时间和摘要。不得先看选样或模型答案再调整候选；真实调用前只向操作侧公开同槽规格与目标，不把独立参考交给生成或审核模型。旧 e03 不复用为本次独立样本或真值，开发例不充当独立真值，H 持续封存。课程发送前由独立评估者将所选规格的引擎事实与独立手算参考核对，记录绑定摘要的通过/失败；冲突即停，不向待测模型或开发侧泄露独立真值。
2. **七次准入，固定串行。** S1–S5 依次为 C 规划、C 内容、C 修复、B 生成、B 修复；S6/S7 为 B/C 审核。每个请求均使用将来冻结的该角色完整 Schema 和固定合成回显数据，以合成 echo 指令执行、将新版角色指令作为可核对上下文数据带入，校验实际请求、原响应、回显、来源、用量及严格本地约束；前一项完整通过才人工允许下一项。新审核视图及其代表性材料必须实际进入审核准入请求，不能只用空对象。固定 echo 只观察该次协议，不证明真实教学指令已被遵循或修复有用。
3. **B 课程：** `B_generate → review_B_0 → [B_repair → review_B_1]`。修复只在当前意见经严格校验、属于允许的普通教学问题且**具名独立核对人**确认 B 反馈不泄露引擎正确答案时发生；核对记录绑定当前候选、审核收据和反馈摘要。不能用恒真回调或先验答案代替该核对。
4. **C 课程：** `C_plan → C_content → review_C_0 → [C_repair → review_C_1]`。规划必须选中准确规格；修复只能改允许的教学内容，不能改事实/轨迹。两臂审核都看到各自完整当前候选及契约允许的参考。
5. **每一跳均停下来核对：** 人工核对阶段/角色/目标/候选/父摘要、外发内容、预算、独立完整性收据和时间；确认后才发下一跳。修复输入必须由本臂前一份**实际回包**形成的候选及该候选的**实际审核意见**构造；重审重新生成候选/视图绑定。若停止，C 或尚未触发的步骤保留 `not_run` 及原因；不续发、不换模型、不补样。
6. **B 到 C 的独立门禁与交付：** B 的模型审核最终通过后必须暂停，独立评估者核对 B 全部版本并登记绑定该槽/候选/收据的报告；报告及事实、答案、代码和严重问题检查通过才允许进入 C，失败或 unknown 全批停止。C 审核最终通过后同样独立核对全部版本。评估涵盖代码、状态、动作、四题答案及解析、讲解、审核意见与实际证据，区分首次和修复后结果；模型 `pass` 和引用命中均不自动代表质量通过。交给用户完整可阅读材料和所有失败；若实际播放器未对该候选完成播放、步进、重置与高亮检查，只能标注交互未验证。

## 4. 请求、时间和预算提案

以下均为**建议上限**，不是已批准额度，不保证可由现有代码执行。未来准确包须冻结每次实际 endpoint、模型、参数、材料、出站和金额边界；配置或策略改变不得沿用本方案或旧批批准。可将历史 DeepSeek 官方 `deepseek-flash` 生成、AIAPI `gpt-6.1-sol` 审核列为待核实候选，不宣称别名、路由或账户费率已核实。

| 项目 | 建议上限及计算 |
|---|---|
| HTTP | 共 **16 次**：7 次准入＋B 最多 4 次＋C 最多 5 次；生成侧最多 10 次、审核侧最多 6 次。无额外计数、`/models`、隐藏预检或网络重试；若将来需要额外 HTTP，必须事先改变准确包和预算，不能事后补记。 |
| 顺序/并发 | 一次最多一个在途请求；一次结束、封存并核验后才发下一个。没有后台排队、自动推进或重定向。 |
| 时间 | 建议新登记起 **120 分钟**，含人工核对和等待；单 HTTP **60 秒**，DNS 最多 **9 秒**。计时和停止机制需满足第 5 节的单次派发验证；人工未及时核对时直接停止，不延长旧窗口。 |
| 单请求字节 | 发送前完整外层 UTF-8 JSON（含 Prompt、Schema、参数）≤ **262,144 字节**；不得截断教学材料使其过关。原始候选 canonical JSON 保持现有 **128,000 字节**上限及原字段约束。 |
| 原响应字节 | 每次原始响应 body 最多 **2 MiB**，以流式有界读取并拒绝非 `identity` 的内容编码，不进行无界解压；超限只保留允许的有界证据并标 `partial/unknown`，不把它当完整原件或通过。整个批次完整 body 的算术存储上限为 32 MiB，另需收据/密文开销。 |
| 本地输入预约 | 每次为**实际完整请求 UTF-8 字节数＋8,192**，单次最多 **270,336**；16 次合计最多 **4,325,376**。发送前逐次占额，失败/unknown 不退；不因没有实际发出可证明之前的未知请求而重新分配。 |
| 输出 | 每次请求的 `max_output_tokens` 建议最多 **8,000**；本地预约总额最多 **128,000**。单角色可事先冻结更低值，不能运行时扩大。 |
| 金额 | 建议整个新批次实际支出上限 **USD 5**，生成侧≤USD 2、审核侧≤USD 3；须先核实账户计费币种、费率及可隔离的服务端余额/额度是否能共同形成该硬上限。若不能证明，则标记费用未就绪并停止；除非未来准确包**另外明确披露并获接受**不可保证的费用例外。本次没有接受该例外。 |

这些是三种不同的量：请求**字节限制**、本地可重算的**预约记账数**、服务商返回或实际计费的**token/金额**。`字节＋8,192` 不是 tokenizer 的保守上界，`max_output_tokens` 也不是已验证的上游总输出/费用硬限制。用量缺失、解析失败或实报超过对应预约即停止，原预约继续占用；返回用量和账单分别记录，不得把前者当已核实账单。超时、取消或断线不能证明上游停止或不再计费。

262,144 字节可能装不下结构合法的密集引用课程；已有 7.68 MB 压力样例证明这一点。候选超限要记录失败并停，不能截断、降低教学要求、改后补发或凭选样回避。它是本次探索资源策略的拟议变化，不声称覆盖完整支持域；如需改变数值，应先在样本独立选取前冻结并重新审查。

## 5. 对三个阻塞的具体处理与执行前提

### 5.1 可信启动与跨角色密钥

人工操作本身不能阻止同名模块劫持或子进程继承。未来只有在以下条件均被独立核验后才可准备出站：

- 在非攻击者可写、已检查所有者/权限/符号链接的可信工作目录中，以**经核对绝对路径及摘要的解释器、启动文件和依赖闭包**启动；采用隔离导入配置，不从当前工作目录、用户 site、`PYTHONPATH` 或其他可写位置隐式加载代码。检查实际加载路径与摘要；在不可信 CWD 构造同名 `scripts` 的原反例时，真实将使用的启动入口不能加载假模块。仅更换工作目录但继续相信 `python -m` 或结果校验，不能算完成。
- 每次仅启动一个角色的单次发送进程；启动该角色时其祖先进程、环境与继承的描述符都不得含**另一角色**的凭据。父进程虽然没有同时持有两种 Key、但仍残留另一角色 Key 时也不合格。干净环境及关闭多余文件描述符；只向当前角色的可信发送进程注入该角色凭据，不出现在 argv、shell 历史、请求原件、日志或另一角色进程。凭据取得和传递方法、密钥管理与具体 OS 适用范围必须在未来包中说明，并用**实际拟用入口和合成 Key**验证另一角色不继承；不能读取真实 Key 做预演。共同 OS 用户下的访问边界及密钥管理限制须如实披露，不声称达到硬件隔离。
- 可信单次发送路径需核验准确 HTTPS 目标、公网地址、Host/SNI 与证书；禁用环境代理、重定向、自动重试和回退。域名解析、地址固定和最终实际连接的对应关系在未来包中定义并以离线替身核验；证书和服务端真实身份不能靠本地摘要单独证明。该路径尚不存在经本次审查认可的真实准入实现。

### 5.2 截止、停止与单次派发

未来的人工步骤只能开启一个已登记的单次发送进程，禁止排队和自动下一跳。**批次截止与单次截止取较早者；实际首次派发不得晚于该截止，即使调用方尚未收到停止结果。** 还必须禁止调用方收到停止结果后的首次派发。这些都是执行前不可豁免的判据，单靠人工看表、发送前检查或事后记一笔不满足。方案需要将较早截止绑定到独立监督与实际发送边界，并保留请求唯一编号及启动、派发、完成、停止的实际记录。发生停止或截止时终止该发送进程及可确认的后代并有界回收；只有确认相关发送进程结束，才报告本地发送已停止。无法确认则明确 `stop_unconfirmed/unknown`，隔离本批并禁止任何继续发送，不能用人工判断把未知改成成功。

用户决定准备准确包后、该包冻结及真实执行审批前，必须用**将来实际使用的同一启动/监督/传输入口**在无真实网络的替身下复现并阻断：最终检查后暂停、父进程阻塞超过批次截止、较短单次截止、**监督方被暂停且发送方在截止后先唤醒**、所有同机监督/发送进程共同暂停跨越截止后恢复、发送进程迟到唤醒、停止后恢复以及进程崩溃。对“截止后但调用方尚未收到停止时首次派发”和“调用方已收到停止后仍首次派发”都必须有明确反例结果。未来准确包须定义**实际首次派发**的本机发送边界和可核对的时间，不能用发送前日志冒充网络侧已派发。

**尚未解决：**本方案没有提出或验证一种能在上述调度条件下保证截止后不发生首次派发的具体系统原语。独立监督加发送前检查只是待验证方向，若干 Mock 反例通过也不是对所有调度的形式证明。未来准备时必须说明并核实适用系统中的具体执行机制及其保证；若不能可靠满足该条件，就不进入真实发送。人工看表、计划结束时间或一条日志均不能代替这一前提。

系统调度、内核停顿和已进入网络的数据不提供硬实时或撤回保证；客户端终止也不证明 Provider 未继续处理。若出现无回包/无法确认终止，保留 unknown 占额并停止，不补发或切换通道。本方案不能以人工监督抹去该剩余风险。

### 5.3 原始响应和迟到证据

每次发送前，由人工在独立侧**先持久登记并核对**顺序号、slot/arm/stage、请求 body 字节数与 SHA-256、父候选/审核收据、预约和截止；登记未完成禁止派发。完成后分别登记 HTTP 状态、允许留存的非敏感响应头、**JSON 解析前的原始响应 body 字节**、长度、摘要、上游用量和采集时间；请求证据只保存准确 body 与脱敏必要头，不保存 `Authorization`。这里的原始 body 指 HTTP 库交付且未解析 JSON 的 body，不宣称保存了完整 HTTP wire 或所有原始头。流超限、中断、凭据疑似回显或正文无法安全保存时，不伪称“完整原件”，保留可安全保存的有界证据、原因与 `partial/unknown`，停止并视需要轮换受影响凭据。不能指望文本扫描识别所有编码或拆分后的密钥。

原件与派生课程、反馈、审核材料都可能含敏感字符串；将来须先确定受限私有目录、静态加密、解密权限、传递与销毁策略。`SyntheticVault` 的临时测试 Key 不可用于真实材料。**在本地先安全封存原始 body，再解析和人工核对；若无法安全保存或复核，立即停止。** 加密不能自动保证派生文本或跨供应商转发安全，任何不安全/未知内容都不能继续外发。

除运行目录外，每次核对完成即建立一份独立保存的收据清单与原件副本（或由独立评估者保管其可验证的密文和摘要）；写入/同步成功并复核后才允许下一次发送。清单至少包括每个已启动请求的编号、状态、期望文件、长度、摘要、来源、用量及候选/父链。回包、迟到或崩溃后，只要派发前登记的请求缺少对应独立终态或应有原件，即使运行账本被清空并重算 seal，也只能报告 `unknown/incomplete`，恢复时不得补发或释放未知占额。单独保护副本与清单，记录操作人和时间；本地哈希仅证明受信采集条件下的一致性，不证明服务器身份、不可回滚或恶意操作者无法一起篡改。

无论记录是 `responded` **还是 `late`**，只要声明观察到完整回包，就必须能找到、解密并匹配收据中的完整 body、状态和用量证据；任一缺失/冲突均标 `evidence_incomplete/unknown`，绝不报完整或 `verified`。若停止后真的收到迟到回包，只保存并结算已知用量、追加独立清单，不继续后续步骤；未收到就明确 unknown，不能编造回包。未来包的离线核对必须重放当前两种“删除密文和响应元数据并重算原 seal”的 responded/late 反例，并检验独立清单对缺失、孤儿文件、错摘要、错候选与错父链的检测；**不得调用有缺陷的旧汇总后把其 `verified` 当结论**。若独立清单及原件同时消失或被共同替换，需报告完整性无法证明，而不是宣称不可篡改。

## 6. 必须在准确包之前闭合的事项

1. 独立评估者审查本方案的职责、公平性、资源、停止与三项反例处理；结论、疑点和方案文件摘要另存，不能把开发自查当独立评估。
2. 只有用户审阅方案后另行决定准备准确包，才可以落实并离线演练可信单次执行、凭据隔离、响应封存、双份收据及独立核查。它们是本方案的**未实现前提**，不是通过人工口头承诺就已解决；没有必要为此建完整自动实验平台。
3. 实际角色指令、Schema、模型/端点、七个合成准入请求、B/C 动态请求构造规则、预算、可靠时间边界、发送材料、保存位置、独立选样与核对方式必须作为新包冻结。依赖前次模型结果的后续请求只能在得到该结果后构造，发送前再记其准确字节和摘要，不能声称现在已有全部准确字节。
4. 本方案涉及执行与资源策略变化：拟将七次准入与单组 B/C 课程放在同一准确包/窗口，改变 ADR-0047 D“准入通过后另备课程包”的顺序；同时引入人工逐次放行、单组探索、256 KiB 请求/2 MiB 响应建议上限、新独立证据复核及候选审核视图，与旧完整自动批次并非等价执行。需在新准确包和必要的具体决策材料中逐项列明并准确批准；不批准合包就保持原先后顺序并分别准备。不能把 T094 当次例外、旧批准、旧样本成绩或费用例外作为新批准。未经用户准确决定，不实现、不出站。
5. T102 的原 10 支持＋4 拒绝双臂实验、独立选样及准确方案仍未完成；一次探索即使通过也不解除现有阻塞、T038 或生产门禁。原任务若要恢复，另按项目协议判断阻塞是否解除。
