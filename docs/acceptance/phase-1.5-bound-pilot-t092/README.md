# T092：新版 Prompt 接线与离线绑定

隔离 Mock 流程 [p15_bound_pilot.py](../../../scripts/isolated_diagnostics/p15_bound_pilot.py) 使用 T091 新提示词及 ADR0047 原有引擎、Schema、确定性装配和审核规则。它只接受 `httpx.MockTransport`，不是 Provider 适配器或正式课程接口。

- 实际模拟 HTTP 请求使用完整 system/user、Schema、阶段及采样参数的规范字节；保留请求原字节、响应原字节、摘要和版本。产物身份记录生成阶段、Prompt 版本、实际指令 UTF-8 摘要、请求/响应及回执摘要，C 规划回执也绑定于后续版本。
- 每个回执关联 run、slot、arm、阶段、序号及上一回执；修复输入重新构造于同臂当前候选、原始允许输入和当前审核意见；新候选的父摘要及对应审核回执与第一次一致。审核请求包含完整准确候选和目标目录，审核返回按候选与精确引用校验。
- `verify_complete` 从规格及已固定指令重建完整请求链、逐次严格检查回包、重建产物、复核当前审核与修复授权；检验的内容包含消息和 Schema，非仅版本字符串。摘要用于受信采集器下的完整性和追溯，不是提供商身份或上游指令实际执行的证明。B 不接收程序参考，错误答案保留；C 事实由引擎提供，语义错误仍需复核。B 普通修复默认停止，只有明确的反馈核对回调接受完整当前意见后才发送，并绑定候选、审核回执和意见摘要；Mock 测试中的核对者只是测试工厂，不能证明真实反馈无答案泄露。
- C 规划结果经验证后完整传入内容请求并绑定规划回执；模型是否遵循规划顺序仍须验证，程序并未强制重排输出。现有契约/阈值、旧冻结和正式教学链路保持。

离线验证命令及结果见 [verification.txt](verification.txt)。Mock 响应与输入均为开发测试，不代表真实模型、真实课程质量或独立教学评价。下一任务按用户要求提供完整的可检查离线课程样例；角色接口与课程真实执行仍待独立准确包及授权。
