头插法：把新结点接到最前面

学习目标：分清“接上旧头”和“更新调用者头”，手算两次插入后的链表，并判断哪些结点可以释放。

读懂示例跟着代码走收尾与边界练习与反馈

先看这一个例子

前提：了解结构体、指针、NULL 和函数返回值。初始值为 9，依次头插 1、2，假定两次 malloc 实际成功。t0 / t1 是新结点的轨迹标签，源码中的局部指针都叫 p。

本例演示单链表头插：初始结点 i0 的值为 9，依次插入 1 和 2。这里假定两次实际分配都成功；规格中的成功标记只允许调用 malloc，并不保证真实分配成功。i0 是初始的栈上结点，t0、t1 是两次新结点的轨迹标签，并不是代码中的变量名。

第一次调用先分配 t0；其 data 和 next 在写入前未知。随后把 data 设为 1，再令 p->next 指向原头 i0。函数返回 p，调用者接回后链表为 t0 → i0 → NULL。函数返回后，其局部变量已离开作用域。

第二次调用在成功分配 t1 后，将 data 设为 2，令 p->next 指向当前头 t0，再返回 p。调用者接回返回值，因此头变为 t1，链表为 t1 → t0 → i0 → NULL。

从调用者头出发依次得到 2、1、9，观察到 NULL 后终止，因此本例的可知前缀也是完整遍历结果，且两次合成分配失败数为 0。若遇到环或未知 next，只能报告重复或未知之前的可知前缀，不能声称有限的完整遍历。原轨迹只展示两次成功路径；本页补入两次成功判空展示，未演示分配失败或释放内存。动态结点不再使用时应安全释放；栈上的 i0 不可 free。对环或未知链接不能未经验证地套用释放过程。

收尾：动态结点何时释放？
本例最终为 t1(2) → t0(1) → i0(9) → NULL。t0、t1 由 malloc 分配，不会随 insert 返回而销毁；局部指针 p 则在函数返回后离开作用域。i0 是 main 的栈上结点，绝不能 free(&i0)。
原代码未清理动态内存。下面是本例专用的收尾补充，可放在 main 的两次插入之后、return 之前；未加入上方插入轨迹，也不作为已执行结果。它先保存 next，再释放当前动态结点，最终保留 i0。
/* Only for this known acyclic list ending at stack node i0. */
while (caller_head != &i0 && caller_head != NULL) {
    Node *next = caller_head->next;
    free(caller_head);
    caller_head = next;
}
/* caller_head == &i0; never free(&i0). */
这段收尾仅适用于本例已知无环、链接有效且以 i0 结束的结构，不能套到环或未知指针上；释放后不能再通过旧指针访问结点。
没有回放的分配失败路径
第 4 行的 allocation_success=1 只允许调用 malloc，不能保证成功。若 malloc 返回 NULL，第 5 行立即 return head，调用者接回的仍是原头，不会写 p->data 或 p->next。本页两次检查均为“非空”，没有失败分支动画；第 4 题的 0 只属于当前成功示例。
