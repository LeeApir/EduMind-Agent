# 单组探索：停止投递与原件封存的限定重设计

状态：离线设计，待独立评估；不构成执行器、准确包或真实调用授权。T102 仍 blocked。采用的 A、B、D 和 C2 见 [采用记录](../phase-1.5-manual-bc-contract-diff-t102/ADOPTION.md)；旧原型与失败证据不改。这里不恢复内核绝对截止研究，也不将金额硬封顶设为 C2 前置。

## 停止与投递

1. 每次人工作出一次明确放行；独立登记完成后，单次监督进程独占当前请求的状态和发送入口。禁止父进程先启动空子进程、再由另一个线程通过 `communicate(job)` 投递；也不在后台预排下一次请求。请求 ID 和唯一派发许可写入独立登记，重启不能再次消费。
2. 监督者先在本地按较早期限检查，再持久登记 `dispatch_committed`；该记录只是一次性意图，不证明进程已创建、物理发送或服务端接收，不能用它将停止后新建的进程描述为已在途。检查后至实际发送间可能被调度暂停，按已批准 A 如实披露，不承诺物理截止。
3. `stop` 是批次不可逆终态，先持久记录停止，再尽力终止并等待有关本地进程。能确认所有相关进程退出才返回 `local_stopped_confirmed`；否则有限等待后返回 `stop_unconfirmed`，仍标记全批停止。**停止后不得新建发送进程**；此前已经创建的发送进程在无法确认退出时可能迟发，不能把 `stop_unconfirmed` 说成已无本地发送活动。无论能否确认退出，都不得登记、授权或启动新的请求。
4. 监督者失联、创建结果不明、停止记录写入失败、进程树无法确认或已发时间未知均为 `unknown`，不重试、不补发、不复用序号或释放预约。重启只读核对并保持停止；不得根据本地账本缺失推断未发送。系统允许的进程及后代边界必须实测；若无法确认，则不得报告 confirmed。

**独立复审发现的未解阻塞**：如果监督者在持久承诺后、真正创建进程前暂停，另一方有限等待后返回 `stop_unconfirmed`，监督者恢复时仍可能新建进程。只写独立仲裁或检查停止标记不能证明消除此竞态；截至本设计尚无经验证的方法同时满足有界返回和停止后不新建进程。须保留 blocked，不能靠重命名意图记录声称解决。原有的旧例检查与 `communicate(job)` 之间暂停反例仍须通过新实际入口重放。也须测试监督者在承诺后、spawn 前暂停，stop 返回后恢复；无论请求 ID 是否相同，若新建发送进程均失败。还须测试重启不能重复消费同一请求 ID。

## 先封存原件，再解析

1. 独立见证侧预登记不可复用序号、臂/阶段、准确请求摘要、父候选与收据、预约和截止；按照固定 B/C 阶段转换规则核对。请求原件与预登记均持久化并核对后才可放行。注册目录由可信目录句柄及相对路径操作，禁止跟随符号链接；固定所有者/权限，创建与读取均核对身份。权限、同步或身份校验失败即停止。
2. 接收原始 body 时实施大小和安全检查；可安全保存的完整 body 在 **JSON、Schema 或用量解析前** 加密封存并持久同步，记录原始字节长度、摘要、HTTP 状态和采集时间。密文及其绑定预登记的元数据须有独立副本，完成复核后才可登记完整终态。加密 key 的取得、恢复和销毁方式必须在准确包冻结；合成测试 key 不能作为真实材料方案。敏感回显、超限、断流或无法安全保存时仅保留安全有界证据并记 `partial/unknown`，不伪称完整。
3. 封存成功后才解析；非法 JSON、缺失用量、用量矛盾或超过预约时保留原件，状态为 `unknown` 并停止，占额不释放。普通与迟到响应共用原件与收据核对流程；迟到可以记录和结算确实观察到的用量，但必须先固定停止状态，绝不允许注册下一阶段。
4. 收据与见证记录绑定 slot、arm、stage、请求摘要、父版本、响应摘要、状态、用量与预约。下一阶段依赖同臂上一份实际产物和相应收据；B 阶段不能接受 C 阶段，修复必须绑定实际审核。错误、缺失、孤儿文件或不一致一律 `evidence_incomplete/unknown`。验收包括对原始字节解密、摘要及独立副本比对，不使用旧 `verified` 汇总代替。
5. 批次开始前由独立保管者持有初始化锚（随机批次 ID、冻结摘要及序号 0），每次核对后独立保存批次 ID、递增序号、最新记录摘要和停止状态；重启对照该锚与全部副本，缺锚、序号倒退、分叉或不符为 unknown，禁止自动续发。实际独立保管方式和可信人员尚未落实，不能把同目录另一份文件当成独立锚。即使有锚，也无法证明保管者及全部副本共同回滚；此威胁下完整性不可证明，不能声称防篡改。恢复从独立预登记、终态、停止标记与原件副本逐项只读重建；任何中间状态、孤儿或缺失均保留 unknown 与预约。
6. 事务边界：先安全写入唯一临时密文并同步文件，再原子发布并同步所在目录；独立副本同样完成并回读核对后，才追加包含该原件摘要的终态并同步。任一步部分写入、同步失败、进程崩溃或无法判定落盘顺序都进入停止/unknown，保留可安全保存的残余文件，不补发、不覆盖；独立终态不存在时绝不报告完整。目录身份验证必须依赖持有的目录句柄，而非先检查路径再按路径写入。上述是待实现约束，不证明真实文件系统故障语义。

## 限定离线验证与实施边界

真实可用前，须以将来实际入口和合成 HTTP/凭据验证：原停止竞态和 spawn 暂停；重复/并发派发、停止和恢复；非法 JSON 先封存；普通/迟到原件与用量；目录替换及符号链接；B/C 错阶段和错父链；每个持久化节点崩溃；删除、篡改、孤儿和双侧回滚；随后分别走通 B/C 生成、实际结构修订审核、一次修复与重审。原失败脚本针对旧原型，保留并应继续复现旧失败；新反例必须验证实际新入口，不能只模拟布尔状态。

本文件不实现上述机制。独立初审已指出停止后新建进程的竞态仍未解决，故不得进入真实发送或声称该设计已通过。可信启动的完整依赖闭包、真实发送器、祖先进程凭据隔离、独立见证持久性、费用和实际运行环境仍未验证。不能据本设计宣布通过、冻结、选样或执行。用户已选 C2 仅为费用方向，准确批次仍须说明实际费率、币种、上游限额和取消后计费等未知风险并另获该批授权。
